# AI 概念准确性与边界

> 这一页解决一个问题：**页面可以写得很好懂，但机制讲错了。**
> 红线 12 管「全页一个口径」，本文件管「这个口径本身对不对」。两件事分开过：先保证说法准确，再保证全页一致。

---

## 〇、一条总则：类比负责进门，边界负责不误导

每个关键类比后面，补一句「真实实现是……；这个类比不能推出……」。
不是每句话都要加，只加那些**读者会当成事实**的类比。

**三句话模板**：

1. 这是帮助理解的类比，不是真实实现。
2. 真实模型里是……
3. 它能帮你记住……，但不能推出……

**什么时候必须加**：

- 这个类比会被读者复述给别人；
- 这个类比涉及「模型怎么工作」；
- 这个类比一旦绝对化，会和后文的检索、工具、微调、评测打架。

## 一、八组最容易混说的边界

| 容易混说 | 正确说法 | 页面怎么写 |
|---|---|---|
| **模型 / 应用** | 模型本身只根据输入和学到的参数生成内容，不会自动核查事实；AI 应用可以接入搜索、知识库、数据库、工具 | 首次出现就把「模型」和「应用」分开；后文统一用词，不来回换 |
| **训练 / 推理** | 训练通常在离线阶段，可分预训练、微调、后训练；日常推理通常不更新参数 | 不写「训练一次做完」；不把推理写成「模型在学」 |
| **原始分数 / 归一化权重** | 注意力先算 Query 与 Key 的相关性分数，softmax 后才得到权重；同一 Query 下权重总和为 1 | 界面叫「权重」就必须归一化并显示数值；否则叫「相关性分数」 |
| **双向注意力 / 因果注意力** | Encoder 式可看两边；Decoder 式生成时只能看自身及之前的位置 | 演示标明当前模式；不要用双向示例讲生成时「不能偷看未来」 |
| **架构家族 / 任务** | Encoder-only / Decoder-only / Encoder-Decoder 是三种架构；理解 / 生成是典型训练目标和输出形式，不是硬能力边界 | BERT 与 GPT 作为代表并列介绍；同一任务可以走不同路线 |
| **语言建模损失 / 业务正确率** | 缩放定律描述语言建模损失随规模变化的经验关系；不直接保证业务正确率 | 不写「平均错误率平滑下降」；写「在论文设定下」 |
| **激活参数 / 存储参数** | MoE 每个 Token 只激活部分专家；其余权重仍需存储、加载和通信 | 不写「只需要存激活的参数」；成本还取决于精度、分布、缓存、通信 |
| **待核实 / 已证伪** | 「页面没给依据」只说明不能直接采信，需要核实；核实后才知道真假 | 风险标记写「待核实」；不把「没来源」直接写成「必定为假」 |

## 二、高风险概念速查

| 概念 | 最容易讲错的地方 | 一句话校正 |
|---|---|---|
| **大模型** | 「它不查资料」被写成模型和应用都不查 | 模型本身不自动查；接检索 / 工具后才会查 |
| **自回归生成** | 「每生成一块都重看全文」被理解成每步全量重算 | 生成依赖已有上下文；实际推理通常会缓存并复用之前的计算结果 |
| **Token / 词表** | 把 Token 等于字或词 | Token 是切分单位；字数不等于 Token 数 |
| **嵌入** | 把初始 Token 嵌入、上下文表示、检索嵌入混成一个 | 初始嵌入按 Token 身份取得；上下文表示会被网络更新；检索嵌入是另一类用法 |
| **注意力** | 把权重当解释、当证据 | 权重高只说明分配了较多关注，不等于模型「看懂了」，也不能单独证明最终判断 |
| **Q / K / V** | 只讲「关注谁」，不讲 V 怎么汇总 | 分数 → 权重 → 对 V 加权求和 → 新表示；演示至少走完这条链 |
| **BERT / GPT** | 写成「理解型 / 生成型」的能力边界 | 两者是不同架构家族的代表；任务和架构不是一一绑定 |
| **预训练 / 微调 / 后训练** | 写成所有模型的必经单一路线 | 常见流程示例；不同模型的后训练目标、方法和阶段组合可以不同 |
| **RAG** | 写成「有据可查 = 一定正确」 | RAG 改善依据，但不保证检索对、引用对、结论对 |
| **幻觉 / 风险标记** | 把「待核实」当「已证伪」 | 风险标记表示不能直接采信；核实后才判断真伪 |
| **选型** | 把偏好写成「不能让步的约束」 | 先列可核验的门槛（预算、延迟、合规），再排偏好 |
| **评测** | 只说「建评测集」，不说怎么评分 | 分类看标签；总结看事实 / 遗漏 / 编造；代码跑测试；结构化输出查 schema |

## 三、装置数据自洽

教学数据可以是假，但概念关系必须真。

1. **叫「权重」就归一化**：展示数值，说明总和为 1；不归一化就叫「相关性分数」。
2. **标尺说清楚**：按组内最大值缩放时，标注「仅组内比较」；不同 Query 的条长不能直接跨组比。
3. **人为值不能当证据**：先设定「他」对「小李」权重最高，再据此证明指代关系，是循环论证；应称「一种假设性的关注分配」，指代判断另列依据。
4. **机制链走完**：Q/K 匹配 → 权重 → V 加权求和 → 输出；停在「关注谁」只讲了半截。
5. **循环类要累积**：逐 Token 生成至少演示两轮，显示上下文增长；只生成一个 Token 看不到循环。

## 四、事实、版本与来源

- 产品能力、价格、参数：写「截至某日期 / 某版本」；不把会变的产品事实写成永久结论。
- 论文结论：写「在论文设定下」；不把语言建模损失直接换成业务正确率。
- 页面保持无链接；来源与版本放在交付说明的「来源台账」或课程包资料页。
- 知识卡片定义来自 `scripts/ai_concepts.json`；改定义先改词典，不要让页面各自打补丁。

## 五、选型与评测页

- **门槛 vs 偏好**：门槛必须可核验（响应耗时上限、预算上限、允许的数据处理方式）；偏好是满足门槛后的排序。
- **多条件冲突**：同时满足不了时，明确写出取舍，不要用两段固定文本拼接。
- **评分方法**：分类看标签是否正确；总结看关键事实、遗漏、编造；代码跑测试用例；结构化输出查格式与字段。
- **测试条件**：记录输入输出长度、并发、接入方式；首 Token 延迟是等到第一个输出，P95 是约 95% 请求不超过的耗时。

## 六、写法对照

| 初稿 | 改后 |
|---|---|
| 大模型不查资料。 | 模型本身不自动查资料；AI 应用可以接入搜索、知识库或工具去查。 |
| BERT 负责理解，GPT 负责生成。 | BERT 是 Encoder-only 的典型代表，GPT 是 Decoder-only 的典型代表；理解 / 生成是典型目标和输出形式，不是硬性能力边界。 |
| 数据、参数、算力一起扩大，平均错误率平滑下降。 | 经典缩放定律描述语言建模损失随规模变化的经验关系；它不直接保证某项业务的正确率。 |
| 每个 Token 都重看全文。 | 每一步都根据已有上下文继续生成；实际推理通常会缓存并复用之前的计算结果。 |
| 注意力权重说明它关注了「小李」。 | 这组数值是人为设定的相关性分数，用来说明一种可能的关注分配；它不能单独证明指代关系。 |

## 七、自检（6 条）

- [ ] 关键类比后面有边界句。
- [ ] 模型 / 应用、训练 / 推理、分数 / 权重、架构 / 任务没有混说。
- [ ] 叫「权重」的数据已归一化；否则改叫「相关性分数」。
- [ ] 人为设定的演示值没有被当成结论证据。
- [ ] 产品能力 / 价格 / 参数有日期或版本；论文结论有条件。
- [ ] 标题承诺的机制在正文里真的讲了。

## 八、词典维护

- 高风险词条应有 `boundary` 字段：一句话写「这个词在什么范围内成立 / 不能推出什么」。
- 词典是知识卡片的唯一来源；改词典比逐页改文案更根本。
- 新增 / 修改词条时，同步检查 `def` / `diff` 是否把类比写成了绝对事实。
