# 小奈三问卡接入（先看例子，再看协议）

> [!abstract] 你只需要做 5 件事
> 1. **判**：这页有没有可播放动画流程？没有 → 不配卡（§0）。
> 2. **写**：从本页三条主线各取一个读者真会问的问题（机制 / 细节 / 边界），写成**三道开放问题**。
> 3. **填**：卡片文案 + `ASKS` 三道问题 + `TOPIC` 学习主题。
> 4. **接**：通信段照抄，不要改。
> 5. **验**：点哪道发哪道；没有选项、没有标准答案、没有提示词预览框。

> **只有一种卡：三问卡。**

---

## 开篇｜一张卡到底长什么样

### 0.1 读者看到的三步

```text
① 看完动画
   点播放 / 看步骤依次出现 / 停在结论
        ↓
② 看到三个问题
   「上下文窗口满了以后，模型会怎么做？」
   「为什么聊得越久，它越容易忘掉最早的话？」
   「什么时候该开新对话，而不是继续聊？」
        ↓
③ 点其中一个
   直接发给小奈；她用大白话接着这个问题讲
```

**它不是聊天框，也不是测验。** 它是动画之后的「继续追问」入口：读者点一个问题，小奈就着这个问题讲。

### 0.2 一个完整例子：页面「上下文窗口什么时候会满？」

**页面上的动画**：点播放，对话轮数从 1 走到 20，上下文占用条逐格填满；到 8,000 tokens 时旁白说「超出的部分会被挤掉」。

**卡片文案**：

| 位置 | 文案 |
|---|---|
| 卡标题 | 跟小奈聊：挑一个问题问她 |
| 说明 | 点一个发给她，她会用大白话接着你的问题讲。 |
| 问题一（机制） | 上下文窗口满了以后，模型会怎么做？ |
| 问题二（细节） | 为什么聊得越久，它越容易忘掉最早的话？ |
| 问题三（边界） | 什么时候该开新对话，而不是继续聊？ |

**点「问题一」后实际发出的 prompt**：

```text
我在学「上下文窗口什么时候会满」。

我想问：上下文窗口满了以后，模型会怎么做？

请用大白话回答：先给一句结论，再举一个例子，别展开成长篇。
```

**点「问题三」时只换问题本身**，主题与回答方式不变；不会把三道问题一起发出去。

### 0.3 你只改这 4 处

| # | 改哪里 | 在模板里的位置 | 改成什么 |
|---|---|---|---|
| ① | 页面标识 | `<body data-page-id>` 与 `<section class="coach" data-coach-title>` | 本页唯一 ID + 卡标题 |
| ② | 卡片文案 | `<section class="coach">` 里的 title / desc / 三个 `.coach-ask` | 按 §1 的写法填 |
| ③ | 三道问题 | 脚本里的 `ASKS` | 机制 / 细节 / 边界各一题 |
| ④ | 学习主题 | 脚本里的 `TOPIC` | 本页一句话主题 |

生产环境上线前，再给 `<body data-coach-origin="宿主 origin">` 填上宿主域名；它不算「写内容」的第 5 处，但属于通信配置，留空只适合本地预览。

通信段（含 `requestId`、8 秒超时、复制兜底、origin 校验、`coach:hello` 握手）、`sendCoachPrompt()`、`coach:ack` / `coach:ready` 监听**整段照抄，不要改**。

## 〇、哪些页面配卡（先判这个）

```text
这页有没有可播放动画流程？
├─ 没有 → 纯知识页 → ❌ 不配卡
└─ 有 → 动画能不能停在结论？
    ├─ 能 → ✅ 配三问卡，贴在动画正下方
    └─ 不能 → 先把结论字幕补出来，再配
```

| 页面类型 | 判据 | 配不配卡 |
|---|---|---|
| **动画页** | 有可播放动画流程——读者按播放看一个过程 | ✅ **配**（贴在动画正下方） |
| **纯知识页** | 只有阅读内容：一句话回答 + 提醒 + takeaway | ❌ **不配** |

**为什么纯知识页不配**：三问卡的价值在「读者刚看完，脑子里冒出一个问题，顺手就能问」。没有动画，就没有这个「刚看完」的时机，卡片会退化成一只聊天入口，和页面的学习动线脱节。

> 命名：**小奈三问卡**（不是「向小奈提问」「AI 助手」）。页面上一律用这个称呼。

## 一、三问卡的五条设计原则

| 原则 | 说明 |
|---|---|
| **三道，不多不少** | 机制 / 一个关键细节 / 能力边界，各一题；不拿整页或整条流程当问题对象 |
| **开放，不判对错** | 没有 A/B/C、没有标准答案、没有「答对 / 答错」反馈；它是追问入口，不是测验 |
| **点哪道发哪道** | 点问题本身就是发送；没有选中态、没有二次确认、没有「提交答案」 |
| **prompt 只写三块** | 学习主题 + 问题 + 回答方式（先结论、再例子、别长篇）；默认不塞页面摘要 / 动画读数 |
| **卡面只写动作** | 只写「点一个发给她」这类话；不写「三道都没有标准答案」这类元说明 |

## 二、通信协议（宿主为父窗口）

页面被 iframe 嵌入，通过 `window.parent.postMessage` 与宿主通信。**发对象，不发 JSON 字符串**；字段名和值必须与下表逐字一致。

### 2.1 页面 → 宿主：`coach:send`

```js
var requestId = 'coach-' + (++seq);   // 每次发送一个，宿主 ack 时原样带回
window.parent.postMessage({
  source:  'learning-page',        // 固定值，宿主据此识别
  type:    'coach:send',           // 出站消息
  v:       1,
  requestId: requestId,            // 可选但推荐：让回执对得上具体某一次提交
  payload: {
    prompt: 'HTML 已组装好的完整提问文字'   // ★ 唯一必需的业务字段，必须非空字符串
  }
}, hostOrigin || '*');             // 优先用 data-coach-origin / ?hostOrigin=；未配置才退回 '*'
```

> `coach:hello` 是可选握手消息（页面 → 宿主），不携带业务内容；宿主不实现也不影响发送。
> 变量 `seq` / `hostOrigin` 来自模板的 `COACH` 对象；完整实现见 `assets/page-template.html` 的复用段。

### 2.2 宿主 → 页面：`coach:ack`

```js
{ source: 'xiaonai', type: 'coach:ack', v: 1, requestId: 'coach-1' }
```

| 消息 | payload | 页面行为 |
|---|---|---|
| `coach:ack` | `requestId`（建议原样带回） | 确认**宿主已接手**，清掉超时计时器，状态提示改为「已交给小奈教练，请查看对话。」 |
| `coach:ready` | — | 可选握手回执：宿主表示已接入，状态提示改为「已连接小奈教练。」 |

`coach:ack` **只表示宿主接手了提问，不代表模型已回复、也不代表后端请求成功**。回复出现在小奈自己的对话界面里，**不在页面内回显**。
带 `requestId` 的 ack 必须与当前请求对得上；对不上的 ack 直接忽略，避免旧请求的回执覆盖新请求的状态。

### 2.3 元素 ID（脚本引用必须一致）

| ID | 用途 |
|---|---|
| `coachInput` | **隐藏**的 textarea，仅用于暂存本轮 prompt；不展示给读者 |
| `coachStatus` | 状态提示行（`role="status" aria-live="polite"`） |

> 三问卡**不需要** `coachSubmit` / `coachReset`；发送由 `.coach-ask` 按钮直接触发。

### 2.4 安全

```js
window.addEventListener('message', function (ev) {
  if (ev.source !== window.parent) return;      // 只收父窗口
  if (hostOrigin && ev.origin !== hostOrigin) return;  // 配了 origin 就收紧，不认别的来源
  var d = ev.data;
  if (!d || typeof d !== 'object') return;
  if (d.source !== 'xiaonai' || d.v !== 1) return;
  if (d.type !== 'coach:ack' && d.type !== 'coach:ready') return;
  /* … */
});
```

**不要把消息里的 `source` 字符串当作身份验证**——它只是识别用的约定值。真正的来源校验靠 `ev.source` + `ev.origin`。

**origin 怎么配**：在 `<body data-coach-origin="https://host.example">` 上填宿主的 **origin**（协议 + 域名 + 端口，不要带路径）；也可以用 `?hostOrigin=https://host.example` 临时覆盖。留空时退回 `'*'`，只适合本地预览或无法预知宿主域名的场景。

### 2.5 超时、失败与复制兜底

页面不能一直停在「正在交给小奈教练…」。通信段内置三层处理：

| 情况 | 页面行为 |
|---|---|
| 不在 iframe | 提示「请在支持小奈教练的宿主页面中打开」，并出现「复制问题」按钮 |
| 在 iframe，但 8 秒内没有 `coach:ack` | 提示「宿主 8 秒内没有响应」，并出现「复制问题」按钮 |
| `postMessage` 抛异常 | 提示「发送失败」，并出现「复制问题」按钮 |
| 收到匹配的 `coach:ack` | 清掉计时器，提示「已交给小奈教练，请查看对话。」 |
| 收到 `coach:ready` | 提示「已连接小奈教练。」（可选握手，不阻塞发送） |

**「复制问题」不是第四个问题按钮**：它只在失败 / 超时时动态出现，复制的是本轮完整 prompt；成功收到 ack 后自动移除。不要把它做成常驻控件，也不要让页面自己发请求或重试队列。

### 3.3 业务脚本（放在通信段之外）

```js
var ASKS = [
  '{{问题一}}',
  '{{问题二}}',
  '{{问题三}}'
];
var TOPIC = '{{本页学习主题}}';

function buildPrompt(q) {
  return '我在学「' + TOPIC + '」。\n\n' +
    '我想问：' + q + '\n\n' +
    '请用大白话回答：先给一句结论，再举一个例子，别展开成长篇。';
}

Array.prototype.forEach.call(document.querySelectorAll('.coach-ask'), function (btn) {
  btn.addEventListener('click', function () {
    var q = ASKS[parseInt(btn.getAttribute('data-q'), 10)];
    if (!q) return;
    var prompt = buildPrompt(q);
    $('coachInput').value = prompt;   /* 方便调试；发送不依赖它 */
    sendCoachPrompt(prompt);
  });
});
```

### 3.4 不要动的地方

- `/* 复用代码开始 */` ~ `/* 复用代码结束 */` 之间的通信段。
- `sendCoachPrompt()`、`requestId`、8 秒超时、`.coach-copy` 复制兜底、`coach:ack` / `coach:ready` 监听、origin 校验、`coach:hello` 握手。
- 头像 `.coach-avatar` 的 base64 CSS。
- `R()` 函数：所有延时写成 `R(160)`，不要写裸 `160`。

### 3.5 没有宿主时的表现

```text
不在 iframe（window.parent === window）
   └→ coachStatus 显示：「请在支持小奈教练的宿主页面中打开此学习页。」
      同时出现「复制问题」按钮；学习内容照常可看。

在 iframe 但宿主没回 coach:ack
   └→ 8 秒后状态改为「宿主 8 秒内没有响应」，出现「复制问题」按钮。

宿主回了 coach:ready
   └→ 状态显示「已连接小奈教练。」；仍按正常流程发送。
```

**不做**：重试队列、自动展开聊天面板、常驻复制按钮。「复制问题」只在失败 / 超时时出现，作为一次性的替代操作。

## 四、三问怎么写

### 4.1 三条主线各一题

| 题 | 问什么 | 句式 | 例 |
|---|---|---|---|
| **机制题** | 它是怎么做到的 | 「它是怎么…的？」 | 大模型是怎么把一句话变成回答的？ |
| **细节题** | 一个关键差异 / 易混点 | 「为什么 X 和 Y 对不上？」 | Token 为什么和字数对不上？ |
| **边界题** | 什么时候会失灵 / 不该用 | 「它什么时候会…？」 | 它为什么说得流畅，却也可能一本正经地编？ |

### 4.2 写题的四条要求

1. **8–24 字**，读完能直接问出口。
2. **每题独立**，不能是同一件事的三种问法。
3. **能脱离页面被回答**：问题本身要自带对象，不写「这个 / 它 / 上面说的」。
4. **不预设答案**：不写「是不是因为…」「A 和 B 哪个对」。

### 4.3 好问题 / 坏问题

| ✅ 好问题 | ❌ 坏问题 | 为什么 |
|---|---|---|
| Token 为什么和字数对不上？ | 下面哪个是 Token？ | 选择题，不是开放问题 |
| 大模型是怎么把一句话变成回答的？ | 大模型是什么？ | 名词解释，不是追问 |
| 它什么时候会一本正经地编？ | 它是不是会编？ | 封闭问句，只能答是 / 否 |
| 为什么聊得越久，它越容易忘掉最早的话？ | 这个为什么会这样？ | 指代不清，脱离页面无法回答 |

### 4.4 问题库

更多按页面类型分好的问题，见 `07-小奈三问卡问题库.md`。

## 五、常见错误

| 写坏了 | 改成 | 为什么 |
|---|---|---|
| 三个 A/B/C 选项 | 三道开放问题 | 这是追问入口，不是测验 |
| 卡面写「三道都没有标准答案」 | 只写「点一个发给她」 | 元说明让卡变啰嗦 |
| 点问题后还要选 / 确认 | 点问题就是发送 | 多一步就少一半点击 |
| prompt 里塞整页摘要 | 只留主题 + 问题 + 回答方式 | 问题自带上下文，摘要只会稀释它 |
| 三道题都是「怎么用」 | 机制 / 细节 / 边界各一题 | 三题要覆盖三条主线 |
| 纯知识页也硬塞卡 | 删掉卡与脚本 | 没有动画，就没有「刚看完」的时机 |
| 问题里写「这个 / 它 / 上面说的」 | 写实对象：「Token 为什么…」 | 小奈看不到页面 |
| 宿主不回 ack 时一直转圈 | 整段照搬新版通信段，见 §2.5 | 页面不能把失败藏起来 |
| 生产环境仍用 `targetOrigin:'*'` | 配 `data-coach-origin` 或 `?hostOrigin=` | 能收紧就收紧，别把消息发给任意父页面 |

## 六、5 分钟验收

- [ ] 恰好三道开放问题；没有选项、没有标准答案、不判对错。
- [ ] 点任意一道，只发这一道；没有选中态、没有二次确认。
- [ ] prompt 只含「学习主题 + 问题 + 回答方式」，没有页面摘要 / 动画读数。
- [ ] 三题分别覆盖机制 / 细节 / 边界，且都能脱离页面被回答。
- [ ] 卡面只写动作，没有「没有标准答案」这类元说明。
- [ ] 隐藏的 `coachInput` 与可见的 `coachStatus` 都在；通信段原样未改。
- [ ] `coach:send` 带 `requestId`；`coach:ack` 原样带回；对不上的 ack 被忽略。
- [ ] 8 秒无 ack 时出现「宿主未响应」+「复制问题」，不会一直停在「正在交给」。
- [ ] 配置了 `data-coach-origin` / `?hostOrigin=` 时，接收校验 `ev.origin`；未配置时知道这是预览模式。
- [ ] 不在 iframe 时，`coachStatus` 给出可见提示，并有「复制问题」兜底。
- [ ] 可选握手 `coach:hello` / `coach:ready` 不阻塞发送；宿主不实现也能正常用。
