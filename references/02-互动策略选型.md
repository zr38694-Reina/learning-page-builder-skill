# 互动策略选型

**先问「这段内容能被证真、被看见、被比较，还是只能被分层」，再挑控件。**
跳过这一步直接挑控件，是这类页面返工的第一大原因。

---

## 一、七类内容性质 → 七种题型

| 内容性质 | 判据（怎么认出来） | 题型 | 心理机制 | 实现 |
|---|---|---|---|---|
| 有**可计量的单位** | 能数出来：钱、字数、颗数、秒数、步数 | **点选 + 计数器** | 量级震撼（原来这么费） | `patterns/01` |
| 有**可调的参数** | 能拖出来：轮数、规模、用量、时长 | **滑块 + 单变量对照** | 失去厌恶 + 对照翻转 | `patterns/02` |
| 有**可拆的流程** | 能分步：三步、四层、五个环节 | **分步推进 + 终态对比** | 对比 + 可验证性 | `patterns/03` |
| **能证真假** | 有客观答案，能核对 | **盲判 + 押注后核对** | 承诺一致 + 预测误差 | `patterns/04` |
| 只能**分层**（无对错） | 没有正确答案，只有深浅 | **自诊：选你停在哪** | 自省（我停得太早） | `patterns/05` |
| 只能**看见**（一个过程） | 是一次经历，不是一道题 | **播放**（代价帧放慢） | 见证 | `patterns/06` |
| 需要**倾向**（两种做法） | 想让人心疼一种代价 | **A/B 对比，默认播坏的那档** | 对比 + 失去厌恶 | `patterns/07` |

> [!important] 最容易选错的两处
> - 用**盲判**去讲一个**没有客观答案**的内容 → 学员不知道自己在押什么注。
> - 用**播放**去讲一个**本该让人押注**的内容 → 学员全程被动，什么都没记住。
> **有对错就必须让人先表态**（押注之后错误才疼）；**没对错就别假装有对错**。

## 二、通用装配要求（七种题型都要满足）

| 要求 | 说明 |
|---|---|
| **装置自带论据** | 装置本身就是证据，不是配图。核心概念**只能通过交互被看见**——不切开就看不到 Token，不拖滑块就看不到遗忘。做不到这点就该换题型。 |
| **可重看** | 动画超过 3 秒，必须给「↻ 再看一遍」；按钮文案要跟着变。3 秒的动画不值得三步控制（不要单步/重置按钮）。 |
| **可打断** | 学员会在动画播到一半时切档。**切档前必须 `clearTimeout` 清定时器**，否则两档会叠在同一条时间线上。 |
| **不重试** | 如果目的是**让解释被读到**，答错不给重试（重试会让人跳过解释去试答案），但**一定要标出正确答案 + 给一句「为什么」**。 |
| **不记分** | 需要**完成感**时才上进度条 / 命中率。随手翻阅型的页面做记分，会把「读到就赚」变成「任务」。 |
| **埋一真** | 反例集里**留一个正确答案**。全假会教出一条更粗暴的错误规则（「数字都不可信」）。真的那一处最好恰恰是最像「精确＝可靠」的那个。 |
| **反馈句式统一** | 先说结论，再说为什么，最后给一条延伸判断。句式统一成「这是 **X** 的……」这类，学员答错时读到的是一段知识，不是一句判词。 |

## 三、节拍：不匀速，代价帧放慢

这是全套策略里最容易被漏掉、又最有效的一条。

| 片段 | 给多久 | 为什么 |
|---|---|---|
| 开场 | 短（~900ms） | 快进到现场 |
| **过程 / 真话** | 中（~1500ms） | 看得清就行 |
| **代价 / 假话 / 后果帧** | **长（2100–2800ms）** | **这就是让学员产生自省的关键帧** |
| 收尾 / 最后一处 | 最长（~2800ms） | 定格，留给回味 |

- **播放式**：把「不做会怎样」的那一帧**放慢**，其余帧加快。
- **盲判式**：真话快过、假话多看、收尾定格（依据是「真假」而非「步序」）。
- **可访问性**：`prefers-reduced-motion` 下，所有时长归零（`beat()` 返回 0），退化成一口气全展开。

## 四、四种「让结论自己长出来」的手法

不写结论，让学员自己撞见：

| 手法 | 做法 | 例 |
|---|---|---|
| **对照组预置在选项里** | 选项不是随机取的，是设计好的对比组 | 5 句里放中文句/英文句/带数字句 → 学员自己发现「中文更费」「字数≠颗数」 |
| **单变量翻转** | 问题、条件全不变，只改一个自变量，结果反转 | 只改对话轮数 → AI 从「帮你避开过敏」翻成「推荐花生酱拌面」 |
| **把缺失项全程挂在场上** | 那条「还缺的一句」从第一步就摆在屏幕上，**只有走到最后一步才高亮** | 视觉上的「一直缺一块」比文字说明更能制造张力 |
| **把体验变成两个数字** | 收尾用对比数字代替形容词 | `跑了 4 趟 · 问了你 3 次` vs `1 趟搞定 · 0 次打扰` |

> [!tip] 数字要动起来，不要静态展示
> 计数器**跟着动画跳**（每弹一个单位，计数 +1，账单跟着变），而不是最后一次性显示总数。
> 静态总数是「结论」，跳动是「过程」。**要展示的是感觉，不是那个数。**

## 五、收尾：先给能力，再给边界，最后给一个可执行动作

每个装置后面都要有一段「诚实提醒」。三段式：

1. **给能力**：它刚才能做到什么（学员自己刚验证过）。
2. **给边界**：它在什么情况下会失效。**主动写出软肋**——一个只夸不设限的页面，学员出门就会踩坑。
3. **给动作**：一条今天就能用的做法（零成本的那条排最前）。

对策条按**代价从低到高**排，最后的往往是「换个用法」而不是「换个工具」——把责任放回学员自己身上，比甩锅给工具更诚实也更有用。

## 六、时长参考

| 装置规模 | 总时长 | 控件 |
|---|---|---|
| 单帧翻转（滑块） | 即时 | 1 个滑块 |
| 3–5 步播放 | 2–3 秒 | 1 个播放按钮（+ 再看一遍） |
| 5–9 步序列 | 5 秒内 | 1 个播放按钮，不给单步控制 |
| 3 步 × 5 处（多状态） | 分段，可跳 | 步骤导航 |
| 9 个状态（3 层 × 3 步） | 分段，可跳 | 层级按钮 + 播放/单步/重置 |

**控件复杂度按时长定**：超过 10 秒的多状态演示才值得给「单步 / 重置」；3 秒的动画给三步控制是负担。
