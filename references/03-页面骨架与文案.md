# 页面骨架与文案

**先写完文案，再写代码。** 这类页面的成本 80% 在文案，20% 在实现；反过来做会反复改稿。

---

## 一、三种骨架，按读者姿态选

| 骨架 | 块数 | 适合 | 特征 |
|---|---|---|---|
| **七段式**（论点式） | 7 | 一节课 = 一个论点，路径式阅读 | 匀质、说服式、有案例 |
| **问答式** | 8 | 一页一问，检索式阅读 | **答案在最前面**、无案例、无模板 |
| **长动线式** | 14 | 一节课 = 一个动作 + 一个演示 + 一份原理附录 | 在七段式基础上把「原理段」写厚、正文拉长 |

> [!important] 三种骨架都带两张常驻块：「知识卡片」（§1.3）与「生活化举例」（§十二）
> **知识卡片**位置固定在**首屏右侧**（替换首屏配图，卡片就是首屏的视觉主体）：**本页出现的 AI 概念都写上**（常见 3–5 条，不限条数）；**默认每页都放**。
> 它不是「额外加餐」，是**本页的术语地图**：读者一进页先拿到它，正文里再遇到这些词时已经有锚点。
> **生活化举例**用一段家常小剧场把本页原理再讲一遍（三拍 + 一句映射），位置固定在**原理之后、诚实提醒之前**；**默认每页都放**。
> 上面的块数已把这两块算进去（知识卡片在首屏、生活化举例在原理之后）；七段式与长动线式同理。

### 1.1 问答式八块（最常用，默认用它）

| # | 模块 | 形态 | 作用 |
|---|---|---|---|
| 1 | **首屏：H1 真问句 ＋ 右侧「知识卡片」** | 「X 是什么？为什么…」，**起名法见 §二**；卡片见 §1.3 | H1 与搜索意图**逐字对齐**（**展示 AI 核心知识点 · 口语 · 主体 6–14 字**）；卡片 = **本页 AI 概念速览**（本页命中全收，常见 3–5 条；**≥6 条切两张滑动**） |
| 2 | 副标题 | 见 §3 三手法 | 承接 + 给自检动作 |
| 3 | **一句话回答** | 大字陈述 + 句内小图，加粗 3 处；桌面超过 2 行时按语义拆成 2–3 段 | **先把结论给完**；H1 含 AI 术语时，先一句人话解释它；长答糊成一个 `p`，或按字符硬切 |
| 4 | 主体 · 可玩装置 | 见 `02-互动策略选型.md` | 亲手看一遍 |
| 5 | 展开 · 原理/清单卡 | 双卡 / 三卡 / 多格 | 补机制，可跳读 |
| 6 | **生活化举例** | 见 §十二：三拍小剧场 + 两格场景图 + 映射句 | **每页都有**：把原理落回一个家常场景（贴近 → 卡住 → 换法），收尾映射回本页术语 |
| 7 | 诚实提醒 | 一句限制或边界 | 防止过度乐观 |
| 8 | **takeaway 4 条** | 「✅ 这一页的 4 个要点」 | 可整段抄进笔记，**收在全页最后** |
| — | 小奈教练卡（**条件项**） | 见 `04-小奈教练接入.md` §0 | 从「看懂」到「用自己事」；**只有带互动装置的页面才有** |

**页面上的块序（照这个排，别插队）**：
`首屏（H1 + 副标题 + 知识卡片） → 一句话回答 → 装置（+小奈卡） → 原理/清单卡 → 生活化举例 → 诚实提醒 → takeaway → 页脚`

**页面没有眉标 / 组定位标签**，直接从 H1 开始（`{{组定位}}` 占位符已从模板移除，别再自己加回来）。

**没有 CTA、没有「下一节」、没有任何超链接、没有付费墙。** 问答式页面的定位是「读到就赚」，加这些就变味了（红线 9 / `01` §2.3）。

**装置（第 4 块）和「小奈教练卡」是绑定的**：有装置 → 配卡；没有装置（纯知识页）→ 不配卡。见 `04` §0。

**页脚固定只写一句**（每个页面都一样，不写内容出处）：

> 教学示意：页面中的数值为演示用途，不对应某个产品的真实输出。

数据来源 / 近似值声明**不写页脚**，写在**装置下方的 `.demo-note`**。

### 1.2 需要叙事案例时（路径式阅读才用）

案例格式固定三拍，缺一不可：

1. **先给一个「看起来很成功」的完整答案** —— 让读者认同「这份答案能用」，落差才成立。
2. **再用具体数字翻车** —— 数字全部具体（12 份 / 800 元 / 11:58 / 38 分钟），**翻车点不是答错，而是问题里从未出现的条件**。
3. **归因到提问者盲区** —— 把「工具的局限」重新表述为「我的盲区」，责任落回读者身上，才有学习动机。

### 1.3 首屏右侧：「知识卡片」（**每页都有**）

这一页会冒出好几个 AI 词。这张卡**只做一件事：把本页出现的 AI 概念，在读者进页第一眼就摆成一张「术语地图」**——
读者往下读时，每个词都已经混过脸熟，正文里再遇到时已经有了锚点。
位置固定在**首屏右侧**（模板 `.hero` 里的 `aside.ai-facts`，替换掉了旧版首屏配图；卡片就是首屏的视觉主体）。
它不占正文块位：正文的收尾仍然是 takeaway。

**概念标准（每条都必须满足）**：每条必须是一个**可命名的 AI 概念**（术语 / 机制 / 现象 / 指标），
有明确所指、能在 `scripts/ai_concepts.json` 里找到定义；**不写动作、步骤、操作建议、判断题或感受**。
每条统一写成「概念名：1–2 句定义 + 一句类比 / 边界」。

**收词规则（红线 7）**：

```
① 本页正文命中的词          ← 主体：全收，条数不限（常见 3–5 条）
② 本课在大纲里那一节命中的词  ← 不足 3 条时补
③ 与本页主题相关的概念        ← 还不够才用：先词典同类，再联网搜
```

**条数不限**：写多少条，看本页命中了多少——把本页出现的概念全列上（常见 3–5 条），一条不嫌少、七条不嫌多。
**排序**：本页主题概念（H1 讲的那个）放第一条；其余按正文首现顺序。
**条目多的时候**（≥6 条）：**切两张、横向滑动看**（见下），每条压到 1–2 句——**只许压缩与分组，不许丢词**。
第 ③ 层是**兜底**，不是捷径：补进来的词必须**与本页主题强相关**（判据见 §1.6）。
难度锚点是**本页正文的措辞水平 + 本课的教学目标**，不是讲师脑子里的知识量——讲深了，读者会在这里掉队。

**定义一律从 `scripts/ai_concepts.json`（概念词典）取**，不临场发挥。
写卡前先跑一次扫描拿本页命中清单与草案：

```bash
python3 scripts/scan_ai_concepts.py \
  --page 本页.html --outline 本课大纲.md --section "本课在大纲里的那一节"
```

A 段 = 本页命中的词（**都要进卡**），B 段 = 本课该讲但本页没提的词（**补足条数的候选**），C 段 = 拼好的草案，D 段 = 疑似 AI 词但**词典没收录**。
**词典里找不到的词，先把 1–2 句解释补进词典，再引用**——不要绕过词典临时编（下次还会用到它）。

**逐条怎么写**（举一个 Token 页的例；每条仍 1–2 句）：

| # | 写什么 | 例（定义取自词典） |
|---|---|---|
| 1 | **主题概念：本页这件事正式叫什么**，放第一条 | 「**词元（Token）**：模型读写文本的最小单位，一个中文字常常是 1–2 个 Token，一个英文单词也常被切成几块。**字数不等于 Token 数**：数字、符号、生僻词会被切得特别碎。」 |
| 2 | 本页正文命中的其它概念，按首现顺序 | 「**上下文窗口**：模型一次能「看到」的文本上限，超过的部分会被截断或遗忘。它决定模型「记不记得前文」。」 |
| 3 | 同上；词典里有易混概念的，顺带一句边界（`confusable` / `diff`） | 「**按 Token 计费**：用多少算多少，输入和输出分别计价，通常输出比输入贵几倍——和包月订阅不是一回事。」 |

**四条约束**（写歪了就会变成没人看的通用科普，或者又变难）：

1. **本页命中的概念只许收全，不许漏。** 正文里出现的 AI 概念，卡里就要有——这是这张卡的及格线。
2. **每条 1–2 句（约 40–80 字）**，一句定义 + 一句类比/边界，**讲透但不展开**。
   再长就成了正篇，该把这半段挪到前面去。
3. **至少两条点着本页或本课的具体内容。** 判据：把本页 H1 换掉，这些句子还成立吗？
   **全都能成立 = 写成了泛泛科普，重写。**
4. **每条只讲一个概念**，**不要再在解释里引新词**——多引一个词，读者就要多查一次。
    **定义一律从 `scripts/ai_concepts.json` 取，找不到就先补词典再引用。**

**不足 3 条时**（短页、纯操作页常见）：按 ② ③ 补到 3 条左右（见 §1.6）；补不齐就有几条写几条。
**唯一例外**：这一页确实与 AI 毫无交集（罕见）→ 整块省略，并在 Phase 1 的诊断清单里写明理由。
**不要在页面上留一张空的卡。**

**卡片太长时：切两张，横向滑动看**（别让首屏被长清单拉长）

| 情况 | 版式 |
|---|---|
| ≤5 条、卡片不高 | **单张静态卡**：`aside.ai-facts` + `facts-head` + 一个 `<ul>`（模板默认版） |
| **≥6 条**，或单张卡高超过首屏约 60%（约 540px） | **两张滑动卡**：容器加 `data-facts-switch`；`facts-head` 里加方块页码 01 / 02（`role="tablist"`）；清单外套 `.facts-track`，切成两张 `.facts-page` |

**怎么切（三条纪律）**：

1. **对半切、每张 3–4 条**：6→3/3、7→4/3、8→4/4、9→5/4、10→5/5。第一张放**主题概念（原第一条）+ 接下来几条**，第二张放余下的。
   排序总规则不变（主题词在前、其余按首现顺序），只是分成两段连续展示。
2. **只做视觉分组**：概念全收不变；两张卡里每条的 `<b data-term>` 一条都不能少——下划线脚本从整块 `.ai-facts` 读词，两张卡一起算。
3. **计数文字改成「N 个概念，两张卡翻看」**；每张卡里 `data-rv` 的 `--d` 从 0 重新数（0 / 80ms / 160ms / 240ms）。

**骨架两头都照抄模板、不要改**：首屏注释里的「知识卡片·长卡版式」（`aside.ai-facts[data-facts-switch]` → `.facts-nav` 页码 + `.facts-track` 里两张 `.facts-page`），加上页底「知识卡片翻页（复用段）」。
它负责页码点击 / 左右方向键 / 横向滑动切换，`prefers-reduced-motion` 下切换为瞬间；**短卡页用不到它，整段删**。
切完自检一嘴：**单张卡（含页码那一行）的高度明显低于首屏**，滑动只换内容、不改变卡片外框位置。

### 1.4 词条在正文里的下划线（**卡写完后必做**）

卡片不是终点——读者是在**正文里**遇到这些词的。所以卡里每个概念词都要「就地可查」：

**做法只有一步：给每条的 `<b>` 都填 `data-term`。**

```html
<li><b data-term="注意力机制|Attention|attention">注意力机制（Attention）</b>：让模型在处理每个词时…</li>
<li><b data-term="关键词">关键词</b>：注意力给每个词都算权重…</li>
<li><b data-term="上下文窗口|context window">上下文窗口</b>：模型一次能读进去的文字上限…</li>
```

页脚那段「**术语下划线（复用段）**」脚本会自动完成其余全部工作：

| 它做什么 | 说明 |
|---|---|
| **取词** | 从卡里读 `<b data-term>` 与该条 `li` 的文字——**词表与解析只有卡片这一处**，改卡就自动同步，两边不会说两套话 |
| **定位** | 在**正文里该词的第一个出现处**加 `.ai-term`（一条只标一次；逐词重扫，所以「第一个」永远是当前 DOM 顺序里的第一个） |
| **交互** | 鼠标悬浮、键盘 Tab 聚焦、触屏点按都显示解析气泡；`Esc` / 滚动 / 点空白处收起 |
| **自动避让** | 跳过 `.demo`（装置）、`.coach`（陪练卡）、`a`（链接，页面里本就不该有）、`.ai-facts`（卡片自身）、`script/style/button/input` 等；也可在任意祖先上加 `data-no-term` 手动关掉一整块 |

**四点注意**：

1. **别名用 `|` 分隔**，填的是**正文里真实出现的写法**（正文写「注意力机制」，`data-term` 就得有「注意力机制」，写全角括号的正式名匹配不上）。
2. **每条都填**——卡里已经全是概念，不再有「动作条」；若该词在正文里没出现，脚本自然标不上，不影响卡片。
3. **命中标题是正常的**：如果这个词的首次出现就在 H1（很常见，比如「注意力机制到底是什么？」），下划线就落在 H1 上——这正是它第一次露面的地方，不需要回避。
4. **两张卡（长卡版式）不用另做处理**：脚本从整块 `.ai-facts` 里读 `li b`，**两张卡一起算**；别把第二张卡挪到 `.ai-facts` 外面，否则那段卡里的词读不到定义。

### 1.5 一批多页：本页命中照收，补词不重复（红线 8）

一次生成的多页（一组 2–5 页，跨组同理）里，**知识卡片按页说话**。

**规则只有两条**：

- **本页正文命中的 AI 概念：全收，不做跨页去重。** 每页都会被单独打开，本页的卡就该列本页的词；同一个词在别页也出现，定义都取自同一份词典，口径天然一致，不算「重复注水」。
- **补进来的词**（本页没提、从大纲本节或同类兜底的）：**不跨页重复**——这些词别页已经讲过了，本页再挂一遍没有信息增量。

**做法：写卡时按顺序串一个台账**（Phase 3 每页跑扫描时做，不必提前分配）。

```bash
U=/tmp/本批概念台账.txt          # 空文件起步
python3 scripts/scan_ai_concepts.py --page p1.html --outline 大纲.md --section "环节 3" --used "$U"
python3 scripts/scan_ai_concepts.py --page p2.html --outline 大纲.md --section "环节 5" --used "$U"
```

- `--used "$U"`：**读**台账里已进过卡的概念（**B 段的补词候选**标 **✗**、C 段补词时跳过），跑完再把本页采用的**追加**进去。同一个文件逐页连用即可，不用手工维护。
- `--exclude "词A,词B"`：临时手动排除（词典 key 或中文词形都认）。

**补词撞车时的优先级**（重要）：

```
1. 换词   —— 从本页 B 段（大纲本节）另挑一个没被占用的
2. 找相关 —— 词典同类里找与本页主题强相关的（§1.6 第 ③ 层）；都没有才联网搜
3. 认薄   —— 实在换不出，有几条写几条，并在交付说明里写明
```

**凑不齐 3 条不是错**：卡的内容以本页实际命中的为准；只有连 1 条强相关的都找不到（这页与 AI 真的没有交集），才整块省略这张卡。

### 1.6 本页概念不足 3 条时：三层阶梯（红线 7）

短页、纯操作页，本页命中的概念不足 3 条是常事（大纲那节也可能没写几个 AI 词）。
**这时候不要硬塞一个热词，也不要就这么空着**——按下面的阶梯往下走：

| 层 | 来源 | 怎么拿 | 代价 |
|---|---|---|---|
| ① | **本页正文**命中的词 | 跑扫描看 A 段 | 主体，**全收** |
| ② | **本课在大纲那一节**命中的词 | 扫描加 `--section`，看 B 段（标 ✗ 的避开） | 本课该讲，读者不会觉得跑题 |
| ③ | **与本页主题相关的概念** | 见下面两步 | 兜底，**必须强相关** |

**第 ③ 层分两步走，顺序不能反**：

**③-a 先查词典同类**（免费、离线、定义现成、可复现）：

```bash
python3 scripts/scan_ai_concepts.py --related "本页主题词"   # 传词典里的词 → 列同类
python3 scripts/scan_ai_concepts.py --related "模型基础"     # 也可传类别名 → 列该类全部
```

词典每词带 `category`（模型基础 / 交互 / Agent 与工具 / 开发 / 产品），同类之间天然互为相关概念。
**扫描脚本会在候选不足时自动把这份候选打出来**：本页命中不足 3 条 → `ℹ️` + 同类列表；
本页一条都没命中 → `⚠️` 并要你走这一层。看到就照做，别忽略。

**③-b 词典也没有，才联网搜**：搜「本页主题 + 相关 AI 概念」，挑**读者读完这页会自然想问的那个词**。
搜到的概念**先按 7 字段（6 字段 + `category`）补进 `scripts/ai_concepts.json`，再采用**——
不要在页面里现编一句定义（下次还得重编，而且口径会飘）。这正是词典「边用边长」的机制。

**第 ③ 层的唯一红线：必须与本页主题强相关。** 判据还是那一句——
**把这个词放进别的页还成立吗？** 成立（比如任何页都能挂个「大模型」），就是热词科普，**不许进卡**。

**兜底了还是不行**：那就承认这页确实薄——**有几条写几条**，并在交付说明里写明；
如果连 1 条强相关的都找不到（这页与 AI 真的没有交集），**整块省略这张卡**，同样写明理由。

---

## 二、H1 起名法：展示 AI 核心知识点 · 精简 · 问句

H1 是这一页唯一的钩子——读者要么被这句话勾住，要么永远不会往下读。
**起名只花两分钟，却决定这一页有没有人进来。别省这两分钟。**

三条不可破：

1. **必须是问句。** 名词短语（「Token 计费机制」）一律不合格——那像目录条目，不像人话。
2. **必须展示一个与 AI 相关的核心知识点。** 读者读完标题，要能指认「这页讲的是哪个 AI 概念 / 机制 / 能力边界 / 使用决策」。只出现「AI」两个字、却看不出具体知识点的标题，不合格。
3. **越短越好。** 主体 **6–14 字**，双问句放到 **20 字**为止。超了先砍；砍不动，说明这一页塞了两个问题，该拆。

### 2.1 照着这个语感起

> 同一个问题，为什么每次答案不一样？
> AI 客服为什么那么蠢？
> Siri 和 ChatGPT 是一种东西吗？
> 免费的 AI 够用吗？什么时候值得付费？
> API 是什么？和开会员有什么区别？
> 生成一张图为什么贵几十倍？
> AI 视频为什么按秒收费？
> 什么是 API 中转站？
> 「拼车号」「共享号」是什么？
> 我的聊天记录会被拿去训练吗？

**每一句背后都要站着一个 AI 知识点**——标题负责把它勾出来，正文负责讲清：

| H1 | 这页真正讲的 AI 知识点 |
|---|---|
| 同一个问题，为什么每次答案不一样？ | 生成的随机性 / temperature |
| AI 客服为什么那么蠢？ | 上下文、知识库与幻觉 |
| Siri 和 ChatGPT 是一种东西吗？ | 规则式系统 vs 生成式大模型 |
| 免费的 AI 够用吗？什么时候值得付费？ | 能力与成本边界 |
| API 是什么？和开会员有什么区别？ | API 与订阅计费 |
| 生成一张图为什么贵几十倍？ | 图像生成的成本结构 |
| AI 视频为什么按秒收费？ | 视频生成的计算成本 |
| 什么是 API 中转站？ | API 接入与代理 |
| 「拼车号」「共享号」是什么？ | 账号共享与风险 |
| 我的聊天记录会被拿去训练吗？ | 数据隐私与训练授权 |

语感四特征：**口语助词**（到底 / 才是 / 也能 / 还）· **第二人称**（我 / 你）· **具体锚点**（几十倍 / 按秒 / 3 分钟 / 每次）· **双问句收尾**（再问出一层）。

### 2.2 六种句式模板（按命中率排）

| 句式 | 骨架 | 例 |
|---|---|---|
| **是什么** | X 是什么?（可加一层延伸问） | 最近很火的 Skill 是什么? |
| **有什么意义 / 强在哪** | X 有什么意义? / X 到底强在哪? | 「提示词工程」有什么意义? |
| **怎么选 / 怎么写** | X 有哪些?该怎么选? | 国产大模型有哪些?该怎么选? |
| **值不值** | X 够用吗?什么时候值得付费? | 免费的 AI 够用吗?什么时候值得付费? |
| **为什么（先说落差）** | 为什么 X 这么贵 / 这么慢 / 按秒收费? | 生成一张图为什么贵几十倍? |
| **跟我有关吗** | 我的 X 会被…吗? / 不会 Y 也能…吗? | 我的聊天记录会被拿去训练吗? |

### 2.3 四个忌讳

| 别写 | 为什么 |
|---|---|
| 名词短语（「大模型选型指南」） | 读者不会这样搜，也看不出跟自己有什么关系 |
| 「一文讲清 / 详解 / 入门指南」 | 编辑口吻，不是读者口吻，且零信息量 |
| 堆两个以上术语（「Agent 与 RAG 的协同机制」） | 一页只留一个概念名，多一个就多一道门槛 |
| 用 `《书名号》` 包术语 | 要强调用 `「」`；书名号看起来像在引别处的文章 |
| 只有「AI」没有知识点（「如何用 AI 提升效率」） | 读者不知道这页讲什么，也搜不到——AI 在这句里只是装饰 |
| 泛职场 / 泛效率标题（「用 AI 做时间管理」） | 换个工具还是同一句，没有 AI 知识增量 |

### 2.4 改稿对照（自检时用）

| 初稿 | 改后 |
|---|---|
| Token 计费机制 | 为什么同一句话，我这边更贵? |
| 提示词工程实践指南 | 「提示词工程」有什么意义? |
| 大模型 / Agent / 应用三层架构 | 模型、Agent、应用是什么关系? |
| API 与会员订阅的差异 | API 是什么?和开会员有什么区别? |
| 如何用 AI 提升工作效率 | AI 客服为什么那么蠢? |
| AI 工具使用技巧 | 免费的 AI 够用吗?什么时候值得付费? |

**写完念一遍。** 念着别扭的，读者也不会搜。

### 2.5 核心知识点自检（起完名逐条过）

- **指认测试**：读完标题，能用一句话说出「这页讲哪个 AI 概念 / 机制 / 能力边界」吗？说不出，重写。
- **替换测试**：把标题里的 AI 对象换成任意一个非 AI 工具，句子还成立吗？成立 = 没有 AI 知识增量，重写。
- **搜索测试**：这句话像用户会在搜索框里敲的吗？不像，重写。
- **锚点测试**：有没有具体锚点（免费 / 付费 / 几十倍 / 按秒 / 每次 / 一次）？没有就加一个。

## 三、副标题三手法

副标题的任务是**让人读下去**，外加**埋下本页最想让他记住的那件事**。

| 手法 | 结构 | 例 |
|---|---|---|
| **术语祛魅** | 点出「你天天看见但从没搞懂」的词 → 承诺一个动作 | 「账单上写着『按 X 计费』，新闻里动不动『百万 X』，这颗 X 到底是个什么东西？**这一页带你亲手把一句话切开看看。**」 |
| **复述错误归因** | 先说出读者最常做的错误归因 → 换一个正确解释 | 「第 1 轮明明说过的事，第 20 轮它答得像完全没听过。**它没坏，也没敷衍你**，只是那句话已经**不在它眼前**了。」 |
| **畏难 → 反转 → 追加价值** | 先说出畏难 → 反转为一句人话 → **再补一个附加价值** | 「开会总听到『…』，**听着像什么大工程**。其实它就是给 AI 配了个**随用随查的书架**：考试可以开卷了，**还得把翻到的那页指给你看**。」 |

**第三种最完整**：反转之后那半句（「还得把翻到的那页指给你看」）顺手预告了本页的核心卖点。
- 埋「引用」→ 后文讲出处
- 埋「亲手切开」→ 后文是装置
- 埋「不在它眼前」→ 后文讲机制

**别写「你将学到…」。** 速览也不给空话，给**一把可自测的尺子 + 一个自检动作**：
> ✅「读完能认出自己停在哪一层，以及下一步写哪一句。」
> ❌「本课将介绍 X 的定义、原理与应用。」

## 四、一句话回答：一个资产，四个落点

首屏那句结论，**同时在四个地方出现，但四段话各写各的**：

| 落点 | 写给谁 | 语气 | 内容重心 |
|---|---|---|---|
| 首屏 `一句话回答` | 只读一句就走的读者 | 人话解释 | **结论**：加粗「定义 + 类比 + 后果」三处 |
| `meta description` | 搜索结果 | 带动作词 | **钩子**：含「来玩玩…」「拖一下…」 |
| 结构化数据 `FAQPage.answer` | 搜索引擎 | 完整句 | **含类比的完整句**（类比本身是完整信息） |
| 目录卡摘要（如写进目录） | 浏览目录的人 | 工具说明书 | **功能点 + 结果**：「交互分词器：点一句话看它被切成多少颗 Token，账单实时跳动」 |

> [!important] 别复制粘贴同一句四次
> 四个位置的读者不同，语气必须各自适配。**先给四个落点各定一个读者，再写四段话。**
> 唯一要保证一致的是：**H1 = 结构化数据里的 Question**，逐字相同。

### 4.1 标题里的 AI 术语，首屏必须先解释

H1 为了勾人会带术语（Agent / RAG / MCP / Token / Skill / API…）。**读者点进来，不代表他懂这个词。** 所以首屏「一句话回答」的第一件事，是用**一句人话**解释标题里的那个术语，再给结论。

三条要求：

1. **先解释，再展开。** 术语解释放在最前面，别让读者带着问号读完整段。
2. **只解释核心那一个。** 标题里有多个术语时，解释 H1 的主语；别把首屏写成术语表。
3. **用「人话 + 一个类比」**，不抄百科定义。解释完，再接原来的「定义 + 类比 + 后果」。

| H1 | 首屏第一句 |
|---|---|
| Agent 到底强在哪？ | **Agent 不是更会聊天，而是会自己拆步骤、调工具、把事做完的 AI。** 你把目标交给它，它自己排计划、找工具、交付结果——像把「问答题」变成「项目执行」。 |
| MCP 是什么？ | **MCP 是让 AI 用统一接口接外部工具和数据的协议。** 像给 AI 装了一个标准插座：以前每接一个工具都要单独适配，现在插上就能用。 |
| RAG 能解决什么？ | **RAG 是让模型先查资料、再回答。** 像开卷考试：答案不是背出来的，而是先翻到那一页，再照着说。 |

> 反例：「Agent 是一种基于大语言模型的智能体系统，具备规划、记忆与工具调用能力。」——这是百科，不是人话。读者要的是「它跟我有什么关系」。

首屏只是第一处。**正文里每个新概念也都要在首现处解释**——完整标准（首现三件套 / 长度纪律 / 术语清点）见 §十一。

### 4.2 超过两行就按语义分段（红线 13）

**一句话回答是一块结论，不是一个无限拉长的段落。** 先把整块文字按单段放在 **1280px 桌面视口**试排：超过两行，就按意思拆成 **2–3 段**；不超过两行，保留单段。分段后整块自然可以超过两行——判断的是“原单段是否过长”，不是要求拆分后整块只剩两行。窄屏自然换行变多不算违规，不要为了少一行删内容，也不要用 `<br>` 或固定宽度假装“控制行数”。

分段顺序照首屏的内容逻辑走：**第 1 段先解释 H1 术语 / 给定义 → 第 2 段讲机制或类比 → 第 3 段讲后果或边界**。可以只拆成两段，但每段至少要有一个完整句子；原句本身过长时，先在分句处改写成 2–3 个完整短句，再分段，不能把一句话从中间掐断。术语、数字、公式、引号和 `.nb` 里的行内小图都要留在同一段内。

```html
<!-- 短答：不超过两行，单段 -->
<div class="statement" data-rv>
  <p><b>一句话回答</b>　{{定义 + 类比 + 后果}}</p>
</div>

<!-- 长答：超过两行，按语义拆段 -->
<div class="statement" data-rv>
  <p><b>一句话回答</b>　{{第 1 段：解释 H1 术语或给定义}}</p>
  <p>{{第 2 段：机制或类比}}</p>
  <p>{{第 3 段：后果或边界}}</p>
</div>
```

每段仍遵守「平均 ≤25 字、超 35 字就拆」与「一段 ≤3 句」。段间距由模板的 `.statement p + p` 提供，不要手写空段落。

## 五、takeaway：便签 · 固定 4 条，顺序固定

```
📌 这一页，带走 4 件事
1. 是什么   —— 这一页的核心概念，一句话
2. 代价/边界 —— 它为什么要紧 / 它在什么时候失效
3. 常见误区 —— 最容易搞错的那一处
4. 我能做什么 —— 一条今天就能用的动作
```

- **版式是便签**：浅灰底 + 顶部黑色「胶带」+ 白色分隔线，见模板 `.note`；暗色模式由 `--note-bg` / `--note-line` 令牌自动切换。
- **必须是 4 条**。4 条正好是「能抄进一页笔记」的上限；第 5 条开始就会有人挑。
- 句式统一：`**加粗结论**：一句人话`。
- 第 4 条一定可执行（"提示词写得精炼，就是在直接省钱"）。
- **与首屏那句呼应闭环**，但不要复制。

## 六、诚实提醒：别只夸不设限

三种写法，至少用一种：

| 写法 | 例 |
|---|---|
| **误区澄清** | 「常见误区：**字数不等于 Token 数**。数字、符号、生僻词会被切得特别碎。」 |
| **主动给软肋** | 「它保证的是『有据可查』，管不了『据是否靠谱』。所以一半功夫要花在整理文件上。」 |
| **给使用边界（不下链接）** | 「本页只讲『怎么查』；至于『怎么建库』，那是另一件事，这里不展开。」 |

页面里**同时写「误区」和「软肋」**，比只写一句「注意」强得多。**先给能力，再给边界，最后给一个可执行动作。**

---

## 七、解释「哪个词在承重」

给了模板/判据之后，必须**点出其中哪一个词在承重**，否则学员会抄走一整段但漏掉关键半句：

> 「少了『**先不要替我做假设**』这半句，AI 可能会自行补上『大家没有忌口』之类的默认条件，未知项又会被一段顺畅的文字盖住。」

同理适用于装置文案：**页面里每一次「特意标记」都要有正文去命名它**（第 1 轮那张纸条为什么是琥珀色的？页面得说）。

---

## 八、文案与题目互为注解

最高级的一种写法：**正文里的判断句，就是题目里埋的那处特例**。

- 正文写「这五类**不等于一定是错的**，它们表示『先别直接写进笔记』」→ 题目里五处**埋一处真的**。
- 正文写「评价要对层」→ 题目第 4 题专门打断「看到模型名 → 模型层」这条捷径。

做法：**先写下本页最重要的那句判断，然后把它设计成一道题的特例。** 学员做错那一刻读到解释，才算真的读到。

---

## 九、写稿顺序（照这个顺序写，返工最少）

```
1. 写下 H1（读者会问的那句话）——五秒定生死，先按 §二 起名法过一遍
2. 写下首屏「一句话回答」（定义 + 类比 + 后果）
3. 写 takeaway 4 条（此时你会发现论点站不站得住）
4. 写副标题（从上面三条里提炼反差）
5. 定题型，写装置的数据（文案 + 数据一起写）
6. 写原理卡（补机制）
7. 写「生活化举例」：三拍小剧场（贴近 → 卡住 → 换法）+ 一句「场景 → 本页术语」的映射（§十二）
8. 写诚实提醒（边界 + 误区）
9. **术语清点**：把全文技术词列一遍，每个新概念的首现处补齐解释（§十一），不留裸术语
10. 跑 `scripts/scan_ai_concepts.py`，据 A 段写「知识卡片」——**本页命中的概念全收**（常见 3–5 条，不足 3 条从 B 段补）
   （**定义取自词典**，见 §1.3）；
   顺手给每条的 `<b>` 都填上 `data-term`（正文里的词形，别名用 `|` 分隔，见 §1.4）
11. （本页有装置才做）写小奈教练卡的 prompt（含硬约束）；纯知识页跳过这一步
12. 最后才写 HTML
```

## 十、去 AI 味：短句、人话、具体

读者一眼能看出「这是 AI 写的」，通常不是因为内容错，而是**腔调不对**。按下面六条写，AI 味会掉一大半。

### 10.1 六个症状（见到就改）

1. **套话连接词**：「不是…而是…」「不仅…还…」「换句话说」「值得注意的是」「这意味着」「本质上」。
2. **抽象名词堆叠**：「能力边界」「认知框架」「核心逻辑」「底层机制」「价值闭环」。
3. **三段式排比 / 对仗**：读着顺，但没信息。
4. **空泛承诺**：「让我们一起…」「你会发现…」「相信你一定能…」。
5. **解释过度**：一句话能说清，写成三句。
6. **先术语后解释**：读者还没懂词，先被术语拦住。

### 10.2 六条写法

- **一句一个意思，平均 ≤25 字。** 超过 35 字就拆成两句。
- **先给动作或例子，再给术语。** 读者先看见，再命名。
- **能删的形容词都删**：重要的、核心的、关键的、真正的、本质上。
- **一段 ≤3 句。** 一段只讲一件事。
- **数字写具体**：3 分钟、2 小时、5 条；不写「快速」「高效」「大幅」。
- **念出来**：像不像你平时跟同事解释一件事？不像就重写。

### 10.3 改稿对照

| AI 味 | 改后 |
|---|---|
| 这不仅提升了效率，更重塑了工作方式。 | 原来 2 小时的活，现在 5 分钟做完。 |
| 本质上，它是通过上下文窗口来管理记忆的。 | 它一次只能读固定长度的文字，超了就忘。 |
| 值得注意的是，权重并不等于理解。 | 权重高只说明它看了这儿，不代表它看懂了。 |
| 让我们一起动手实践一下吧！ | 点下面任意一句，看它怎么被切开。 |
| 该机制在多种场景下均具有广泛适用性。 | 写文案、查资料、做表格，都能用。 |
| 这是一个需要综合考虑多方面因素的复杂问题。 | 先看三件事：给谁用、花多少钱、多久要。 |

### 10.4 交稿前自检

- [ ] 删掉所有「这意味着 / 本质上 / 换句话说 / 值得注意的是」，意思有没有少？没少就删。
- [ ] 每句念一遍，超过一口气的长度就拆。
- [ ] 每段问一句「这段在解释什么」，一句话说不出就重写。
- [ ] 有没有一句「换个 AI 也能写」？有就删。
- [ ] **每个新概念第一次出现，有没有一句人话解释？**（做完术语清点；判据见 §十一）

第 3 步是试金石：**如果 takeaway 凑不出 4 条，说明这一页的论点不成立**，回去重新选题，别硬写。

## 十一、小白视角：新概念首现必解释（红线 10）

**读者默认是「零基础的小白」**——第一次接触这个主题，也没读过同组别的页；他不知道 Token、不知道 API、分不清「模型」和「产品」。用户明确说「读者有基础」时才放宽。**判据只有一条：读者不需要另外查资料，就能顺着往下读。**

**做法：每个新概念，在它第一次出现的地方就地解释。** 三件套，可裁到两件：

1. **一句人话定义**：不用任何术语，说清「它是干什么的 / 会怎么样」。
2. **一个类比或例子**：拿日常事物对上号（小抄、排队、点餐、开卷考试）。
3. **一句后果**（可选）：不知道它会怎样，或知道了能怎样。

| 位置 | 要解释什么 |
|---|---|
| 首屏「一句话回答」 | H1 里的那个术语（§4.1） |
| 正文任何一段 | 每个**第一次出现**的新概念——装置文案、原理卡、诚实提醒里都不例外 |
| 知识卡片 | 卡里的条目本身就是解释（§1.3），正文里不用再展开 |

**长度纪律：一句话打底，最多两句。** 解释是「让读者别卡住」，不是加餐——一个概念写成一小段，页面就变成词典了。
**同一页只解释一次**：首现处解释完，后文直接用这个词。**跨页不豁免**——同组别的页解释过，本页照解释（页面会被单独打开；「批内不重复」只约束卡片里的补词，红线 8）。

| 坏（裸术语） | 好（首现三件套） |
|---|---|
| 向量数据库让检索更快。 | **向量数据库**：把文字变成一串数字、按「意思像不像」找东西的仓库。像图书馆按内容摆书，不按书名。 |
| 参数越多，模型越强。 | **参数**：模型里可调的旋钮数量，训练就是把这些旋钮拧到合适的位置。旋钮多能装的事多，也更费算力。 |
| 用 API 调用就行。 | **API**：程序之间打电话的号码。报出号码（接口地址）和暗号（参数），对方把结果送回来。 |

**英文缩写**：首现写成「中文全称（缩写）」，再补一句人话——「LSTM（长短期记忆网络）：会挑着记、挑着忘的循环网络」。全页**中文优先**，缩写只作对照。

**收尾动作：术语清点。** 写完文案，把全文技术词从头列一遍，逐个问两件事：
① 这个词，读者可能是第一次见吗？② 它的首现处有解释吗？
「裸着出现」的就地补解释；补不进、或读者根本不需要这个词的，说明这里可以不用它，换成人话。

## 十二、生活化举例（**每页都有**）：三拍小剧场 + 一句映射

**这一块回答一个问题：这个原理，读者在生活里见过吗？** 见过，就会信、就会记；没见过，前面讲得再准也是飘的。
所以每页在**原理之后、诚实提醒之前**插一段「家常小剧场」——用一个具体到能拍出来的生活场景，把本页原理**再讲一遍**。

### 12.1 固定三拍（缺一不可）

| 拍 | 干什么 | 例（1.1.1 外婆认猫记） |
|---|---|---|
| **1 贴近** | 一个具体的人 + 一件具体的事，一两句把场景搭起来 | 你出差三天，托外婆来家里喂猫，在冰箱上贴了张「猫的样子」清单：四条腿、有胡须、有毛、会喵喵叫。 |
| **2 卡住** | 老办法在哪儿对不上——具体到某个东西、某个数字 | 猫缩成一团睡在沙发角，腿和胡须全看不见；下楼又撞见无毛猫。两条都对不上清单。 |
| **3 换法** | 换了什么，结果怎么不一样 | 连着几个晚上陪她刷猫的视频，几百只看下来；她说不清「猫的样子」该怎么写，但一闪而过的猫影，她一眼认出。 |

### 12.2 一句映射（整块的落点）

三拍讲完，**必须有一句收尾把场景换回术语**，句式照 `.life-map`：**左边场景元素 → 右边本页术语**，
再用一句话点回本页正文（「第①站的词表就是这么越写越厚的」）。

- 例：`**清单 → 人写规则，刷视频 → 数据训练**：清单上写下的都管用，没写到的全漏……`
- **判据**：把这句里的场景词换成别页的，还成立吗？成立 = 没扣住本页，重写。
- 映射句要点着**本页的具体内容**（装置站点、原理栏的名字、正文里的例子），别写成「生活也是这样」这类鸡汤。

### 12.3 四条约束

1. **一个场景讲透，别罗列。** 不要「就像 A，又像 B，还像 C」——选一个，把细节写实。
2. **细节必须具体**：人名、物件、数量（「三个晚上」「几百只」）。模糊的场景（「一个人遇到了一件事」）不算。
3. **三拍各 1–2 句，整块 ≤120 字**（不含映射句）。这块是「落回生活」，不是新写一篇。
4. **不与正文已有类比重复**：首屏、原理栏用过的类比不要再讲一遍——要么换场景，要么把原来那句挪到这里写完整。

### 12.4 场景图（`.life-scene`，照模板骨架重画）

- 骨架固定：**两格对照**——左格「照老办法」翻车（出 ✗），右格「换新办法」成功（出 ✓）；
  右格中间一块蓝色方块（新办法 / 模型），左边流进「几百个例子」的小方块。
- 图里只留 **≤6 字的短标签**（格标题、物件名、结果），正文全部交给 HTML 三拍文字。
- **窄屏（≤600px）标签自动隐藏，只留图形**——所以三拍文字必须能独立讲清故事，不能依赖图里的字。
- 类名与时序（`la-*` / `--ld`）、动效降级与响应式的细节见 `references/06-视觉风格与配图.md` §2、§7。

### 12.5 常见写坏的样子

| 症状 | 修 |
|---|---|
| 场景是通用的（「就像生活一样，有的方法好、有的方法差」） | 换成一个能拍出来的具体场景（谁、在哪儿、干了什么） |
| 三拍只剩一拍（直接给结论） | 把「卡住」拍补出来——没有翻车，读者感受不到旧办法的边界 |
| 有场景没映射（讲完故事就结束） | 补 `.life-map`：左边场景 → 右边术语，再点回本页 |
| 和首屏 / 原理栏的类比重复 | 删一个，只留讲得最完整的那处 |
| 场景占了大半屏 | 砍到三拍各 1–2 句 |

## 十三、跨模块一致性：同一件事，全页一个说法（红线 12）

读者会**横向对照**：首屏说一句，原理区又说一句，takeaway 再总结一句——两处口径不一样，读者立刻觉得「这页自己都没想清楚」。

**做法：写完全文、动手写 HTML 之前，拉一张「主张台账」。** 这张表只用来自己核对：

| 主张 | 出现在哪些模块 | 统一口径 |
|---|---|---|
| 会不会查资料 / 查库 | 首屏副标题、知识卡片、一句话回答、原理卡、takeaway、结构化数据 | 「回答默认不是从数据库里查出来的；接上搜索 / 检索 / 工具才会去取外部信息」 |
| 回答怎么来的 | 一句话回答、装置结论、原理区 | 「一块一块预测下一个词」 |
| 数字 / 价格 / 规模 | 装置、`.demo-note`、原理、takeaway | 同一套数、同一单位、同一句来源声明 |
| 术语写法 | 全页 | 一种主写法；别名只在 `data-term` 里出现 |

**五类高频冲突**（写完逐类过一遍）：

1. **绝对化 vs 有限定**：「永远免费」和「按量计费」同时出现；「它不会出错」和「它也会编事实」同时出现。修法：给绝对化那句加限定（默认 / 通常 / 在…下），或改掉。
2. **装置结论 vs 原理区方向相反**：装置让人看到「越多越好」，原理却写「越少越好」。先定哪一个是本页结论，再改另一处。
3. **takeaway vs 诚实提醒打架**：提醒说「别信它的事实」，带走的 4 条却写「直接拿它查资料」。
4. **数字 / 单位 / 术语走样**：同一页里同一个数出现两个版本；同一个概念两种叫法混用又不说明。
5. **meta / 结构化数据与正文不符**：H1 改过，`description` 或 FAQ 的 `answer` 还是旧口径——这三处必须与正文逐字对口径。

**收尾动作**：改完任何一处，把关键词搜一遍（「不查」「永远」「一定」「免费」「只有」「完全」），确认别的模块没有留着旧说法。页面会被单独打开、被截图、被投喂给别的系统，矛盾只会被放大。
