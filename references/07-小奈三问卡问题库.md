# 小奈三问卡问题库（每页三道开放问题）

> [!abstract] 怎么用
> 1. **定三条主线**：本页在讲「整体机制 / 一个关键细节 / 能力边界」的哪三块。
> 2. **各写一题**：机制题、细节题、边界题各一道，**三道，不多不少**。
> 3. **检查**：每题 8–24 字、彼此独立、能脱离页面被回答、不预设答案。
> 4. **填卡**：把三题按顺序放进 `ASKS`，见 `04-小奈三问卡接入.md` §3。
>
> **三问卡不是测验**：没有选项、没有标准答案、不判对错。它只负责把读者刚看完装置后「最想接着问的三个问题」摆出来，点哪道发哪道。

---

## 一、三道题分别问什么

| 题型 | 目的 | 句式 | 例子 |
|---|---|---|---|
| **机制题** | 让读者弄懂「它到底怎么做到的」 | 「它是怎么…的？」 | 大模型是怎么把一句话变成回答的？ |
| **细节题** | 抓住一个最容易误解 / 对不上的点 | 「为什么 X 和 Y 对不上？」 | Token 为什么和字数对不上？ |
| **边界题** | 知道它什么时候会失灵、不该信 | 「它什么时候会…？」 | 它为什么说得流畅，却也可能一本正经地编？ |

> 三道题不是「同一件事的三种问法」。如果三题都在问「怎么用」，说明没有覆盖边界；如果三题都在问「是什么」，说明没有进入机制。

## 二、按页面类型选三问

### 2.1 原理 / 机制页

| 题 | 例子 |
|---|---|
| 机制 | 大模型是怎么把一句话变成回答的？ |
| 细节 | Token 为什么和字数对不上？ |
| 边界 | 它为什么说得流畅，却也可能一本正经地编？ |

### 2.2 流程 / 步骤页

| 题 | 例子 |
|---|---|
| 机制 | 一句话从输入到成稿，中间到底走了哪几步？ |
| 细节 | 哪一步最容易卡住，为什么？ |
| 边界 | 哪一步可以跳过，哪一步不能省？ |

### 2.3 参数 / 成本页

| 题 | 例子 |
|---|---|
| 机制 | 为什么同一个问题，每次答案不一样？ |
| 细节 | 温度调高以后，到底变了什么？ |
| 边界 | 什么任务不该把温度调高？ |

### 2.4 上下文 / 记忆页

| 题 | 例子 |
|---|---|
| 机制 | 上下文窗口满了以后，模型会怎么做？ |
| 细节 | 为什么聊得越久，它越容易忘掉最早的话？ |
| 边界 | 什么时候该开新对话，而不是继续聊？ |

### 2.5 知识库 / RAG 页

| 题 | 例子 |
|---|---|
| 机制 | RAG 是怎么从资料里找到答案的？ |
| 细节 | 为什么它找到了资料，还是会答偏？ |
| 边界 | 什么情况下它应该直接说「找不到」？ |

### 2.6 Agent / 自动化页

| 题 | 例子 |
|---|---|
| 机制 | Agent 是怎么把一个大任务拆成几步的？ |
| 细节 | 它为什么会在中途跑偏？ |
| 边界 | 哪些操作必须留给人确认？ |

### 2.7 对比 / 选型页

| 题 | 例子 |
|---|---|
| 机制 | 这两个方案的本质差别是什么？ |
| 细节 | 为什么便宜的那个在长任务上更贵？ |
| 边界 | 什么场景下应该选更贵的那个？ |

### 2.8 能力边界 / 风险页

| 题 | 例子 |
|---|---|
| 机制 | 它为什么会一本正经地编？ |
| 细节 | 为什么它越自信，越可能错？ |
| 边界 | 哪些问题必须人工核对？ |

## 三、可直接套用的问题

### 3.1 大模型基础

- 大模型是怎么把一句话变成回答的？
- 它为什么能接话，却不知道自己在说什么？
- 它什么时候会一本正经地编？

### 3.2 Token / 成本

- Token 为什么和字数对不上？
- 为什么中文和英文的 Token 数不一样？
- 同样一句话，为什么这次比上次贵？

### 3.3 上下文 / 记忆

- 上下文窗口满了以后，模型会怎么做？
- 为什么聊得越久，它越容易忘掉最早的话？
- 什么时候该开新对话，而不是继续聊？

### 3.4 RAG / 知识库

- RAG 是怎么从资料里找到答案的？
- 为什么它找到了资料，还是会答偏？
- 什么情况下它应该直接说「找不到」？

### 3.5 Agent / 自动化

- Agent 是怎么把一个大任务拆成几步的？
- 它为什么会在中途跑偏？
- 哪些操作必须留给人确认？

### 3.6 选型 / 微调

- 微调和提示词，本质差别是什么？
- 为什么微调后的模型更容易「只会在训练过的场景里表现好」？
- 什么情况下不值得微调？

### 3.7 多模态 / AIGC

- 文生图是怎么把一句话变成画面的？
- 为什么同一个提示词，两次生成的图不一样？
- 哪些画面它最容易画错？

## 四、好问题 / 坏问题

| ✅ 好问题 | ❌ 坏问题 | 为什么 |
|---|---|---|
| Token 为什么和字数对不上？ | 下面哪个是 Token？ | 选择题，不是开放问题 |
| 大模型是怎么把一句话变成回答的？ | 大模型是什么？ | 名词解释，不是追问 |
| 它什么时候会一本正经地编？ | 它是不是会编？ | 封闭问句，只能答是 / 否 |
| 为什么聊得越久，越容易忘掉最早的话？ | 这个为什么会这样？ | 指代不清，脱离页面无法回答 |
| 什么情况下应该直接说「找不到」？ | 请分析一下 RAG 的优缺点。 | 太泛，没有具体对象 |
| 为什么便宜的那个在长任务上更贵？ | 哪个方案更好？ | 预设了「二选一」，不是开放问题 |

## 五、三道题的自检

- [ ] **恰好三道**，机制 / 细节 / 边界各一题。
- [ ] 每题 **8–24 字**，读完能直接问出口。
- [ ] 三道题**彼此独立**，不是同一件事的三种问法。
- [ ] 每题都**自带对象**，不写「这个 / 它 / 上面说的」。
- [ ] 每题都**能脱离页面被回答**：遮住页面，小奈仍知道在问什么。
- [ ] **不预设答案**：没有「是不是 / 哪个对 / A 还是 B」。
- [ ] 卡面只写「点一个发给她」，**不写「没有标准答案」**。
