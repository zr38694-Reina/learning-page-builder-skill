# 小奈互动模式库（先选原型，再写卡）

> [!abstract] 怎么用
> 1. **查表**：在 §0 找到本页题型对应的**互动原型**。
> 2. **照抄**：只读对应原型那一节，抄 `readContext` / `buildPrompt` 两段。
> 3. **命名交付物**：从 §6 选一种形状，填死 3–5 个字段。
> 4. **验收**：过 §7 的五问。
>
> **提示词框是预填的**：页面加载时 `refreshPrompt()` 调用 `buildPrompt('')`，把完整指令填进框；学员只改「我的情况」，再一键发送。`refreshPrompt` / `resetPrompt` / 发送监听在 §2.2 给一份，**所有原型共用**，只换 `buildPrompt` 的业务文案。
>
> **一页只用一种原型。** 混用会让交付物退化成「一段既有表又有建议的话」。

## 一、先判断：学员手里剩下了什么

```text
学员刚在装置里做完的事
├─ 得到一个数 / 一个档位 / 一个判断      → 诊断型
├─ 走完一条流程 / 排好一版 / 定位一处坏点 → 对照型
├─ 得到一版可以修改的稿子 / 方案         → 改写型
└─ 看完一个过程 / 分完一堆条目           → 产出型
```

判据只有一条：**学员能不能把自己刚做的结果，原样交给小奈。**

交不出来（只剩「我看了」「我玩了」）→ 这张卡必然是空提示词框，先回去补装置状态，不要写卡。

交付物必须是一个**名词**：判断卡、对照表、改写稿、检查清单。写不出名词，说明原型还没选对。

## 二、诊断型（`01` / `02` / `04` / `05`）

**学员状态**：刚调出一个数字或选了一个档位，页面已经给出读数。
**交付物**：判断卡——结论｜依据（引用页面读数）｜阈值｜下一步。

### 2.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | 判断我该「压缩还是新开」 |
| 说明 | 她会先用页面上的轮数和占用率给出判断，再给一个阈值和一条下一步动作。 |
| 占位 | 这段对话主要在聊【】；已经确定【】；必须记住【】；现在卡在【】。 |
| 按钮 | 判断我该压缩还是新开 |

### 2.2 业务代码

```js
function readContext() {
  return [
    { k: '当前设置', v: rounds.value + ' 轮 / 上限 ' + cap + ' 轮' },
    { k: '页面读数', v: used + ' / ' + max + ' tokens（' + pct + '%）' }
  ];
}

var COACH_CONFIG = {
  concept: '上下文窗口',
  hard: [
    '不要把产品的长期记忆功能与上下文窗口混为一谈。',
    '不要假设你看过我未粘贴的聊天记录；信息不足时先问我。'
  ],
  deliverable: ['判断结论', '依据（引用页面读数）', '阈值', '下一步动作'],
  skeleton: '这段对话主要在聊【】；已经确定【】；必须记住【】；现在卡在【】。'
};

function buildPrompt(text) {
  var state = readContext().map(function (c) { return c.k + '：' + c.v; }).join('；');
  return '请用本页「' + COACH_CONFIG.concept + '」的视角，帮我判断这段对话该压缩还是新开。\n\n' +
    '我的情况：' + (text || '【在这里补一句你的情况；不填也可以直接发送】') + '\n' +
    '页面演示状态：' + state + '\n\n' +
    '【硬约束】\n' +
    '1. ' + COACH_CONFIG.hard[0] + '\n' +
    '2. ' + COACH_CONFIG.hard[1] + '\n\n' +
    '先只问一个会改变结论的问题；我回答后，再按「' +
    COACH_CONFIG.deliverable.join('｜') + '」四项给出方案。';
}

/* —— 预填 / 重置 / 发送（所有原型共用，不用改） —— */
var promptDirty = false;

function refreshPrompt() {
  $('coachInput').value = buildPrompt('');
  promptDirty = false;
}

function resetPrompt() {
  refreshPrompt();
  $('coachInput').focus();
}

$('coachInput').addEventListener('input', function () {
  promptDirty = true;
});

$('coachSubmit').addEventListener('click', function () {
  var input = $('coachInput');
  var prompt = (input.value || '').trim();
  if (!prompt) {
    $('coachStatus').textContent = '提示词为空，请先补一句你的情况。';
    input.focus();
    return;
  }
  /* 框里已是完整提示词：直接发送，不再二次拼装 */
  sendCoachPrompt(prompt);
});

$('coachReset').addEventListener('click', resetPrompt);

/* 页面加载即预填 */
refreshPrompt();
```

**装置状态变化时**：在回调末尾加 `if (!promptDirty) refreshPrompt();`——学员没改过就自动同步，改过就不覆盖。**这一段所有原型共用**；下面 §3 / §4 / §5 只换 `readContext` 与 `buildPrompt` 的业务文案，不再重复贴。`buildPrompt` 里的 `（我还没填写）` 也统一换成 `【在这里补一句你的情况；不填也可以直接发送】`。

### 2.3 交付物样例

```text
判断结论：该压缩，不该新开
依据：12 轮已占 75%，再聊 3 轮就会溢出；后半段一直在重复前文
阈值：超过 70% 且还要继续同一话题 → 先压缩，不新开
下一步：把「已确定 / 必须记住」两段摘成一张交接单，粘到新对话开头
```

## 三、对照型（`03` / `09` / `10` / `11` / `13`）

**学员状态**：刚走完一条流程、排出一版顺序、拼出一版成品，或指认了一处坏点。
**交付物**：对照表——我的素材｜每步实际发生｜我以为｜差异；收尾加「最该核对的一步 + 今天能做的一条动作」。

> [!warning] 这一类最容易写抽象
> 装置给的是**过程**，不是数值。如果 `readContext()` 只读「第几步」，prompt 里就没有学员自己的东西，小奈只能回一段通用解释。
> **必须让学员交一句原话 / 一版结果**，再把它逐格填进表。原话写在提示词框的「我的情况 / 我的原话」处，不要塞进页面状态。

### 3.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | **把我这句话拆成五步** |
| 说明 | 她会拿你写的那句话，逐步说明它在五步里各变成了什么，再指出你最该核对的一步。 |
| 占位 | 我打算发给 AI 的原话是「」；我最担心它【编数据 / 答非所问 / 语气不对】；这句话用在【】。 |
| 按钮 | 拆出容易出错的一步 |

### 3.2 业务代码（本页实测版）

```js
function readContext() {
  var out = [];
  var scene = document.querySelector('.scene.on');
  var h3 = scene ? scene.querySelector('h3') : null;
  out.push({ k: '演示进度', v: textOf('demoProgress') || '尚未开始' });
  out.push({ k: '正在讲的一步', v: h3 ? h3.textContent : '尚未开始' });
  return out;
}

var COACH_CONFIG = {
  concept: '逐块生成',
  hard: [
    '引用我的原话时逐字保留，不要替我改写，也不要补出我没说过的话。',
    '不要把页面上的五步流水线当成哪家产品的真实流程；Token 切分和每步细节因模型而异。',
    '不要替我保证答案都对；它只是按规律接话，说错了不会自己发现。'
  ],
  deliverable: ['五步对照表', '最该核对的一步', '今天能做的一条动作'],
  skeleton: '我打算发给 AI 的原话是「」；我最担心它出错的地方是【】；这句话用在【】。'
};

function buildPrompt(text) {
  var state = readContext().map(function (c) { return c.k + '：' + c.v; }).join('；');
  return '请用本页「' + COACH_CONFIG.concept + '」的视角，把下面这句话放进这条五步流水线，逐步对照。\n\n' +
    '我的原话：' + (text || '【在这里补一句你的情况；不填也可以直接发送】') + '\n' +
    '页面演示状态：' + state + '\n\n' +
    '【硬约束】\n' +
    '1. ' + COACH_CONFIG.hard[0] + '\n' +
    '2. ' + COACH_CONFIG.hard[1] + '\n' +
    '3. ' + COACH_CONFIG.hard[2] + '\n\n' +
    '先只问一个会改变结论的问题；我回答后，再按「' +
    COACH_CONFIG.deliverable.join('｜') + '」三项给出。';
}
```

**对照表的固定列**（写进 prompt，不让模型自由发挥）：

```text
| 步骤 | 我的原话在这里变成什么 | 我可能以为 | 实际发生 |
```

### 3.3 交付物样例

```text
| 步骤 | 我的原话在这里变成什么 | 我可能以为 | 实际发生 |
| ① 输入 | 「帮我把这份周报润色一下」 | 它在读我的周报 | 它只看到这句话本身 |
| ② 切 Token | 被切成若干小块 | 它按字理解 | 按模型自己的切法 |
| ③ 变向量 | 每块变成一串数字 | 只和同义词比 | 意思相近就靠近，不保证事实 |
| ④ 结合上下文 | 每块回头参考其他位置 | 它记住了全部历史 | 只看这次窗口里的内容 |
| ⑤ 预测下一块 | 一块一块接出润色稿 | 它核对过数据 | 没有查证机制，错了也会接着写 |

最该核对的一步：⑤——事实对错没有查证环节
今天能做的一条动作：发出前，把数字和专有名词逐项对照原始资料
```

## 四、改写型（`07` / `12`）

**学员状态**：刚在 A/B 里选了一边，或在预算里分完一轮资源。
**交付物**：改写稿——原版｜改写版｜改动理由｜风险。

### 4.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | 把「我选的这一版」改成能用的版本 |
| 说明 | 她会保留你的目标，只改其中一处最拖后腿的地方，并说明为什么改、可能带来什么风险。 |
| 占位 | 我选的是【A / B】；我要它完成【】；我不能让步的是【】。 |
| 按钮 | 改写我选的这一版 |

### 4.2 业务代码

```js
function readContext() {
  return [
    { k: '我选的版本', v: currentSide === 'a' ? 'A：模板话术' : 'B：具体话术' },
    { k: '页面结论', v: textOf('abVerdict') || '还没看完对比' }
  ];
}

var COACH_CONFIG = {
  concept: '具体话术比模板话术更容易被执行',
  hard: [
    '不要编造我的产品信息或客户背景；缺什么先问我。',
    '保留我写明的不可让步项，改写理由要对应页面结论，不要反着来。'
  ],
  deliverable: ['原版', '改写版', '改动理由', '风险'],
  skeleton: '我选的是【】；我要它完成【】；我不能让步的是【】。'
};

function buildPrompt(text) {
  var state = readContext().map(function (c) { return c.k + '：' + c.v; }).join('；');
  return '请用本页「' + COACH_CONFIG.concept + '」的视角，帮我改写我选的那一版。\n\n' +
    '我的情况：' + (text || '【在这里补一句你的情况；不填也可以直接发送】') + '\n' +
    '页面演示状态：' + state + '\n\n' +
    '【硬约束】\n' +
    '1. ' + COACH_CONFIG.hard[0] + '\n' +
    '2. ' + COACH_CONFIG.hard[1] + '\n\n' +
    '先只问一个会改变结论的问题；我回答后，再按「' +
    COACH_CONFIG.deliverable.join('｜') + '」四项给出。';
}
```

### 4.3 交付物样例

```text
原版：您好，关于您反馈的问题我们已经记录，会尽快处理。
改写版：您说的「周三之后还没收到退款」我查到了，今天 18:00 前会由财务原路退回；如果没到账，直接回复这条消息。
改动理由：把「已记录」换成可核对的时间点和路径，降低二次追问
风险：承诺了具体时间，需要确认财务实际排期；不确定就改成「今天内给您确认时间」
```

## 五、产出型（`06` / `08`）

**学员状态**：刚看完一次播放，或把条目分完堆。
**交付物**：清单 / 脚本——对象｜归属或步骤｜判断规则｜复用方式。

### 5.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | 生成我的「发布前检查清单」 |
| 说明 | 她会把页面上的过程拆成你能照着做的几步，并给每条一个判断规则。 |
| 占位 | 我要检查的东西是【】；我最怕漏掉【】；检查完要交给【】。 |
| 按钮 | 生成我的检查清单 |

## 六、交付物命名表（写卡前先填这一行）

| 交付物 | 固定字段（3–5 个） | 原型 | 什么时候用 | 反例 |
|---|---|---|---|---|
| **判断卡** | 结论｜依据｜阈值｜下一步 | 诊断型 | 页面在教一个二选一 / 够不够 | 「帮你分析一下」 |
| **对照表** | 我的素材｜每步实际发生｜我以为｜差异 | 对照型 | 页面在教一条流程 / 顺序 / 结构 | 「指出容易出错的一步」 |
| **改写稿** | 原版｜改写版｜改动理由｜风险 | 改写型 | 页面在教两版取舍 / 资源分配 | 「给点优化建议」 |
| **检查清单** | 对象｜归属或步骤｜判断规则｜复用方式 | 产出型 | 页面在教一次过程 / 一套分类 | 「总结一下重点」 |

三条硬规则：

1. **必须含学员原话或页面原值，至少一处。** 全是通用词的交付物，换个人也能用，等于没用。
2. **字段写进 prompt，用「｜」隔开。** 不写字段，模型就会自由发挥成散文。
3. **一屏放得下。** 超过 5 项就换更窄的交付物，或删掉最不重要的一项。

## 七、具体性六问（写完卡先过）

- [ ] **打开时框里是不是完整提示词？** 页面加载后已经预填页面读数、硬约束和交付物字段，学员只需改「我的情况」；还是空框 → 回 §2.2 接 `refreshPrompt()`。
- [ ] **点发送是不是直接发框内全文？** 不再用 `buildPrompt()` 包一层；框里是什么就发什么。
- [ ] **遮住「我的情况」**：prompt 还能执行吗？能 → 学员原话没被用上，回 §3 / §4 补。
- [ ] **遮住「页面演示状态」**：还能执行吗？能 → 状态是装饰，`readContext()` 读错了东西。
- [ ] **交付物能画出来吗**：能不能立刻画成一张表 / 一份稿？不能 → 回 §6 换交付物。
- [ ] **换个场景还成立吗**：把学员任务换成完全不同的行业，这张卡还成立吗？仍成立 → 写得太通用，重写标题与占位。

## 八、抽象 → 具体（高频对照）

| ❌ 抽象写法 | ✅ 具体写法 | 为什么 |
|---|---|---|
| 把「逐块生成」套到你的用法上 | 把我这句话拆成五步 | 标题要说清**产出什么** |
| 我要让 AI 做的事是【】 | 我打算发给 AI 的原话是「」 | 要素材，不要任务名 |
| 指出最容易出错的一步 | 填一张五步对照表，最后一行写最该核对的一步 | 表格能抄走，标签不能 |
| 你的任务落在五步中的哪一步 | 你的原话在每一步各变成了什么 | 任何生成都走完五步，「落在哪一步」不成立 |
| 先问一个会改变结论的问题（不举例） | 这句话一旦出错，你最不能接受事实错、格式错还是语气错？ | 给正例，模型才知道什么叫「改变结论」 |
| 页面演示状态：整段讲解文字 | 演示进度：第 3 / 5 步；正在讲的一步：变成向量 | 状态是学员看到的读数，不是教材正文 |
| 按「结论｜依据｜阈值｜下一步」给出方案（字段空泛） | 按「判断结论｜引用哪条页面读数｜超过多少就该动｜今天做什么」给出 | 字段要能直接填，不能是名词摆设 |
| 提示词里只写「别乱编」 | 「缺什么先问我，不要编造我的产品信息」 | 禁令要能执行，不是表态 |
| 打开卡片是空框，让学员自己拼 | 加载即预填完整提示词，只留「我的情况」给学员改一句 | 学员要的是「改一句就发」 |
| 点发送时又用 `buildPrompt()` 包一层 | 直接 `sendCoachPrompt(框内全文)` | 框里已经是完整提示词，再包会重复 |
| 装置一变就覆盖学员改过的提示词 | `promptDirty` 标记；改过不覆盖，点重置才重建 | 学员的修改不能被动画吞掉 |
