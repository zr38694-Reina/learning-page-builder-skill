# 小奈互动模式库（先选原型，再写卡）

> [!abstract] 怎么用
> 1. **查表**：在 §0 找到本页题型对应的**互动原型**。
> 2. **照抄**：只读对应原型那一节，抄 `readContext` / `buildPrompt` 两段。
> 3. **命名交付物**：从 §6 选一种形状，填死 3–5 个字段。
> 4. **验收**：过 §7 的六问。
>
> **提示词是写好的**：页面加载时 `refreshPrompt()` 调用 `buildPrompt()`，把 **3 行完整版**填进框；素材全部来自页面当前状态，**没有 `【】` 待填空**，学员打开即可一键发送。`refreshPrompt` / `resetPrompt` / 发送监听在 §2.2 给一份，**所有原型共用**，只换 `buildPrompt` 的业务文案。
>
> **一页只用一种原型。** 混用会让交付物退化成「一段既有表又有建议的话」。

## 一、先判断：学员手里剩下了什么

```text
学员刚在装置里做完的事
├─ 得到一个数 / 一个档位 / 一个判断      → 诊断型
├─ 走完一条流程 / 排好一版 / 定位一处坏点 → 对照型
├─ 得到一版可以修改的稿子 / 方案         → 改写型
└─ 看完一个过程 / 分完一堆条目           → 产出型
```

判据只有一条：**学员能不能把自己刚做的结果，原样交给小奈。**

交不出来（只剩「我看了」「我玩了」）→ 这张卡必然是空提示词框，先回去补装置状态，不要写卡。

交付物必须是一个**名词**：判断卡、对照表、改写稿、检查清单。写不出名词，说明原型还没选对。

## 二、诊断型（`01` / `02` / `04` / `05`）

**学员状态**：刚调出一个数字或选了一个档位，页面已经给出读数。
**交付物**：判断卡——结论｜依据（引用页面读数）｜阈值｜下一步。

### 2.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | 判断页面这段对话该压缩还是新开 |
| 说明 | 她会先用页面上的轮数和占用率给出判断，再给一个阈值和一条下一步动作。 |
| 提示词 | 页面加载时自动写好 3 行：当前设置 + 页面读数 + 判断卡字段；无待填空 |
| 按钮 | 发送给小奈教练 |

### 2.2 业务代码

```js
function readContext() {
  return [
    { k: '当前设置', v: rounds.value + ' 轮 / 上限 ' + cap + ' 轮' },
    { k: '页面读数', v: used + ' / ' + max + ' tokens（' + pct + '%）' }
  ];
}

var COACH_CONFIG = {
  concept: '上下文窗口',
  hard: [
    '数字是演示值，别把长期记忆和上下文窗口混为一谈'
  ],
  deliverable: ['判断结论', '引用哪条页面读数', '超过多少就该动', '今天做什么']
};

function buildPrompt() {
  var by = {};
  readContext().forEach(function (x) { by[x.k] = x.v; });
  return '请用「' + COACH_CONFIG.concept + '」的视角，判断页面这段对话该压缩还是新开，并给一个可执行的阈值。\n' +
    by['当前设置'] + '，' + by['页面读数'] + '；' + COACH_CONFIG.hard.join('；') + '。\n' +
    '先问一个会改变结论的问题；我回答后，按「' + COACH_CONFIG.deliverable.join('｜') + '」给出。';
}

/* —— 写好 / 重置 / 发送（所有原型共用，不用改） —— */
var promptDirty = false;

function refreshPrompt() {
  $('coachInput').value = buildPrompt();
  promptDirty = false;
}

function resetPrompt() {
  refreshPrompt();
  $('coachInput').focus();
}

$('coachInput').addEventListener('input', function () {
  promptDirty = true;
});

$('coachSubmit').addEventListener('click', function () {
  var input = $('coachInput');
  var prompt = (input.value || '').trim();
  if (!prompt) {
    $('coachStatus').textContent = '提示词为空，请先点「重置提示词」。';
    input.focus();
    return;
  }
  /* 框里已是完整提示词：直接发送，不再二次拼装 */
  sendCoachPrompt(prompt);
});

$('coachReset').addEventListener('click', resetPrompt);

/* 页面加载即写好 */
refreshPrompt();
```

**装置状态变化时**：在回调末尾加 `if (!promptDirty) refreshPrompt();`——学员没改过就自动同步，改过就不覆盖。**这一段所有原型共用**；下面 §3 / §4 / §5 只换 `readContext` 与 `buildPrompt` 的业务文案，不再重复贴。`buildPrompt()` 固定返回 **3 行**（`\n` 两个），不空行、不留 `【】`；素材从 `readContext()` 与页面当前展示取。

### 2.3 交付物样例

```text
判断结论：该压缩，不该新开
依据：12 轮已占 75%，再聊 3 轮就会溢出；后半段一直在重复前文
阈值：超过 70% 且还要继续同一话题 → 先压缩，不新开
下一步：把「已确定 / 必须记住」两段摘成一张交接单，粘到新对话开头
```

## 三、对照型（`03` / `09` / `10` / `11` / `13`）

**学员状态**：刚走完一条流程、排出一版顺序、拼出一版成品，或指认了一处坏点。
**交付物**：对照表——页面素材｜每步实际发生｜我以为｜差异；收尾加「最该核对的一步 + 今天能做的一条动作」。

> [!warning] 这一类最容易写抽象
> 装置给的是**过程**，不是数值。如果 `readContext()` 只读「第几步」，prompt 里就没有具体对象，小奈只能回一段通用解释。
> **必须让页面交出一个具体素材**（演示原句 / 当前选项 / 当前一步），再把它逐格填进表；不要让学员先补一句话。

### 3.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | **把演示里的这句话拆成五步** |
| 说明 | 她会拿页面上的演示原句，逐步说明它在五步里各变成了什么，再指出你最该核对的一步。 |
| 提示词 | 页面加载时自动写好 3 行：演示原句 + 当前步骤 + 对照表字段；无待填空 |
| 按钮 | 发送给小奈教练 |

### 3.2 业务代码（本页实测版）

```js
function readContext() {
  var out = [];
  var scene = document.querySelector('.scene.on');
  var h3 = scene ? scene.querySelector('h3') : null;
  var line = document.querySelector('.input-line');
  out.push({ k: '演示原句', v: line ? line.textContent.trim() : '尚未开始' });
  out.push({ k: '演示进度', v: textOf('demoProgress') || '尚未开始' });
  out.push({ k: '正在讲的一步', v: h3 ? h3.textContent : '尚未开始' });
  return out;
}

var COACH_CONFIG = {
  concept: '逐块生成',
  hard: [
    '教学示意，Token 切分与流程细节因模型而异',
    '说错了它自己也不会发现'
  ],
  deliverable: [
    '五步对照表：步骤｜变成什么｜我以为｜实际发生',
    '最该核对的一步',
    '今天能做什么'
  ]
};

function buildPrompt() {
  var by = {};
  readContext().forEach(function (x) { by[x.k] = x.v; });
  return '请用「' + COACH_CONFIG.concept + '」的视角，把页面上的「' + by['演示原句'] + '」按五步拆开，说明每一步实际发生了什么。\n' +
    '当前' + by['演示进度'] + '「' + by['正在讲的一步'] + '」；' + COACH_CONFIG.hard.join('；') + '。\n' +
    '先问一个会改变结论的问题；我回答后，按「' + COACH_CONFIG.deliverable[0] + '」给出，并指出' + COACH_CONFIG.deliverable[1] + '和' + COACH_CONFIG.deliverable[2] + '。';
}
```

**对照表的固定列**（写进 prompt，不让模型自由发挥）：

```text
| 步骤 | 页面这句话在这里变成什么 | 我可能以为 | 实际发生 |
```

### 3.3 交付物样例

```text
| 步骤 | 页面这句话在这里变成什么 | 我可能以为 | 实际发生 |
| ① 输入 | 「周末想去哪儿？」 | 它在查周末攻略 | 它只看到这句话本身 |
| ② 切 Token | 被切成若干小块 | 它按字理解 | 按模型自己的切法 |
| ③ 变向量 | 每块变成一串数字 | 只和同义词比 | 意思相近就靠近，不保证事实 |
| ④ 结合上下文 | 每块回头参考其他位置 | 它记住了全部历史 | 只看这次窗口里的内容 |
| ⑤ 预测下一块 | 一块一块接出回答 | 它核对过天气 | 没有查证机制，错了也会接着写 |

最该核对的一步：⑤——事实对错没有查证环节
今天能做的一条动作：发出前，把数字和专有名词逐项对照原始资料
```

## 四、改写型（`07` / `12`）

**学员状态**：刚在 A/B 里选了一边，或在预算里分完一轮资源。
**交付物**：改写稿——原版｜改写版｜改动理由｜风险。

### 4.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | 把页面这一版改成能用的版本 |
| 说明 | 她会保留页面的原意，只改其中一处最拖后腿的地方，并说明为什么改、可能带来什么风险。 |
| 提示词 | 页面加载时自动写好 3 行：页面这一版原文 + 页面结论 + 改写稿字段；无待填空 |
| 按钮 | 发送给小奈教练 |

### 4.2 业务代码

```js
function readContext() {
  return [
    { k: '页面这一版', v: (currentSide === 'a' ? 'A 模板话术：' : 'B 具体话术：') + currentText },
    { k: '页面结论', v: textOf('abVerdict') || '还没看完对比' }
  ];
}

var COACH_CONFIG = {
  concept: '具体话术比模板话术更容易被执行',
  hard: [
    '不编造页面之外的信息，缺什么先问我',
    '改写理由不要和页面结论相反'
  ],
  deliverable: ['原版', '改写版', '改动理由', '风险']
};

function buildPrompt() {
  var by = {};
  readContext().forEach(function (x) { by[x.k] = x.v; });
  return '请用「' + COACH_CONFIG.concept + '」的视角，把页面上的' + by['页面这一版'] + '改成能直接发出去的一版。\n' +
    '页面结论：' + by['页面结论'] + '；' + COACH_CONFIG.hard.join('；') + '。\n' +
    '先只问一个会改变结论的问题；我回答后，再按「' + COACH_CONFIG.deliverable.join('｜') + '」四项给出。';
}
```

### 4.3 交付物样例

```text
原版：您好，关于您反馈的问题我们已经记录，会尽快处理。
改写版：您说的「周三之后还没收到退款」我查到了，今天 18:00 前会由财务原路退回；如果没到账，直接回复这条消息。
改动理由：把「已记录」换成可核对的时间点和路径，降低二次追问
风险：承诺了具体时间，需要确认财务实际排期；不确定就改成「今天内给您确认时间」
```

## 五、产出型（`06` / `08`）

**学员状态**：刚看完一次播放，或把条目分完堆。
**交付物**：清单 / 脚本——对象｜归属或步骤｜判断规则｜复用方式。

### 5.1 卡片四句

| 位置 | 写法 |
|---|---|
| 标题 | 生成页面的「发布前检查清单」 |
| 说明 | 她会把页面上的过程拆成能照着做的几步，并给每条一个判断规则。 |
| 提示词 | 页面加载时自动写好 3 行：已分堆条目 + 卡住的条目 + 清单字段；无待填空 |
| 按钮 | 发送给小奈教练 |

### 5.2 业务代码

```js
function readContext() {
  var placed = document.querySelectorAll('.pile-item.placed').length;
  return [
    { k: '已分类条目', v: placed + ' / ' + items.length + ' 条' },
    { k: '还没归堆的条目', v: textOf('pileStuck') || '无' }
  ];
}

var COACH_CONFIG = {
  concept: '先按判断规则归类，再逐条核对',
  hard: [
    '不要改页面的分类标准',
    '有争议的条目标出来，不要硬塞'
  ],
  deliverable: ['对象', '归属或步骤', '判断规则', '复用方式']
};

function buildPrompt() {
  var by = {};
  readContext().forEach(function (x) { by[x.k] = x.v; });
  return '请用「' + COACH_CONFIG.concept + '」的视角，把页面上已有的 ' + by['已分类条目'] + '整理成一份能照着做的检查清单。\n' +
    '还没归堆的条目：' + by['还没归堆的条目'] + '；' + COACH_CONFIG.hard.join('；') + '。\n' +
    '先只问一个会改变结论的问题；我回答后，再按「' + COACH_CONFIG.deliverable.join('｜') + '」四项给出。';
}
```

### 5.3 交付物样例

```text
| 对象 | 归属 | 判断规则 | 复用方式 |
| 客户退款进度 | 需人工核 | 涉及金额和到账时间 | 每次先查工单再回 |
| 产品功能介绍 | 可直接答 | 与官网文案一致 | 贴官网原句 |
| 竞品对比 | 先不答 | 没有官方口径 | 转交市场部确认 |
```

## 六、交付物命名表（写卡前先填这一行）

| 交付物 | 固定字段（3–5 个） | 原型 | 什么时候用 | 反例 |
|---|---|---|---|---|
| **判断卡** | 结论｜依据｜阈值｜下一步 | 诊断型 | 页面在教一个二选一 / 够不够 | 「帮你分析一下」 |
| **对照表** | 页面素材｜每步实际发生｜我以为｜差异 | 对照型 | 页面在教一条流程 / 顺序 / 结构 | 「指出容易出错的一步」 |
| **改写稿** | 原版｜改写版｜改动理由｜风险 | 改写型 | 页面在教两版取舍 / 资源分配 | 「给点优化建议」 |
| **检查清单** | 对象｜归属或步骤｜判断规则｜复用方式 | 产出型 | 页面在教一次过程 / 一套分类 | 「总结一下重点」 |

四条硬规则：

1. **必须含页面素材或页面原值，至少一处。** 全是通用词的交付物，换个页面也能用，等于没用。
2. **字段写进 prompt，用「｜」隔开。** 不写字段，模型就会自由发挥成散文。
3. **一屏放得下。** 超过 5 项就换更窄的交付物，或删掉最不重要的一项。
4. **提示词固定 3 行、无待填空。** 任务 + 素材 / 状态 + 边界 / 交付物 + 字段；不出现 `【】`、`____`、「改成你的」。

## 七、具体性六问（写完卡先过）

- [ ] **打开时框里是不是 3 行完整提示词？** 页面加载后已经写好页面素材、读数、硬约束和交付物字段，且没有 `【】` 待填空；还是空框 → 回 §2.2 接 `refreshPrompt()`。
- [ ] **点发送是不是直接发框内全文？** 不再用 `buildPrompt()` 包一层；框里是什么就发什么。
- [ ] **遮住页面素材**：prompt 还能执行吗？能 → 第 1 行没有具体对象，回 §3 / §4 补。
- [ ] **遮住「页面演示状态」**：还能执行吗？能 → 状态是装饰，`readContext()` 读错了东西。
- [ ] **交付物能画出来吗**：能不能立刻画成一张表 / 一份稿？不能 → 回 §6 换交付物。
- [ ] **换个页面还成立吗**：换一个装置读数或演示原句，这张卡还成立吗？仍成立 → 素材写死了，改 `readContext()` / `buildPrompt()`。

## 八、抽象 → 具体（高频对照）

| ❌ 抽象写法 | ✅ 具体写法 | 为什么 |
|---|---|---|
| 把「逐块生成」套到你的用法上 | 把演示里的这句话拆成五步 | 标题要说清**产出什么** |
| 我要让 AI 做的事是【】 | 页面上的「周末想去哪儿？」 | 素材从页面取，不要任务名 |
| 指出最容易出错的一步 | 填一张五步对照表，最后一行写最该核对的一步 | 表格能抄走，标签不能 |
| 你的任务落在五步中的哪一步 | 页面这句话在每一步各变成了什么 | 任何生成都走完五步，「落在哪一步」不成立 |
| 先问一个会改变结论的问题（不举例） | 这句话一旦出错，你最不能接受事实错、格式错还是语气错？ | 给正例，模型才知道什么叫「改变结论」 |
| 页面演示状态：整段讲解文字 | 演示进度：第 3 / 5 步；正在讲的一步：变成向量 | 状态是学员看到的读数，不是教材正文 |
| 按「结论｜依据｜阈值｜下一步」给出方案（字段空泛） | 按「判断结论｜引用哪条页面读数｜超过多少就该动｜今天做什么」给出 | 字段要能直接填，不能是名词摆设 |
| 提示词里只写「别乱编」 | 「缺什么先问我，不要编造我的产品信息」 | 禁令要能执行，不是表态 |
| 打开卡片是空框，让学员自己拼 | 加载即写好 3 行完整提示词，素材从页面取 | 学员要的是「打开就能发」 |
| 提示词写成 5 段、10 行，还留【】 | 压成 3 行：任务+素材 / 状态+边界 / 交付物+字段 | 读者要一句能直接发的，不是待办清单 |
| 点发送时又用 `buildPrompt()` 包一层 | 直接 `sendCoachPrompt(框内全文)` | 框里已经是完整提示词，再包会重复 |
| 装置一变就覆盖学员改过的提示词 | `promptDirty` 标记；改过不覆盖，点重置才重建 | 学员的修改不能被动画吞掉 |
