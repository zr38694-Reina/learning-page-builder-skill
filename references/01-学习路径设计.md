# 学习路径设计

「学习路径」分两层，**先定课程级，再定页面级**。课程级定错，页面写得再好也是孤岛。

---

## 一、课程级：这一页站在哪里

### 1.1 三级坐标

任何一页都必须能填出这三个空，填不出说明粒度没想清楚：

| 层 | 作用 | 判定标准 |
|---|---|---|
| **篇章 part** | 这一批内容属于哪个专题 | 用一个「专题名」能概括它，如「写给第一次接触 X 的你」 |
| **主题 topic** | 这一组几页在回答同一类问题 | 组内页可以互相引用，而不用解释背景 |
| **知识点 lesson** | 这一页 = 一个问题 | **H1 就是一个问句**（**AI 向 · 口语 · 主体 6–14 字**，起名法见 `03-页面骨架与文案.md` §二），读者搜那句话就能进来 |

命名习惯：`part` 用「给谁 / 什么场景」，`topic` 用「哪一类问题」，`lesson` 用**读者会问的那句话**。

### 1.2 组内形状：两种，都要认得出来

拆一组内容时，先判断它是**弧线**还是**节点网络**：

| | 弧线（连续三连） | 节点网络 + 局部骨干链 |
|---|---|---|
| 适用 | 概念递进，后一页依赖前一页 | 一页一问的 FAQ / 三千问 |
| 排法 | 顺着认知顺序排，**不能乱序** | 各页独立成立，但**局部埋 1–2 条强依赖** |
| 衔接 | 正文里点出页与页的因果，但**不放链接、不写「下一节」** | 正文**不写「下一节」、不放链接**，交给目录树兜底 |
| 风险 | 中间断一节，后面全塌 | 埋的依赖链太隐蔽，读者走不到 |

**判定方法**：抽掉中间一页，后面的页还能不能读懂？
- 读不懂 → 弧线，必须排顺序（**顺序表达依赖；正文不互链、不写「下一节」**）。
- 读得懂 → 节点网络，别在正文里写「接着看下一节」（那会暗示「你必须按顺序读」，与检索式定位冲突）。

**页序不写进页面**：弧线的先后靠**排列顺序**表达，读者在目录里按顺序点；页面正文里既不互链、也不写「下一节」（红线 9）。

### 1.3 三种实测好用的组内弧线

| 弧线 | 三拍 | 适合 |
|---|---|---|
| **名词分层 → 差异对比 → 使用抓手** | 这几个词谁是谁 → 这一层强在哪 → 我怎么用上它 | 一个陌生概念群 |
| **广撒网 → 加动作 → 按代价收敛** | 往哪儿看 → 用什么动作查 → 查到什么程度就停 | 一个方法论 / 一道工序 |
| **约束 → 约束 → 解法** | 成本约束 → 容量约束 → 在约束下的工程解 | 一个「为什么要这么做」的因果链 |

第三种最容易被忽略但最好用：**前两页只给约束、不给方案**，第三页才给解法——它就是天然的聚合页。

### 1.4 谁当最后一页：算依赖关系

**聚合点 = 被最多页依赖、且自己不依赖别页的那一页。** 让它当这一组的最后一页（或枢纽）。

```
被依赖（别人要先看它）  依赖别人（它要先看别页）
       高                   低     → 聚合页 / 收口页，放最后
       低                   高     → 入口页 / 引导页，放最前
       高                   高     → 枢纽页，适合放中间承上启下
```

反过来说：**如果一页同时需要组内其他两页作前提，它就该是最后一页。** 排在中前，读者会在还没读到前提时撞见它——多一次「看不懂」就多一次流失。

## 二、页面级：读者动线

### 2.1 先判读者的进入姿态（决定整个骨架）

| | 检索式阅读 | 路径式阅读 |
|---|---|---|
| 谁 | 带着一个具体疑问点进来的人 | 跟着一条路径走过来的人 |
| 需求 | **第一屏要能止损**（我到底该记住哪句） | 需要被说服，需要看到代价 |
| 骨架 | **答案在最前面**：一句话回答 → 亲手试 → 原理 | 案例 → 翻车 → 归因 → 模板 |
| 反面 | 铺垫、卖关子 | 上来就给结论 |

**同一个课程里两种骨架并存是正常的**：页面结构不是模板，而是**按读者的进入姿态选的**。
被一个问题推进来的人，先给答案；被一条路径带进来的人，先给案例。

### 2.2 通用动线（检索式页面的默认顺序）

```
困惑复述 → 一句话回答 → 亲手试（装置） → 原理 → 误区/软肋 → AI 概念解析 → 4 条带走
   ①          ②            ③            ④       ⑤          ⑥          ⑦
```

三条不可动摇的顺序：

1. **装置在原理之前**（③ 在 ④ 前）。先看见现象，再读命名。
2. **一句话回答在第 2 屏**（紧跟标题）。检索式读者只读这一句就走了，让他读到结论。
3. **takeaway 在全页最后且固定 4 条**（⑦）。它是「能整段抄进笔记」的东西。
   **「AI 相关概念解析」卡（⑥）紧贴在它前面**——概念先收拢，再收尾；见 `03` §1.3。

### 2.3 页面内不放链接、不写「下一站」

**硬约束**：生成的 HTML 里**不出现任何超链接**（没有 `<a href>`），正文里**不写**「下一节 / 下一站 / 想看深入版 / 接着去哪儿」这类指向别处的话。

为什么：页面会被**单独打开、被 iframe 嵌入、被投喂给别的系统**——页内链接要么失效（相对路径没了），要么把刚读进去的读者从本页带走。**续学靠页序与标题**（读者在目录里挑下一个问句），不靠页内跳转。

那「路径」体现在哪？只体现在**页面之外**的三处：

| 体现方式 | 在哪 | 作用 |
|---|---|---|
| **页序** | 组内的排列顺序 | 依赖关系靠先后表达，不靠链接 |
| **H1 问句** | 页面标题 | 读者在目录里自己挑下一句要问的 |
| **交付说明** | 给用户/运营的回复 | 讲清这页在组里的位置、下一句该问什么 |

**需要表达「先有前提、才好看懂后面」时**：用**文字点出因果**（「先看懂约束，再看解法才不突兀」），但**不要写成链接、也不要写成「下一节见」**。组内的「回指」是**内容上的先讲前提**，不是页内跳回。

## 三、Phase 1 诊断输出模板

给用户确认时用这个格式，**只给清单，不给代码**：

```
诊断：<内容性质一句话>；建议拆 <N> 页（<组内形状：弧线 / 节点网络>）。

| 序 | 页面（H1 问句） | 内容性质 | 互动题型 | 组内位置 | 概念卡（本批不重复） |
|---|---|---|---|---|---|
| 1 | 「X 是什么？为什么…」 | 有可计量单位 | 点选+计数器 | 入口（只给约束） | 上下文窗口 / 关键词 |
| 2 | 「为什么…会…」 | 有可调参数 | 滑块+对照 | 中段（只给约束） | Token / 缩放定律 |
| 3 | 「…到底怎么做？」 | 有可拆流程 | 分步+终态对比 | **聚合页（最后一页）** | RAG / 引用 |

读者姿态：检索式（先给答案）｜组内续学：靠**页序与标题**，页面内**不放链接、不写「下一站」**。
```

**「概念卡」那一列怎么来**：拆多页时**先给每页跑一遍** `scan_ai_concepts.py`，用 `--used <台账文件>` 串起来，
脚本会把已用概念标 ✗ 并自动换词——**同一个概念只归一页**（红线 8；归属判据与优先级见 `03-页面骨架与文案.md` §1.5）。
这一列写进清单，Phase 2/3 照着填卡即可，不必再各页各挑。

确认后进 Phase 2。
