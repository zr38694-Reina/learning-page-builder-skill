# 小奈教练接入（先看一个例子，再看协议）

> [!abstract] 你只需要做 4 件事
> 1. **判**：这页有没有可玩装置？没有 → 不配卡（§0）。
> 2. **写**：卡片上 4 句话——标题、她会做什么/不会做什么、填空骨架、按钮（§5）。
> 3. **读**：在 `readContext()` 里读 1–3 个页面上的真实状态（§6.2）。
> 4. **拼**：在 `buildPrompt()` 里把「我的情况 + 页面状态 + 硬约束 + 固定输出清单」拼成一句话（§4 / §6.3）。
>
> 其余通信代码**整段照抄模板，不要改**。

## 开篇｜一张卡到底长什么样

### 0.1 学员看到的四步

```text
① 玩装置
   拖动滑块 / 点选项 / 排顺序
        ↓
② 看到自己的状态
   「对话 12 轮，上下文已用 75%」
        ↓
③ 点「带入当前演示状态」
   输入框自动出现：12 轮 / 75% / 6,000 tokens
   学员再补一句自己的情况
        ↓
④ 点「判断我该压缩还是新开」
   小奈在对话框里先问一个关键问题，再给方案
```

**这张卡不是聊天框，是「把页面上的练习，换成你自己的事」的传送门。**

### 0.2 一个完整例子：页面「聊久了，AI 为什么会忘事？」

**页面上的装置**：一个「对话轮数 1–20」的滑块，旁边实时显示「上下文占用 6,000 / 8,000 tokens（75%）」。

**卡片文案**（直接照这个感觉写）：

| 位置 | 文案 |
|---|---|
| 卡标题 | 把这页的「聊天记忆」换成你的真实对话 |
| 她会做什么 / 不会做什么 | 小奈会先用你带入的轮数和占用率，判断你该压缩、分段，还是新开一段。**她不会假装读过你没粘贴的聊天记录。** |
| 输入框标签 | 用四句话说说你这段对话 |
| 输入框占位 | 我这段对话主要在聊【】；已经确定【】；必须记住【】；现在卡在【】。 |
| 带入按钮 | 带入当前演示状态 |
| 提交按钮 | 判断我该压缩还是新开 |

**`readContext()` 读出来的页面状态**：

```text
对话轮数：12 轮；上下文占用：6,000 / 8,000 tokens（75%）
```

**学员点提交后，实际发给小奈的 prompt**：

```text
请用本页「上下文窗口」的视角，帮我判断这段对话该压缩还是新开。

我的情况：我这段对话主要在聊【小红书选题】；已经确定【每周发 3 条】；
必须记住【账号定位是职场新人】；现在卡在【它开始重复问我发过什么】。
页面演示状态：对话轮数：12 轮；上下文占用：6,000 / 8,000 tokens（75%）

【硬约束】
1. 不要把产品的长期记忆功能与上下文窗口混为一谈。
2. 不要假设你看过我未粘贴的聊天记录；信息不足时先问我。
3. 页面上的 8,000 tokens 是演示值，不代表任何真实模型的上下文长度。

先只问一个会改变结论的问题；我回答后，再按
「判断结论｜保留什么｜丢弃什么｜下一步动作」四项给出方案。
```

看到区别了吗？**不是「请帮我看看我的对话」，而是把页面读数、自己的情况、边界和输出格式一次给全。**

### 0.3 你只改这 4 处

| # | 改哪里 | 在模板里的位置 | 改成什么 |
|---|---|---|---|
| ① | 页面标识 | `<body data-page-id>` 与 `<section class="coach" data-coach-title>` | 本页唯一 ID + 卡标题 |
| ② | 卡片文案 | `<section class="coach">` 里的 title / desc / placeholder / 两个按钮 | 按 §5 的 4 句模板填 |

## 〇、哪些页面配卡（先判这个，再往下读）

**不是每页都配。** 一份资料拆成多个 HTML 页面时，**逐页判**：

```text
读者要不要动手？
├─ 不要 → 纯知识页 → ❌ 不配卡
└─ 要 → 页面能不能读出他刚才的操作？
    ├─ 能 → ✅ 配卡，贴在装置正下方
    └─ 不能 → 先把装置状态补出来，再配
              （否则只是一只空聊天框）
```

| 页面类型 | 判据 | 配不配卡 |
|---|---|---|
| **互动页** | 有一个**可玩装置**——读者要动手点 / 拖 / 押 / 调 / 排，页面能读出他刚才的操作状态 | ✅ **配**（贴在装置正下方） |
| **纯知识页** | 只有阅读内容：一句话回答 + 原理卡 + 提醒 + takeaway，读者全程只是看 | ❌ **不配** |

**为什么纯知识页不配**：这张卡的全部价值在「一键带入页面上的实际状态」。**没有装置，就没有状态可带**，剩下的只是一只空聊天框——而「不给空聊天框」正是本文件 §1 的第一条原则。硬塞一张卡只会让人觉得这页没做完。

**怎么落地**：诊断清单里逐页标注「小奈卡：要 / 不要」（`SKILL.md` Phase 1 ⑤）。不配卡的页面，**把模板里 `<section class="coach">` 与 `<script>` 中的 COACH 复用段、`readContext` / `buildPrompt` / `bring` 及两个按钮监听整段删掉**，页面不含任何 postMessage 代码。

> 命名：**小奈教练**（不是「助教」「AI 助手」）。页面上一律用这个称呼，与宿主系统保持一致。

**协议刻意做小**：整个通信只有「发一条提问」和「收一条确认」两件事。默认不增加队列、重试、复制兜底、超时、自动展开、额外消息分支或第三方依赖。宿主需要什么，由宿主自己在收到提问后去补——页面只负责把 prompt 组装好、发出去。

## 一、三条设计原则

| 原则 | 说明 |
|---|---|
| **不给空聊天框** | 卡片必须**贴着一个具体装置**（`anchor` = 该页的演示区块），并能**一键带入页面上的实际状态**。降低「我该问什么」的启动成本。 |
| **带入成本越低越好** | 优先「从页面读数」（`textContent` / 当前选中项 / 滑块值）> 给**填空骨架** > 开放问题。<br>填空骨架例：`这段长对话正在做【】；已经确定【】；必须遵守【】；还没解决【】。` **填空题比问答题的启动成本低一个量级。** |
| **硬边界写进 prompt** | **页面教你什么，就防你什么。** 见 §4。 |

## 二、通信协议（宿主为父窗口）

页面被 iframe 嵌入，通过 `window.parent.postMessage` 与宿主通信。**发对象，不发 JSON 字符串**；字段名和值必须与下表逐字一致。

### 2.1 页面 → 宿主：`coach:send`

```js
window.parent.postMessage({
  source:  'learning-page',        // 固定值，宿主据此识别
  type:    'coach:send',           // 本协议唯一的出站消息
  v:       1,
  payload: {
    prompt: 'HTML 已组装好的完整提问文字'   // ★ 唯一必需的业务字段，必须非空字符串
  }
}, '*');   // 已知宿主 origin 时可收紧为宿主域名
```

### 2.2 宿主 → 页面：`coach:ack`

```js
{ source: 'xiaonai', type: 'coach:ack', v: 1 }
```

| 消息 | payload | 页面行为 |
|---|---|---|
| `coach:ack` | — | 确认**宿主已接手**，状态提示改为「已交给小奈教练，请查看对话。」 |

`coach:ack` **只表示宿主接手了提问，不代表模型已回复、也不代表后端请求成功**。回复出现在小奈自己的对话界面里，**不在页面内回显**。

### 2.3 元素 ID（脚本引用必须一致）

| ID | 用途 |
|---|---|
| `coachInput` | 提问输入框（`textarea`） |
| `coachSubmit` | 提交按钮 |
| `coachStatus` | 状态提示行（`role="status" aria-live="polite"`） |

### 2.4 代码结构：通信段与页面业务分开

通信代码用**「复用代码开始／结束」注释**框起来，原样复用；页面专属的 `buildPrompt(text)` 与按钮事件**放在通信段之外**。这样换一页只需要改段外那三处（见 §6）。

### 2.5 安全

```js
window.addEventListener('message', function (ev) {
  if (ev.source !== window.parent) return;      // 只收父窗口
  var d = ev.data;
  if (!d || typeof d !== 'object') return;
  if (d.source !== 'xiaonai' || d.type !== 'coach:ack' || d.v !== 1) return;   // 不认的消息一律忽略
  /* … */
});
```

**不要把消息里的 `source` 字符串当作身份验证**——它只是识别用的约定值。若要更严，加 origin 白名单。

## 三、没有宿主时的表现

页面可能被单独打开、离线打开，或被别的系统嵌入。此时**不静默失败**，也不做任何兜底机制：

```text
不在 iframe（window.parent === window）
   └→ coachStatus 显示：「请在支持小奈教练的宿主页面中打开此学习页。」
      学习内容照常可看，发送功能不可用。

在 iframe 但宿主没回 coach:ack
   └→ 状态停在「正在交给小奈教练…」，不再变化。
      已发出的 postMessage 保持有效，宿主晚到也还能接上。
```

**不做**：复制兜底按钮、800ms 超时降级、重试队列、自动展开聊天面板。学员的最后一道保险由宿主提供，不由页面提供。

## 四、prompt 怎么写：硬边界

**页面教你什么，陪练就防你什么。** 这一条是这个 skill 里最值得抄的设计。

| 页面的内容 | prompt 里必须写死的约束 |
|---|---|
| 演示里有**具体数字/价格/参数** | 「**不要声称页面上的数字或价格适用于所有模型/产品**；精确值应以官方口径核对」 |
| 讲**上下文窗口 / 记忆** | 「**不要把产品的长期记忆功能与上下文窗口混为一谈**」 |
| 讲**知识库 / 检索** | 「**不要假装已经读取了资料，也不要编造页码或条款**」 |
| 讲**风险标注 / 核查** | 「**找不到依据就写『待核对』，绝不编页码或来源**」 |
| 涉及**操作执行**（Agent、自动化） | 「**付款、删除、发送和敏感数据操作必须保留人工确认**」 |
| 涉及**医疗 / 法律**资料 | 「只设计可追溯引用与人工审核，**不提供诊疗或法律结论**」 |

### 4.1 三句话检查（写完 prompt 先过这一关）

- [ ] **有没有页面状态？** —— `readContext()` 读出来的值真的拼进去了吗？
- [ ] **有没有 1–2 条硬约束？** —— 从上面表格里选，不能空着。
- [ ] **有没有固定输出清单？** —— 小奈回答完，读者能拿到哪几样东西？

三项缺一项，读者拿到的就会是一段「正确的废话」。

### 4.2 填空模板（直接抄）

```text
请用本页「{{概念名}}」的视角，帮我处理下面这件事。

我的情况：{{学员填的 / 从页面带入的}}
页面演示状态：{{从装置里读出的真实状态}}

【硬约束】
1. {{这一页最容易犯的错，写成一句禁令}}
2. {{这一页的数字/结论的边界}}

先只问一个会改变结论的问题；我回答后，再按
「{{清单 1}}｜{{清单 2}}｜{{清单 3}}｜{{清单 4}}」给出方案。
```

### 4.3 完整成品（照这个长度写）

```text
请用本页「上下文窗口」的视角，帮我判断这段对话该压缩还是新开。

我的情况：我这段对话主要在聊【小红书选题】；已经确定【每周发 3 条】；
必须记住【账号定位是职场新人】；现在卡在【它开始重复问我发过什么】。
页面演示状态：对话轮数：12 轮；上下文占用：6,000 / 8,000 tokens（75%）

【硬约束】
1. 不要把产品的长期记忆功能与上下文窗口混为一谈。
2. 不要假设你看过我未粘贴的聊天记录；信息不足时先问我。
3. 页面上的 8,000 tokens 是演示值，不代表任何真实模型的上下文长度。

先只问一个会改变结论的问题；我回答后，再按
「判断结论｜保留什么｜丢弃什么｜下一步动作」四项给出方案。
```

> 用户要求**原文发送**时，`buildPrompt` 写成 `text => text` 即可。

## 五、字段对照（写卡时逐项填）

| 字段 | 含义 | 填不出来时，问自己 | 例子 |
|---|---|---|---|
| `anchor` | 卡片挂在页面哪个元素后面 | 「读者刚玩完哪个东西？」 | 滑块/选项/排序装置的容器（`.demo`） |
| `title` | 卡标题 | 「读者点这张卡，是要完成哪件事？」 | 「把这页的『聊天记忆』换成你的真实对话」 |
| `desc` | 一句话说明她会做什么 | 「她先看什么？她不会做什么？」 | 「先用你带入的轮数和占用率，判断该压缩还是新开。**不会假装读过你没粘贴的记录。**」 |
| `placeholder` | 输入框占位 | 「读者最少要补哪 3–4 个信息？」 | 「主要在聊【】；已经确定【】；必须记住【】；卡在【】。」 |
| `current()` | 从页面读数 | 「页面上哪个数字/选项能代表他刚才的操作？」 | 轮数、占用率、选中项、排序结果 |
| `currentLabel` | 带入按钮文案 | 「点一下会带进什么？」 | 「带入当前演示状态」 |
| `button` | 提交按钮 | 「点完会得到什么？」 | 「判断我该压缩还是新开」 |
| `buildPrompt(text)` | 拼装完整指令 | 「她需要哪些上下文才不会答偏？」 | 见 §4.3 |

### 5.1 最小可行卡（先跑通，再美化）

只写这 4 句，也能用：

```text
标题：把这页的「{{概念}}」换成你的「{{场景}}」
说明：她会先{{看什么}}，再{{给什么}}；不会{{最容易犯的错}}。
占位：我的情况是【】；已经确定【】；现在卡在【】。
按钮：{{动词}} + {{结果}}
```

### 5.2 卡标题的三种写法

| 写法 | 例子 | 适合 |
|---|---|---|
| **换成我的事** | 把这页的「聊天记忆」换成你的真实对话 | 最通用，推荐 |
| **帮我做判断** | 判断我该压缩还是新开 | 页面本身在讲二选一 |
| **帮我产出一份东西** | 生成我的「对话交接单」 | 页面有明确交付物 |

> ❌ 不要写「向小奈提问」「和小奈聊聊」「AI 助手」——读者不知道点进去要干嘛。

## 六、实现：照着改这 4 处

直接复制 `assets/page-template.html` 里的 `<section class="coach">` 及其脚本（`COACH` 段）。需要改的只有四处：

### 6.1 卡片 HTML（只换文案）

```html
<!-- data-page-id 在 <body> 上：<body data-page-id="{{PAGE_ID}}"> -->
<section class="coach" id="coach"
         data-coach-title="{{卡标题：一个动作}}">
  <div class="coach-head">
    <span class="coach-avatar" aria-hidden="true">奈</span>
    <div>
      <h3 class="coach-title">{{卡标题}}</h3>
      <p class="coach-desc">{{她会做什么}}。<b>{{她不会做什么}}</b></p>
    </div>
  </div>
  <label class="coach-label" for="coachInput">{{输入框标签}}</label>
  <textarea id="coachInput" rows="3" placeholder="{{填空骨架}}"></textarea>
  <div class="coach-actions">
    <button type="button" class="btn ghost small" id="coachBring">带入当前演示状态</button>
    <button type="button" class="btn blue small" id="coachSubmit">{{动词 + 结果}}</button>
  </div>
  <p class="coach-status" id="coachStatus" role="status" aria-live="polite"></p>
</section>
```

### 6.2 `readContext()`：读页面上已有的值

```js
function readContext() {
  return [
    { k: '对话轮数', v: rounds.value + ' 轮' },
    { k: '上下文占用', v: used + ' / ' + cap + ' tokens（' + pct + '%）' }
  ];
}
```

**只读页面已有文本**：`textContent` / 当前选中项 / 滑块值。不要在这里做推断，也不要编一个页面上没有的数字。

### 6.3 `buildPrompt()`：套 §4.2 模板

```js
function buildPrompt(text) {
  var state = readContext()
    .map(function (c) { return c.k + '：' + c.v; })
    .join('；');

  return '请用本页「上下文窗口」的视角，帮我判断这段对话该压缩还是新开。\n\n' +
    '我的情况：' + (text || '（学员未填写，可先从页面状态开始）') + '\n' +
    '页面演示状态：' + state + '\n\n' +
    '【硬约束】\n' +
    '1. 不要把产品的长期记忆功能与上下文窗口混为一谈。\n' +
    '2. 不要假设你看过我未粘贴的聊天记录；信息不足时先问我。\n' +
    '3. 页面上的数字是演示值，不代表任何真实模型的上下文长度。\n\n' +
    '先只问一个会改变结论的问题；我回答后，再按' +
    '「判断结论｜保留什么｜丢弃什么｜下一步动作」四项给出方案。';
}
```

### 6.4 不要动的地方

- `/* 复用代码开始 */` ~ `/* 复用代码结束 */` 之间的通信段。
- `sendCoachPrompt()`、`coach:ack` 监听、origin 校验。
- `R()` 函数：所有延时写成 `R(160)`，不要写裸 `160`。
- 头像 `.coach-avatar` 的 base64 CSS。

### 6.5 头像（内置，不要改）

`.coach-avatar` 的**小奈头像已按 base64 内嵌在模板里**（约 15 KB 的 PNG data URL，写在 `background-image:url("data:image/png;base64,…")`）。这是刻意的：

- **不要换成外部图片链接** —— 模板的硬要求是「单文件、零依赖、可离线」，外链头像会破坏这一条。
- **不要动这行 CSS** —— 换页时头像自动跟着走，无需任何操作。
- 标签里的文字 `奈` 是**兜底**（`font-size:0;color:transparent` 时不可见），头像加载不出来时才顶上来；不要删。
- 确实要换形象时：把新头像压到 **120×120 左右的 PNG**，用 `base64` 编成一整行替换整段 `url("…")`；**不要**在 data URL 里换行，否则 CSS 会断。

### 6.6 宿主接入参考（仅宿主尚未实现协议时使用）

HTML 本身不调用模型接口。宿主必须加载 iframe 并监听 `message`，再调用自身已有的教练发送方法：

```js
/** 为指定 iframe 连接教练发送方法，返回取消监听函数。 */
const connectCoach = (iframe, sendPrompt) => {
  const handleMessage = (event) => {
    const message = event.data;
    if (event.source !== iframe.contentWindow) return;
    if (!message || typeof message !== 'object') return;
    if (message.source !== 'learning-page' || message.type !== 'coach:send' || message.v !== 1) return;
    const prompt = message.payload && message.payload.prompt;
    if (typeof prompt !== 'string' || !prompt.trim()) return;
    sendPrompt(prompt);
    iframe.contentWindow.postMessage({ source: 'xiaonai', type: 'coach:ack', v: 1 }, '*');
  };
  window.addEventListener('message', handleMessage);
  return () => window.removeEventListener('message', handleMessage);
};
```

`iframe` 是实际嵌入学习页的 `HTMLIFrameElement`；`sendPrompt` 是宿主提供的函数，接收完整字符串并调用已有聊天发送功能。保留返回值，在宿主组件卸载或移除 iframe 时调用它。

不要把未定义的示例变量当成可运行接入。已有登录、发送中和失败处理继续由原发送方法负责。

## 七、5 分钟验收（交付前逐条打勾）

- [ ] 卡片**紧贴装置下方**，不是页面底部。
- [ ] 输入框是**填空骨架**，不是「请输入你的问题」。
- [ ] 点「带入当前演示状态」→ 输入框出现**页面上的真实读数**，不是空。
- [ ] 点提交且输入为空 → 出现「请先填写内容。」，焦点回到输入框。
- [ ] 点提交且输入非空 → 状态变成「已交给小奈教练，请查看对话。」
- [ ] 实际发出的 prompt 同时包含：**我的情况 / 页面状态 / 1–2 条硬约束 / 固定输出清单**。
- [ ] 纯知识页**没有** `<section class="coach">`，也没有任何 `postMessage` 代码。
- [ ] 独立打开 HTML → 显示「请在支持小奈教练的宿主页面中打开此学习页。」
- [ ] iframe 内 → 宿主能收到 `coach:send`，且 `payload` 只有 `prompt` 一个字段。
- [ ] 没有真实联调时，**不声称已连接真实教练**。

## 八、常见错误：抽象 → 具体

| ❌ 抽象写法 | ✅ 具体写法 | 为什么 |
|---|---|---|
| 标题「向小奈提问」 | 「把这页的『聊天记忆』换成你的真实对话」 | 读者要知道点进去**完成哪件事** |
| 说明「小奈可以帮你分析问题」 | 「先用你带入的轮数和占用率判断该压缩还是新开。**不会假装读过你没粘贴的记录。**」 | 说清**她先看什么、不会做什么** |
| 占位「请输入…」 | 「主要在聊【】；已经确定【】；必须记住【】；卡在【】。」 | 填空比开放问题**启动成本低一个量级** |
| prompt 只写「请帮我看看」 | 情况 + 页面状态 + 硬约束 + 四项输出 | 不给上下文，小奈只能答得正确但没用 |
| 卡片放在页面最底部 | 紧贴装置下方 | 读者刚玩完，才有话可说 |
| 纯知识页硬塞一张卡 | 删掉卡与脚本 | 没有装置 = 没有状态可带 = 空聊天框 |
| 把页面上没有的数字写进 `readContext()` | 只读 `textContent` / 选中项 / 滑块值 | 编造状态会让学员失去信任 |
| 在 prompt 里写「页面上的价格适用于所有模型」 | 「页面数字是演示值，精确值以官方口径为准」 | 具体数字最容易被当成真值 |

---

> [!tip] 一句话记住
> **装置负责让学员「看见」，小奈卡负责让学员「换成自己的事」。**
> 卡片写不好，通常不是文案问题，是**没想清楚读者刚在装置里看到了什么、下一步想拿它干什么**。
