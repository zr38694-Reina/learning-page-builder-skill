# 小奈教练接入（先看两个例子，再看协议）

> [!abstract] 你只需要做 5 件事
> 1. **判**：这页有没有可玩装置？没有 → 不配卡（§0）。
> 2. **选**：查 `07-小奈互动模式库.md` §0，定互动原型（诊断 / 对照 / 改写 / 产出）与**三行提示词**。
> 3. **写**：卡片文案——标题、她会做什么、提示词框标签、发送按钮（§5）。
> 4. **读**：在 `readContext()` 里读 1–3 个页面上的真实状态（§4.0 / §6.2）。
> 5. **拼**：在 `buildPrompt()` 里写一条 **≤3 行的大白话**：① 我在学哪个知识点 + 当前状态 + 页面素材 + 题面 + 边界，句尾「先别解释」② 反馈 ③ 兜底（§4 / §6.3）。模板会在**页面加载时自动写好**；学员打开即可点**发送给小奈教练**，**不需要补任何空**。
>
> 其余通信代码**整段照抄模板，不要改**。

## 开篇｜一张卡到底长什么样

### 0.1 学员看到的四步

```text
① 玩装置
   拖动滑块 / 点选项 / 排顺序
        ↓
② 看到自己的状态
   「对话 12 轮，上下文已用 75%」
        ↓
③ 提示词框已经是 3 行大白话
   我在学「上下文窗口什么时候会满」。页面显示 12 轮、75%，请出一道判断题，先别解释。
   我回答后，你先说我哪里对、哪里偏，再给一句正确说法。
   如果我没答上来，就直接告诉我答案，不要继续追问。
   不需要补任何空，可直接发送
        ↓
④ 点「发送给小奈教练」
   一键发送；小奈先出一道小题，
   再按「哪里对、哪里偏、正确说法」回你
```

**这张卡不是聊天框，也不是让学员自己拼 prompt 的输入框，而是「把页面上的一个知识点直接交给小奈练一遍」的传送门。**
**学员打开卡片时，提示词已经写好；直接点发送即可。**

### 0.2 一个完整例子：页面「聊久了，AI 为什么会忘事？」

**页面上的装置**：一个「对话轮数 1–20」的滑块，旁边实时显示「上下文占用 6,000 / 8,000 tokens（75%）」。

**卡片文案**（直接照这个感觉写）：

| 位置 | 文案 |
|---|---|
| 卡标题 | 考我：什么时候该压缩 |
| 她会做什么 | 她会拿页面上的轮数和占用率，出一道判断题，只考「什么时候该压缩」这一点。 |
| 提示词框标签 | 发给小奈的提示词（可直接修改） |
| 提示词框预填 | 3 行大白话：学哪个点 + 状态 + 题面 / 反馈 / 兜底；**无待填空** |
| 重置按钮 | 重置提示词 |
| 发送按钮 | 发送给小奈教练 |

**`readContext()` 读出来的页面状态**：

```text
轮数：12 轮；占用：75%
```

**打开卡片后直接发出的 prompt（3 行）**：

```text
我在学「上下文窗口什么时候会满」。页面显示 12 轮、已占 75%，请拿这段对话出一道判断题，先别解释；数字是演示值。
我回答后，你先说我哪里对、哪里偏，再给一句正确说法。
如果我没答上来，就直接告诉我答案，不要继续追问。
```

看到区别了吗？**不是「帮我把整页内容梳理一遍」，而是只练「什么时候该压缩」这一个点**，页面读数自动带上，只有 3 行，而且全是大白话。
这段文字在**打开卡片时就已经写好**；学员直接点「发送给小奈教练」，不需要补任何空。

### 0.3 你只改这 4 处

| # | 改哪里 | 在模板里的位置 | 改成什么 |
|---|---|---|---|
| ① | 页面标识 | `<body data-page-id>` 与 `<section class="coach" data-coach-title>` | 本页唯一 ID + 卡标题 |
| ② | 卡片文案 | `<section class="coach">` 里的 title / desc / 提示词框标签 / 两个按钮 | 按 §5 的模板填 |
| ③ | 页面读数 | 脚本里的 `readContext()` | 按 §4.0 的装置表，读 1–3 个**页面上真实存在**的值 |
| ④ | 拼装指令 | 脚本里的 `buildPrompt()` | 套 §4.2 的三行大白话：学哪个点 + 页面素材 / 当前状态 + 别扩展 / 反馈 + 兜底；**不留 `【】` 待填空** |

模板里的 `refreshPrompt()` / `resetPrompt()` / 发送监听是**通用逻辑**，不要改：页面加载即写好 3 行大白话、点「重置提示词」按当前状态重建、点发送直接把框内全文发出去。

### 0.4 第二个例子：分步流程页（「五步生成流水线」）

**为什么要有这个例子**：0.2 是滑杆页（诊断型）。只会照它写，遇到「分步推进」就会退化成「把整条流程讲一遍」。分步页的正确原型是**对照型**，但也只练**一个点**：拿页面上的演示原句，只考「Token 怎么切」；不要扩写成五步总复习。

**页面上的装置**：五步流水线，学员点「下一步」或点步骤跳转，页面显示「第 3 / 5 步」。

**卡片文案**：

| 位置 | 文案 |
|---|---|
| 卡标题 | 考我：这句话怎么切成 Token |
| 她会做什么 | 她会拿页面上的「周末想去哪儿？」，出一道切分小题，只考「Token 怎么切」这一点。 |
| 提示词框标签 | 发给小奈的提示词（可直接修改） |
| 提示词框预填 | 3 行大白话：学哪个点 + 状态 + 题面 / 反馈 / 兜底；**无待填空** |
| 重置按钮 | 重置提示词 |
| 发送按钮 | 发送给小奈教练 |

**`readContext()` 读出来的页面状态**：

```text
演示原句：周末想去哪儿？；演示进度：第 3 / 5 步；正在讲的一步：每块文字，换成一串数字
```

**打开卡片后直接发出的 prompt（3 行）**：

```text
我在学「Token 是怎么切出来的」。现在在第 3 / 5 步，请拿「周末想去哪儿？」出一道对照题，先别解释；这是教学示意，切法因模型而异。
我回答后，你先说我哪里对、哪里偏，再给一句正确说法。
如果我没答上来，就直接告诉我答案，不要继续追问。
```

**反馈长什么样**：

```text
我哪里对：知道要切成小块
我哪里偏：以为按字数切，其实按模型自己的切法，生僻词和符号会被切碎
正确说法：Token 不等于字，切法因模型而异
```

**和 0.2 的差别**：滑杆页练的是「该不该压缩」这个判断，分步页练的是「Token 怎么切」这个动作。两者都只练一个点，打开时都是 3 行大白话，**不需要补任何空**。

完整可抄的代码见 `07-小奈互动模式库.md` §3。

> `/* 复用代码开始 */` 到 `/* 复用代码结束 */` 之间（`coach:send` 发送、`coach:ack` 监听、origin 校验、独立打开提示）**整段照搬**。

## 〇、哪些页面配卡（先判这个，再往下读）

**不是每页都配。** 一份资料拆成多个 HTML 页面时，**逐页判**：

```text
读者要不要动手？
├─ 不要 → 纯知识页 → ❌ 不配卡
└─ 要 → 页面能不能读出他刚才的操作？
    ├─ 能 → ✅ 配卡，贴在装置正下方
    └─ 不能 → 先把装置状态补出来，再配
              （否则只是一只空提示词框）
```

| 页面类型 | 判据 | 配不配卡 |
|---|---|---|
| **互动页** | 有一个**可玩装置**——读者要动手点 / 拖 / 押 / 调 / 排，页面能读出他刚才的操作状态 | ✅ **配**（贴在装置正下方） |
| **纯知识页** | 只有阅读内容：一句话回答 + 原理卡 + 提醒 + takeaway，读者全程只是看 | ❌ **不配** |

**为什么纯知识页不配**：这张卡的全部价值在「页面加载时就把真实状态写进提示词」。**没有装置，就没有状态可带**，剩下的只是一只空提示词框——而「不给空提示词框」正是本文件 §1 的第一条原则。硬塞一张卡只会让人觉得这页没做完。

**怎么落地**：诊断清单里逐页标注「小奈卡：要 / 不要」（`SKILL.md` Phase 1 ⑤）。不配卡的页面，**把模板里 `<section class="coach">` 与 `<script>` 中的 COACH 复用段、`readContext` / `buildPrompt` / `refreshPrompt` 及两个按钮监听整段删掉**，页面不含任何 postMessage 代码。

> 命名：**小奈教练**（不是「助教」「AI 助手」）。页面上一律用这个称呼，与宿主系统保持一致。

**协议刻意做小**：整个通信只有「发一条提问」和「收一条确认」两件事。默认不增加队列、重试、复制兜底、超时、自动展开、额外消息分支或第三方依赖。宿主需要什么，由宿主自己在收到提问后去补——页面只负责把 prompt 组装好、发出去。

## 一、六条设计原则

| 原则 | 说明 |
|---|---|
| **一张卡只练一个点** | 先从本页正文圈**一个知识点**（一句话能说清、有对错或明确做法），标题和 prompt 第 1 行都只提它。**不拿整页、整条流程当练习对象**——那是复习，不是练习。 |
| **不给空提示词框** | 卡片必须**贴着一个具体装置**（`anchor` = 该页的演示区块）。打开卡片时，提示词框**已经由 `buildPrompt()` 写成 ≤3 行大白话**：学哪个点 + 页面素材 / 当前状态 + 别扩展 / 反馈 + 兜底。**学员直接发送，不需要补任何空。** |
| **零补全成本** | 页面素材与读数全部自动带入（演示原句 / 当前选项 / 滑块值 / 分堆结果）；提示词里**不出现 `【】`、`____`、「改成你的」「请补充」**。读者想换成自己的素材可以改，但那不是必填步骤。 |
| **用大白话** | 不写「阈值 / 字段 / 归因 / 对照表」这类术语；像跟同事解释一样写。反馈 + 兜底要能直接抄进笔记。 |
| **硬边界写进 prompt** | **页面教你什么，就防你什么。** 只选 1 条，压进第 1 行末尾。见 §4。 |
| **反馈固定** | 第 2 行「我哪里对、哪里偏、一句正确说法」；第 3 行「没答上就直接给答案」。四种原型共用，不再换字段。 |

## 二、通信协议（宿主为父窗口）

页面被 iframe 嵌入，通过 `window.parent.postMessage` 与宿主通信。**发对象，不发 JSON 字符串**；字段名和值必须与下表逐字一致。

### 2.1 页面 → 宿主：`coach:send`

```js
window.parent.postMessage({
  source:  'learning-page',        // 固定值，宿主据此识别
  type:    'coach:send',           // 本协议唯一的出站消息
  v:       1,
  payload: {
    prompt: 'HTML 已组装好的完整提问文字'   // ★ 唯一必需的业务字段，必须非空字符串
  }
}, '*');   // 已知宿主 origin 时可收紧为宿主域名
```

### 2.2 宿主 → 页面：`coach:ack`

```js
{ source: 'xiaonai', type: 'coach:ack', v: 1 }
```

| 消息 | payload | 页面行为 |
|---|---|---|
| `coach:ack` | — | 确认**宿主已接手**，状态提示改为「已交给小奈教练，请查看对话。」 |

`coach:ack` **只表示宿主接手了提问，不代表模型已回复、也不代表后端请求成功**。回复出现在小奈自己的对话界面里，**不在页面内回显**。

### 2.3 元素 ID（脚本引用必须一致）

| ID | 用途 |
|---|---|
| `coachInput` | 提示词框（`textarea`）——里面是**3 行大白话**，页面加载即写好 |
| `coachSubmit` | 发送按钮——直接把框内全文发给小奈 |
| `coachReset` | 重置按钮——按当前页面状态重建提示词 |
| `coachStatus` | 状态提示行（`role="status" aria-live="polite"`） |

### 2.4 代码结构：通信段与页面业务分开

通信代码用**「复用代码开始／结束」注释**框起来，原样复用；页面专属的 `buildPrompt()` 与按钮事件**放在通信段之外**。这样换一页只需要改段外那三处（见 §6）。

### 2.5 安全

```js
window.addEventListener('message', function (ev) {
  if (ev.source !== window.parent) return;      // 只收父窗口
  var d = ev.data;
  if (!d || typeof d !== 'object') return;
  if (d.source !== 'xiaonai' || d.type !== 'coach:ack' || d.v !== 1) return;   // 不认的消息一律忽略
  /* … */
});
```

**不要把消息里的 `source` 字符串当作身份验证**——它只是识别用的约定值。若要更严，加 origin 白名单。

## 三、没有宿主时的表现

页面可能被单独打开、离线打开，或被别的系统嵌入。此时**不静默失败**，也不做任何兜底机制：

```text
不在 iframe（window.parent === window）
   └→ coachStatus 显示：「请在支持小奈教练的宿主页面中打开此学习页。」
      学习内容照常可看，发送功能不可用。

在 iframe 但宿主没回 coach:ack
   └→ 状态停在「正在交给小奈教练…」，不再变化。
      已发出的 postMessage 保持有效，宿主晚到也还能接上。
```

**不做**：复制兜底按钮、800ms 超时降级、重试队列、自动展开聊天面板。学员的最后一道保险由宿主提供，不由页面提供。

## 四、prompt 怎么写：硬边界

**页面教你什么，陪练就防你什么。** 这一条是这个 skill 里最值得抄的设计。

| 页面的内容 | prompt 里必须写死的约束 |
|---|---|
| 演示里有**具体数字/价格/参数** | 「**不要声称页面上的数字或价格适用于所有模型/产品**；精确值应以官方口径核对」 |
| 讲**上下文窗口 / 记忆** | 「**不要把产品的长期记忆功能与上下文窗口混为一谈**」 |
| 讲**知识库 / 检索** | 「**不要假装已经读取了资料，也不要编造页码或条款**」 |
| 讲**风险标注 / 核查** | 「**找不到依据就写『待核对』，绝不编页码或来源**」 |
| 涉及**操作执行**（Agent、自动化） | 「**付款、删除、发送和敏感数据操作必须保留人工确认**」 |
| 涉及**医疗 / 法律**资料 | 「只设计可追溯引用与人工审核，**不提供诊疗或法律结论**」 |

### 4.0 `readContext()` 读什么：按装置类型查表

| 装置类型 | 该读（1–3 条） | 不该读 | 读法示例 |
|---|---|---|---|
| 点选 + 计数器 | 当前选项 + 页面上的计数 | 解释段落、结论句 | 「当前选项：标准版；页面计数：4,800 字」 |
| 滑块 + 对照 | 当前值 + 上下限（+ 页面占用率） | 滑块旁的说明文字 | 「当前设置：12 轮 / 上限 20 轮」 |
| 分步推进 | 页面演示原句 + 当前步序号 + 步骤名 | 整段 `.scene-cap` 讲解 | 「演示原句：周末想去哪儿？；演示进度：第 3 / 5 步；正在讲的一步：…」 |
| 盲判 + 核对 | 学员押的选项 + 是否已揭晓对错 | 未揭晓时的正确答案 | 「我押的是 B；页面已揭晓：错」 |
| 排序 / 拼装 | 学员当前排出的顺序 / 已选零件 | 未提交时的正确顺序 | 「我的排法：…」 |
| 归类分堆 | 已分堆数量 + 卡住的条目 | 标准答案 | 「已分类 6 / 9 条；卡住：…」 |
| 播放 / 自诊 | 当前档位或当前幕 | 全部解说文字 | 「停在第 2 幕：…」 |

四条纪律：

1. **只读页面已有文本**：`textContent` / `value` / 当前选中项。不要在 `readContext()` 里推断、计算或编造。
2. **≤3 条，每条 ≤40 字**。第 4 条起一律删——prompt 不是页面摘要。
3. **讲解段落最多读一句**，优先读标题或进度。整段教材正文是「页面在讲课」，不是「学员的状态」。
4. **素材从页面当前状态取**：演示原句 / 当前选项 / 当前档位 / 分堆结果，由 `buildPrompt()` 直接写进第 1 行；**不让学员补填**，提示词里也不留 `【】`。

### 4.1 六项检查（写完 prompt 先过这一关）

- [ ] **是不是只练一个知识点？** —— 标题和第 1 行都只提这一个点，没有扩到整页或整条流程。
- [ ] **第 1 行有没有页面素材 + 当前状态？** —— 页面当前展示的原句 / 选项 / 读数，原样放进去。
- [ ] **第 1 行有没有题面和 1 条边界？** —— 判断题 / 对照题 / 改写题 / 分类题四选一；边界只留最相关的一条。
- [ ] **第 2、3 行是不是固定两句？** —— 「哪里对、哪里偏、正确说法」+「没答上就直接给答案」，不用术语。
- [ ] **有没有待填空？** —— 搜不到 `【】`、`____`、「改成你的」「请补充」。
- [ ] **是不是 ≤3 行、每行 ≤70 字、整条 ≤180 字？** —— 换行符 ≤2 个，不空行。

六项缺一项，读者拿到的就会是一段「正确的废话」。
**页面加载时提示词框必须已经是这 3 行大白话**——不是空框，也不是留一个 `【】` 让学员补。

### 4.2 三行模板（直接抄）

```text
我在学「{{知识点}}」。{{页面状态一句}}，请拿页面上的「{{页面素材}}」出一道{{判断题 / 对照题 / 改写题 / 分类题}}，先别解释；{{1 条边界，用大白话}}。
我回答后，你先说我哪里对、哪里偏，再给一句正确说法。
如果我没答上来，就直接告诉我答案，不要继续追问。
```

- **逻辑行固定 3 行**（`\n` 两个），不空行；**每行 ≤70 字、整条 ≤180 字**。
- 第 1 行只提**一个知识点**；素材只取页面上的**一句**，超过 40 字截到第一个句号或逗号。
- 第 2 行固定是「先说我哪里对、哪里偏，再给一句正确说法」；不要换成「分析一下」。
- 第 3 行固定留兜底：「如果我没答上来，就直接告诉我答案，不要继续追问。」
- 全文不出现 `【】`、`____`、「请补充」「改成你的」——**读者打开就能直接发送**。
- **预填方式**：页面加载时用 `buildPrompt()` 生成这 3 行填进提示词框；学员直接发送，不再二次拼装。想换成自己的素材可以手动改，但不是必填步骤。

### 4.3 完整成品（诊断型，照这个长度写）

```text
我在学「上下文窗口什么时候会满」。页面显示 12 轮、已占 75%，请拿这段对话出一道判断题，先别解释；数字是演示值。
我回答后，你先说我哪里对、哪里偏，再给一句正确说法。
如果我没答上来，就直接告诉我答案，不要继续追问。
```

> 用户要求**原文发送**时仍用本节模板：学员在框里改字即可，不需要改 `buildPrompt()`。

### 4.4 四种原型只换第 1 行的题面

| 原型 | 第 1 行出什么题 | 例子 |
|---|---|---|
| **诊断型** | 判断题 | 75% 该不该压缩 |
| **对照型** | 对照题 | 这句话怎么切成 Token |
| **改写型** | 改写题 | 把模板话术改具体 |
| **产出型** | 分类题 | 这条消息放哪堆 |

第 2、3 行**四种原型完全一样**，不再换字段。题型只负责「出什么题」，反馈一律是「哪里对、哪里偏、正确说法」，最后留一句「没答上就直接给答案」。

### 4.5 哪两个短句在承重

这两句不能删，它们是这张卡「练习感」的来源：

1. **「先别解释」**——小奈如果一上来就讲答案，学员只是读了一遍，没有练。
2. **「如果我没答上来，就直接告诉我答案」**——先给学员一次尝试的机会，但答不上来时也不让他卡住。

写法上照小山学堂的模板：一句话只干一件事，把**最关键的那半句**单独放在句尾，让人一眼看到。

## 五、字段对照（写卡时逐项填）

| 字段 | 含义 | 填不出来时，问自己 | 例子 |
|---|---|---|---|
| `anchor` | 卡片挂在页面哪个元素后面 | 「读者刚玩完哪个东西？」 | 滑块/选项/排序装置的容器（`.demo`） |
| `point` | 这张卡只练哪个知识点 | 「一句话能说清、有对错或明确做法吗？」 | 「上下文窗口什么时候会满」 |
| `title` | 卡标题 | 「读者点这张卡，是要练哪个点？」 | 「考我：什么时候该压缩」 |
| `desc` | 一句话说明她会做什么 | 「她拿页面上的什么，考哪一点？」 | 「她会拿页面上的轮数和占用率，出一道判断题，只考『什么时候该压缩』这一点。」 |
| `promptHint` | 提示词框上方一句说明 | 「读者打开卡片时看到什么？」 | 「已按当前页面状态写好 3 行，可直接发送；想换成自己的素材再改。」 |
| `task` | 第 1 行出什么题 | 「判断题 / 对照题 / 改写题 / 分类题？」 | 判断题：75% 该不该压缩 |
| `promptLines` | 提示词固定 3 行的分工 | 「每行分别放什么？」 | ① 学哪个点 + 状态 + 素材 + 题面 + 边界 ② 反馈 ③ 兜底 |
| `current()` | 从页面读数 | 「页面上哪个数字/选项能代表他刚才的操作？」 | 轮数、占用率、选中项、排序结果；按 §4.0 装置表选 |
| `resetLabel` | 重置按钮文案 | 「点一下会重建什么？」 | 「重置提示词」 |
| `button` | 发送按钮文案 | 「点完会得到什么？」 | 「发送给小奈教练」 |
| `output` | 第 2 行固定反馈 | 「学员看完能直接抄走吗？」 | 我哪里对、哪里偏、一句正确说法 |
| `buildPrompt()` | 写成 3 行大白话；页面加载时由 `refreshPrompt()` 调用 | 「她需要哪些上下文才不会答偏？」 | 见 §4.3 |

> [!tip] 卡面只写「她会做什么」
> 不在卡面上堆「不会假装…」「不保证事实正确」这类免责声明——读起来像模板。边界写进 `buildPrompt()` 的硬约束；页面上由 `.demo-note` 和诚实提醒承担。卡面只留一句具体动作。

### 5.1 最小可行卡（先跑通，再美化）

只写这 4 句，也能用：

```text
标题：考我：{{知识点}}
说明：她会拿页面上的{{素材}}，出一道小题，只考这一点。
提示词框：页面加载时自动写好 3 行大白话（学哪个点 + 出题 / 反馈 / 兜底），无待填空
按钮：发送给小奈教练
```

**提示词框不是空的**：页面加载时 `refreshPrompt()` 会调用 `buildPrompt()`，把 3 行大白话填进去。学员直接发送；想换自己的素材可以手动改；点「重置提示词」按当前页面状态重建。

### 5.2 卡标题的三种写法

| 写法 | 例子 | 适合 |
|---|---|---|
| **换成一个具体动作** | 判断页面上这段对话该压缩还是新开 | 最通用，推荐 |
| **帮我做判断** | 判断这段对话该压缩还是新开 | 页面本身在讲二选一 |
| **帮我产出一份东西** | 生成这段对话的「交接单」 | 页面有明确交付物 |

> ❌ 不要写「向小奈提问」「和小奈聊聊」「AI 助手」——读者不知道点进去要干嘛。

## 六、实现：照着改这 4 处

直接复制 `assets/page-template.html` 里的 `<section class="coach">` 及其脚本（`COACH` 段）。需要改的只有四处：

### 6.1 卡片 HTML（只换文案）

```html
<!-- data-page-id 在 <body> 上：<body data-page-id="{{PAGE_ID}}"> -->
<section class="coach" id="coach"
         data-coach-title="{{卡标题：一个动作}}">
  <div class="coach-head">
    <span class="coach-avatar" aria-hidden="true">奈</span>
    <div>
      <h3 class="coach-title">{{卡标题}}</h3>
      <p class="coach-desc">{{她会做什么}}</p>
    </div>
  </div>
  <label class="coach-label" for="coachInput">{{提示词框标签}}</label>
  <p class="coach-hint" id="coachHint">已按当前页面状态写好 3 行，可直接发送；想换成自己的素材再改。</p>
  <textarea id="coachInput" rows="5" aria-describedby="coachHint"
            placeholder="页面打开后这里会自动生成可直接发送的完整提示词"></textarea>
  <div class="coach-actions">
    <button type="button" class="btn ghost small" id="coachReset">重置提示词</button>
    <button type="button" class="btn blue small" id="coachSubmit">发送给小奈教练</button>
  </div>
  <p class="coach-status" id="coachStatus" role="status" aria-live="polite"></p>
</section>
```

### 6.2 `readContext()`：读页面上已有的值

```js
function readContext() {
  return [
    { k: '轮数', v: rounds.value + ' 轮' },
    { k: '占用', v: pct + '%' }
  ];
}
```

**只读页面已有文本**：`textContent` / 当前选中项 / 滑块值。不要在这里做推断，也不要编一个页面上没有的数字。

### 6.3 `buildPrompt()`：套 §4.2 模板

```js
function buildPrompt() {
  var state = readContext()
    .map(function (c) { return c.k + '：' + c.v; })
    .join('；');

  return '我在学「上下文窗口什么时候会满」。页面显示 ' + state + '，请拿这段对话出一道判断题，先别解释；数字是演示值。\n' +
    '我回答后，你先说我哪里对、哪里偏，再给一句正确说法。\n' +
    '如果我没答上来，就直接告诉我答案，不要继续追问。';
}
```

**预填、重置与发送**（模板已内置，换页时不用改）：

```js
var promptDirty = false;   /* 学员改过提示词后，装置变化不再覆盖 */

function refreshPrompt() {
  $('coachInput').value = buildPrompt();
  promptDirty = false;
}

function resetPrompt() {
  refreshPrompt();
  $('coachInput').focus();
}

$('coachInput').addEventListener('input', function () {
  promptDirty = true;
});

$('coachSubmit').addEventListener('click', function () {
  var input = $('coachInput');
  var prompt = (input.value || '').trim();
  if (!prompt) {
    $('coachStatus').textContent = '提示词为空，请先点「重置提示词」。';
    input.focus();
    return;
  }
  /* 框里已经是完整提示词：直接发送，不再二次拼装 */
  sendCoachPrompt(prompt);
});

$('coachReset').addEventListener('click', resetPrompt);

/* 页面加载即写好：学员打开卡片时就看到 3 行大白话 */
refreshPrompt();
```

**装置状态变化时**：在状态更新回调的末尾加一句 `if (!promptDirty) refreshPrompt();`——学员没改过就自动同步；改过就不覆盖，点「重置提示词」才重建。

### 6.4 不要动的地方

- `/* 复用代码开始 */` ~ `/* 复用代码结束 */` 之间的通信段。
- `sendCoachPrompt()`、`coach:ack` 监听、origin 校验。
- `refreshPrompt()` / `resetPrompt()` / `coachSubmit` / `coachReset` 的绑定：加载即写好 3 行大白话、提交直接发送框内全文、重置按当前状态重建。
- `R()` 函数：所有延时写成 `R(160)`，不要写裸 `160`。
- 头像 `.coach-avatar` 的 base64 CSS。

### 6.5 头像（内置，不要改）

`.coach-avatar` 的**小奈头像已按 base64 内嵌在模板里**（约 15 KB 的 PNG data URL，写在 `background-image:url("data:image/png;base64,…")`）。这是刻意的：

- **不要换成外部图片链接** —— 模板的硬要求是「单文件、零依赖、可离线」，外链头像会破坏这一条。
- **不要动这行 CSS** —— 换页时头像自动跟着走，无需任何操作。
- 标签里的文字 `奈` 是**兜底**（`font-size:0;color:transparent` 时不可见），头像加载不出来时才顶上来；不要删。
- 确实要换形象时：把新头像压到 **120×120 左右的 PNG**，用 `base64` 编成一整行替换整段 `url("…")`；**不要**在 data URL 里换行，否则 CSS 会断。

### 6.6 宿主接入参考（仅宿主尚未实现协议时使用）

HTML 本身不调用模型接口。宿主必须加载 iframe 并监听 `message`，再调用自身已有的教练发送方法：

```js
/** 为指定 iframe 连接教练发送方法，返回取消监听函数。 */
const connectCoach = (iframe, sendPrompt) => {
  const handleMessage = (event) => {
    const message = event.data;
    if (event.source !== iframe.contentWindow) return;
    if (!message || typeof message !== 'object') return;
    if (message.source !== 'learning-page' || message.type !== 'coach:send' || message.v !== 1) return;
    const prompt = message.payload && message.payload.prompt;
    if (typeof prompt !== 'string' || !prompt.trim()) return;
    sendPrompt(prompt);
    iframe.contentWindow.postMessage({ source: 'xiaonai', type: 'coach:ack', v: 1 }, '*');
  };
  window.addEventListener('message', handleMessage);
  return () => window.removeEventListener('message', handleMessage);
};
```

`iframe` 是实际嵌入学习页的 `HTMLIFrameElement`；`sendPrompt` 是宿主提供的函数，接收完整字符串并调用已有聊天发送功能。保留返回值，在宿主组件卸载或移除 iframe 时调用它。

不要把未定义的示例变量当成可运行接入。已有登录、发送中和失败处理继续由原发送方法负责。

## 七、5 分钟验收（交付前逐条打勾）

- [ ] 卡片**紧贴装置下方**，不是页面底部。
- [ ] **只练一个知识点**：标题和第 1 行都只提这一个点，没有扩到整页或整条流程。
- [ ] **打开页面即写好**：提示词框里已经是 **3 行大白话**（学哪个点 + 状态 + 素材 + 题面 + 边界 / 反馈 / 兜底），不是空框，也不是固定示例。
- [ ] **无待填空**：框内搜不到 `【】`、`____`、「改成你的」「请补充」；不点任何按钮也能直接发送。
- [ ] 页面读数 **≤3 条**；手机宽度下整段内容**仍可见**（提示词框可滚动）。
- [ ] 点「发送给小奈教练」→ 发出的就是**框内全文**，不再二次拼装。
- [ ] 学员手动改字后直接发送，改动**生效**。
- [ ] 点「重置提示词」→ 按当前页面状态**重建**，覆盖手动编辑。
- [ ] 装置状态变化且学员**未编辑** → 提示词自动刷新；**已编辑** → 不被覆盖。
- [ ] 点发送且提示词为空 → 出现「提示词为空，请先点『重置提示词』。」，焦点回到提示词框。
- [ ] 点发送且提示词非空 → 状态变成「已交给小奈教练，请查看对话。」
- [ ] 实际发出的 prompt 同时包含：**一个知识点 / 页面状态 / 页面素材 / 题面 / 1 条边界 / 反馈 / 兜底**。
- [ ] **行数测试**：`prompt.split('\n').length <= 3`；每行 ≤70 字、整条 ≤180 字。
- [ ] **术语测试**：框内搜不到「阈值 / 字段 / 归因 / 对照表」这类词；读起来像同事说话。
- [ ] **遮素材测试**：遮住第 1 行的页面素材或状态，prompt 会失去具体对象（还能执行 = 素材/状态是装饰）。
- [ ] **换知识点测试**：把知识点换成本页另一个点，这条提示词还成立吗？仍成立 = 写得太泛。
- [ ] **抄走测试**：反馈能直接贴进笔记 / 照做吗？不能 = 还是「建议」。
- [ ] 纯知识页**没有** `<section class="coach">`，也没有任何 `postMessage` 代码。
- [ ] 独立打开 HTML → 显示「请在支持小奈教练的宿主页面中打开此学习页。」
- [ ] iframe 内 → 宿主能收到 `coach:send`，且 `payload` 只有 `prompt` 一个字段。
- [ ] 没有真实联调时，**不声称已连接真实教练**。

## 八、常见错误：抽象 → 具体

| ❌ 抽象写法 | ✅ 具体写法 | 为什么 |
|---|---|---|
| 标题「向小奈提问」 | 「考我：什么时候该压缩」 | 读者要知道点进去**练哪个点** |
| 标题「把这一页的重点梳理一遍」 | 「考我：这句话怎么切成 Token」 | 一张卡只练一个知识点 |
| 说明「小奈可以帮你分析问题」 | 「她会拿页面上的轮数和占用率，出一道判断题，只考『什么时候该压缩』这一点。」 | 说清**她拿什么考、只考哪一点** |
| 打开卡片是空框，让学员自己写 | 页面加载即写好 3 行大白话；素材从页面取，无待填空 | 学员要的是「打开就能发」，不是「从零拼 prompt」 |
| prompt 只写「请帮我看看」 | 「我在学哪个点 + 状态 + 素材 + 题面 + 边界 / 反馈 / 兜底」压成 3 行 | 不给上下文，小奈只能答得正确但没用 |
| 卡片放在页面最底部 | 紧贴装置下方 | 读者刚玩完，才有话可说 |
| 纯知识页硬塞一张卡 | 删掉卡与脚本 | 没有装置 = 没有状态可带 = 空提示词框 |
| 把页面上没有的数字写进 `readContext()` | 只读 `textContent` / 选中项 / 滑块值 | 编造状态会让学员失去信任 |
| 在 prompt 里写「页面上的价格适用于所有模型」 | 「页面数字是演示值，精确值以官方口径为准」 | 具体数字最容易被当成真值 |
| 标题「把 X 套到你的任务上」 | 「考我：这句话怎么切成 Token」 | 标题要说清**练哪一个点**，不是「套一下」 |
| prompt 写「请把整页内容拆成五步」 | 只圈「Token 怎么切」这一个点 | 复习不是练习，一次只练一个点 |
| 占位「我打算发给 AI 的原话是「」」 | 直接用页面演示原句「周末想去哪儿？」 | 素材从页面取，不让学员补 |
| prompt 结尾「给出建议」 | 「用『我哪里对｜我哪里偏｜正确说法』回我」 | 反馈能抄走，建议不能 |
| 输出「指出最容易出错的一步」 | 「我哪里对｜我哪里偏｜正确说法」 | 反馈能直接记，标签不能 |
| `readContext()` 读整段 `.scene-cap` 讲解 | 只读进度 + 步骤名，≤3 条 | 教材正文不是学员状态 |
| 重置按钮只是清空 / 塞一段固定示例 | 重置 = 按当前页面状态重建 3 行大白话 | 固定示例 = 换个页面也一样，等于没带 |
| 点发送时又用 `buildPrompt()` 包一层 | 直接 `sendCoachPrompt(框内全文)` | 框里已经是完整提示词，再包一层会重复 |
| 装置一变就覆盖学员改过的提示词 | 用 `promptDirty` 标记；改过不覆盖，点重置才重建 | 学员的修改不能被动画吞掉 |

---

> [!tip] 一句话记住
> **装置负责让学员「看见」，小奈卡负责把「刚看见的」直接交给小奈练一遍。**
> 卡片写不好，通常不是文案问题，是**没想清楚读者刚在装置里看到了什么、下一步想拿它干什么**。
