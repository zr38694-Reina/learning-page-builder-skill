# 09 · 旧页升级：从四旧模块到五块骨架

改一版页面规范时，历史页面不会自己变新。这份文件管的是**存量页面的升级**——把按旧骨架写的页面（手点装置 / 原理方块带 / AI 小故事 / 分开的提醒与 takeaway）改成当前五块骨架。

一次升级 = **换掉四块骨架 + 保住原有内容**。不是重写页面：历史页里常有 base64 品牌图、术语下划线脚本、结构化数据，从零重写会把这些丢掉。

---

## 一、先判定是不是旧骨架

```bash
grep -c -E 'class="(how|life|edge|qa2)"|flowSvg|step-dot|attn-token' 页面.html
```

> 结果为 0 → 已经是新版，别动。≥ 1 → 按下面走。

旧骨架的四个特征模块，新规范里**全部取消**：

| 旧模块 | 新规范里的去处 |
|---|---|
| 手点装置（`step-dot` / 点选 token / 权重条） | 换成**可播放动画流程**（5 拍 + 判词 + 播控） |
| 原理区（`.how` + `flowSvg` 方块带 + 三栏说明） | 拆开：机制进动画字幕，边界进便签边界段 |
| AI 小故事（`.life` 三拍小剧场） | 整块删除（类比要么进首屏，要么不要） |
| 分开的「诚实提醒」`.edge` + takeaway | 合并成一张居中便签：**4 句带走（黑字 + 实心方块）+ 2 条边界（灰字 + 空心方块）**，中间 18px 留白、不写小标题 |

判定为旧版后先**备份**原文件到工作区 `backups/`，再动手。

---

## 二、改法：三段脚本 + 锚点断言

**不要**一个大脚本改完，也不要手写整个 HTML。按 CSS → HTML → JS 三段，每段只按锚点切割并断言：

```python
def cut(start, end, new, tag):
    assert s.count(start) == 1, tag
    i = s.index(start); j = s.index(end, i)
    s = s[:i] + new + s[j:]
```

断言的作用是：锚点没匹配上就立刻停，文件一个字节都不写。**全部改完再写盘**（`io.open(P,'w')` 放在脚本最后一行）。

脚本命名 `upgrade_p{NN}_{css,html,js}.py`，改完留档；下一张同批的页面直接改内容复用。

### 旧壳太旧时改用「捐献者」整页移植

同批里若已有一张按最新规范重写过的页面，直接拿它当**外壳捐献者**：

- 截取它的 `<head>`（令牌 / 圆角 / 色板 / 全部组件 CSS）、页脚 base64 figure、尾部脚本三段（`ld+json` / 主脚本 / 术语下划线）整体复用；
- 只替换正文内容，以及 `--fs-hero` 分母、`title` / `description`、`ld+json`、三问卡的 `ASKS` / `TOPIC`。

比在旧页里逐段替换更快、漏网更少。代价是必须逐条核对捐献者里**写死的本页信息**（页面标题、正文关键词、术语用例），漏一处就是串页。

## 三、CSS 只做四件事

1. `--fs-hero` 改反算，`.hero h1` 去 `max-width` + `nowrap`（公式见 `references/03` 的 H1 起名一节，分母 = 标题字数 × 0.96）。
2. 首屏 `.hero-answer .statement` 换成 `.ans-stack` 三层块（含 `--f-*` 局部色板 + 亮/暗两套）；旧页的两栏 `.hero-row`（右栏塞卡片）整段拆掉，卡片另起 `section.facts-band` 放动画上方。
3. 装置 CSS 换成 `.anim-*`（逐拍卡片）+ `.anim-vis`（示意行）；动画有「按权重 / 按比例」这类可视化时加 `.anim-vis.wts` + `.wrow`（三列：词 / 条 / 百分比，`.hi` 高亮）。
4. 便签加 `.note-edge`（灰字 + 空心方块）样式：**带走段在前、边界段在后**，两段之间 18px 留白，**不写小标题**（旧 `.note-next` 已废）；便签 `margin:0 auto` 居中 + `border-radius:var(--r-card)`；900px 以上带走段两列、边界段单列。

删旧 CSS 时同步删两处容易漏的：`@media (prefers-reduced-motion)` 里的 `.flow` / `.life-scene` 规则、响应式里的 `.qa2` / `.weight-track`。

## 四、HTML 的五块骨架

首屏三层不是三段排版，是**三种内容**：

| 层 | 标签写法 | 内容 |
|---|---|---|
| `.ans-lead` | `一句话回答`（固定名，不许改） | 结论：**加粗一句人话** + 半句补充 |
| `.ans-why` | 口语短句（「它凭什么判断」「它为什么能接」） | 机制：为什么会这样 |
| `.ans-fix` | 口语短句（「该怎么理解」「该怎么用它」） | 出路：`fix-cmp` 两栏对照，右栏 `.fix-skill` 用 `--f-tint1` 高亮底 |

动画区结构固定：`#demo` > `.demo-head`（`#animProgress`）+ `#animStage`（5 个 `.anim-step[data-hold]`，最后一拍加 `.hot`）+ `#animVerdict[hidden]` + `#animPlay` + `.demo-note`。

### 机制类主题的五拍套路

1. 起手：现在缺什么 / 要解决什么（提问）
2. 比对：拿什么跟什么比，比出什么（核心动作）
3. 分配：数值怎么变成占比 / 权重，为什么这样看
4. 取回：按占比拿到了什么，结果是什么
5. 变量：换一个条件再算一遍，结论会怎么变 → 收在判词

每拍字幕 2 句：一句说做了什么，一句说「这意味着什么」。别写成名词解释。

### 核对 / 审查类主题的五拍套路

适用「这话能不能信」「这个结论站不站得住」这类页面：

1. 起手动作是什么（如「先接话不查证」）
2. / 3. / 4. 逐处塌：每拍一句**被审的原话** + 塌的原因 + 「✗ 该怎么核」
5. 唯一站得住的那句（`.hot`）+ 判词收尾

被审原话用 `.anim-quote`（左竖线引用块，`bad` / `ok` 变体）单独一块，和字幕分开写——引用块里的 `<b>` 必须是 `inline`，否则会被 `.anim-step` 的后代选择器断成独立行（见下文坑 7）。

### 动画形式两种二选一

上面两个套路都是**线性五拍（切换式）**。另一种是**全图流程图（不是五拍）**：一张完整 SVG 常驻不换屏，播放按时间轴逐节点 / 逐箭头点亮（`.on` 累加不撤销）、底部字幕条跟拍，适合「一条链路 + 分支 / 回路」。成页 donor：`Skill微PBL1.1-01-为什么AI记不住上周的交代-学习页.html`（Obsidian 老师课程资料汇总/Skill微PBL/学习页/）；选型细节与三个实现要点见 `02-动画流程选型.md`「一·补」。验证也跟着形式走：流程图形式不适用「同屏恰好一拍」采样，改验「点亮单调累加、终态全亮、暂停续播、重播归零」。

## 五、短屏首屏溢出

首屏内容常在 1280×800（笔记本最紧的一档）比视口高 40–50px。加一条短屏媒体查询收紧竖向节奏，**别砍内容**：

```css
@media (min-width:1000px) and (max-height:860px){
  .hero .shell{padding-top:clamp(20px,3vw,40px);padding-bottom:clamp(18px,2.4vw,30px)}
  .hero h1{margin-bottom:clamp(14px,1.8vw,22px)}
  .hero-sub{margin-bottom:clamp(16px,2vw,24px)}
  .hero-credit{margin-top:clamp(14px,1.8vw,22px)}
}
```

## 六、术语落点：升级后必查

术语下划线脚本的 `SKIP` 里含 **`.demo`**——动画字幕里的词**不会**被标注。删掉原理区后，很多概念就只剩动画里有落点了。

```js
// 期望数量 ≈ 卡片条数
document.querySelectorAll('.ai-term').length
```

不够就**把词补进首屏或便签**（`hero-sub`、第②层、便签边界条各塞一两个），不要改脚本的 `SKIP`——那是为了防止在可交互区里误标。

两个配套改动别漏：

- 卡片是**一概念一卡**（现在所有页都这样），术语脚本取解析的那两行必须跟着改：`<b>` 的父节点是 `.fc-head` 不是 `li`，要 `b.closest('li')` 回到卡片，再**优先取 `.fc-def` 的文本**——否则弹窗会把序号「01」和括号里的英文名一起串进去（照抄 `examples/02` 页的同段）。
- 概念 **6 条**时不要 3+3 切两张（对半切已作废）：把两条相邻同族概念并成一条（`data-term="甲|乙"`，解析里两个词都讲到），凑成 **5 条单页**；翻页脚本与 `.facts-track` 整段删。

## 七、验证清单

浏览器里逐条读，别靠眼看截图（四档视口 320 / 375 / 768 / 1280）：

- `h1.getBoundingClientRect().height / lineHeight === 1`（H1 单行）
- 首屏 `.hero .shell` 高度 = 视口高度（满屏），且短屏那档不溢出
- **切换式（红线 16）**：播放全程任意时刻 `.anim-step.show` 恰好 = 1；播完停在最后一拍（`.hot`）+ `#animVerdict.hidden === false` + 进度文案「播放完毕」+ 按钮变「↻ 再看一遍」；`.anim-dots` 每拍一个、`aria-current` 恰好 1 个；点某拍停在该拍、再点播放从下一拍继续
- 点「↻ 再看一遍」后 `.show` 归 0、判词隐藏、能重播到 5
- `.ai-term` 落点**按卡判断**：逐张卡取 `.fc-head b` 的 `data-term` 别名组，任一别名落到正文即合规（别拿固定词表比，别名会多标）；落点总数 ≥ 概念数；气泡 `data-def` 不以序号「01」开头（即确认取的是 `.fc-def`）
- `document.documentElement.scrollWidth > innerWidth + 1` → `false`
- 暗色：`data-theme="dark"` 下量 `--f-c1` 落地色（`rgb(125,151,255)`）、`.anim-step.hot` 背景、`.fc-num`（c5）文字转深色
- 圆角：样式层搜 `border-radius:0` 必须为 0；`--r-card` / `--r-sm` 已定义（容器 14 / 内嵌 10）
- `prefers-reduced-motion` 下直达终态、无过渡
- 标签配对：剥掉 `<style>` / `<script>` / 注释后逐 tag 数开闭
- 无 JS 报错

## 八、必踩的坑

1. **本地静态服务有缓存**：改完文件要带 `?v=N` 重新打开，否则拿到旧内容（症状：明明改了文案，页面还是老的）。
2. **320px 溢出的隐形元凶**：`.anim-step` 是 `34px 1fr` 网格，含 `width:max-content` 的示意行会把 1fr 列的 min-content 撑到一整行宽，`scrollWidth` 随之爆掉。修法一行：`.anim-step>div{min-width:0}`。验出来是「整块 anim-step 超宽」就先查这个。
3. **Chrome headless 直截 `--screenshot` 在窄视口下会切内容**（视口怪癖）。窄屏验证用 playwright 的 `full_page=True` + `locator.screenshot()` 按元素截，别用 `sips` 裁大图（`--cropOffset` 是相对中心的，算坐标容易裁错段）。
4. **进场自动播会吃掉你「点播放」那一下**：滚动到 `#demo` 后 IntersectionObserver 自动开播（state = playing），此时点 `#animPlay` 是**暂停**不是播放。测「自动播到终态」就别点按钮，纯轮询 `#animVerdict.hidden` 等它播完（五拍 hold 合计约 6s，采样别只等 3–4s）；要测手动播放就先点一个进度点把状态打成 paused。页面侧对应加守卫：`if (animState === 'idle') playAnim()`。
5. **暗色令牌取值看序列化格式**：`getPropertyValue('--f-c1')` 拿到的是字面量 `#7d97ff`，不是 `rgb(125,151,255)`——塞进探针元素再读 `color` 归一化后再比。
6. **`.anim-step b{display:block}` 会咬到拍内的行内加粗**：想在拍里放「被审原话」这类引用块，其中 `<b>` 会整段断成独立行。标签行用 `.anim-step>div>b` 限定直接子级，引用块的 b 显式 `display:inline`。往 `.anim-step` 里加任何新子块前，先过一遍 `.anim-step` 的后代选择器。
7. **`data-rv` 元素截图前必须先滚一遍页面**：入场靠 IntersectionObserver，直接截图截到的是 `opacity:0` 的空块。先分步 `scrollTo` 滚到底再回目标区块，或截图脚本里统一补 `.in`。
8. **断言会误判注释与脚本**：`border-radius:0`、`note-next` 这类检查要缩小到样式层或 HTML 属性；`<p` 会命中 `<path`，用正则词边界（`<p[\s>]`）。

## 九、交付格式

回复里给：**改前缺什么** → **五块对照表** → **两个「需要说明的判断」**（删了哪些概念、为什么，用哪个互动换了什么） → **验证数据**（几项全过） → **备份路径**。别只说「已更新」。
