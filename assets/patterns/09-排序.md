# 09 · 排序（把打乱的步骤拖回正确顺序）

**何时用**：内容有**正确的先后**——步骤链、因果链、处理流程。
**心理机制**：生成效应（自己排过一遍才记得住）。
**判据**：错序会产生**可解释的坏结果**——不是「随便排都行」，而是「排错了看得出错在哪」。

> 与「分步推进」（`03`）的分界：**`03` 是页面替你走完流程（消费型），`09` 是读者自己把顺序立起来（生成型）。**
> 两者天生配一对：**先用 `03` 看一遍，再用 `09` 考一遍。**
> 只有一个流程、且学员从没见过 → 用 `03`；想让流程被**记住** → 用 `09`。

---

## 结构

```
[ 打乱的一张一张卡 ]          ← 可拖
──────────────────────────
[1] [2] [3] [4] [5]          ← 放置槽（虚线空框，拖进去才有内容）
──────────────────────────
      [ 核对 ]  [ 重来 ]
```

**槽位必须空白可见**（虚线框），让「一共有几步」这件事从一开始就成立——
学员能据此反推自己手里少没少卡。

---

## 实现要点

```js
var RIGHT = ['锁定读者', '给结论', '给证据', '给边界', '给动作'];

function check() {
  var got = slots.map(function (s) { return s.dataset.card; });
  // 只报「第一个错位」——不直接给正确答案
  var firstBad = got.findIndex(function (v, i) { return v !== RIGHT[i]; });
  if (firstBad === -1) return pass();
  slots[firstBad].classList.add('bad');
  tip.textContent = '第 ' + (firstBad + 1) + ' 步开始不对——'
    + why(RIGHT[firstBad], got[firstBad]);
}
```

**关键：只报「第一个错位」，不报全部。**
一次报全部 = 学员直接照着改，等于没排；只报第一处 = 学员必须自己再推一遍后面。

```js
// 判据要解释「错序会怎样」，不是「你错了」
function why(right, got) {
  return '你把「' + got + '」放在了「' + right + '」该在的位置——'
    + '这样读者读到结论时，还不知道它是为谁而写的。';
}
```

---

## 三条手法

### ① 给一个「锚点卡」降低起步难度

第一张或最后一张**预先放好且锁定**（`draggable="false"`），并标一句「这张是起点，不用动」。
学员知道从哪头想，不会一上来就卡住。

### ② 错序的代价要落到「读者身上」

不要写「顺序错误」。写**后果**：

> 你把「给证据」排到了「给结论」前面——读者读到第 3 张还不知道你到底要说什么，
> **他会在第 2 张就走掉。**

**判词否定的是排法，不是人**（同 `07` 的收尾原则）。

### ③ 允许「排到一半就核对」

不是排完 5 张才能核。**每放一张都可以点核对**——
但按钮文案要跟着变：`还没排完（已放 3 / 5）` → `核对顺序`。

---

## 节拍

| 动作 | 时长 |
|---|---|
| 拖动 | 即时 |
| 落位吸附 | 200ms |
| 错误标红 | 240ms |
| 全对的收尾判词 | 400ms |

- **不做自动播放**（同 `08`），排序是主动动作。

---

## 陷阱

- **一次报出所有错位** → 学员照抄，丧失生成过程。**只报第一处。**
- **槽位不可见 / 灰着** → 学员不知道一共几步，无法自查。
- **卡片文案自带顺序线索**（「第一步：先…」）→ 直接送答案，**改掉文案，去掉序号**。
- **排完不给「重来」** → 学员想再练一遍只能刷新（同 `05`）。
- **拿它去讲一个没有唯一顺序的流程**（如「写作的几个方面」）→ 退化成主观题。
  **有唯一正序才用 `09`**，否则用 `03` 或 `08`。
