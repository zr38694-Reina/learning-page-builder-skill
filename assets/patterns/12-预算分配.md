# 12 · 预算分配（给定资源，做取舍）

**何时用**：内容有**有限的总资源**——时间、额度、token、注意力、人力，多个去处争夺它。
**心理机制**：取舍痛感（原来我只能做这么多）。
**判据**：**零和**——多给一处必然削另一处，且总量封顶。

> 与「滑块」（`02`）的分界：**`02` 是单变量（改一个看翻转），`12` 是多变量零和（改了 A 就削 B）。**
> 只要还存在「只改一个自变量就翻转结论」，就用 `02`——它更聚焦、成本更低。
> `12` 只在**必须同时权衡三处以上**时才上。

---

## 结构

```
总预算 [ ▓▓▓▓▓▓▓▓▓▓ ] 剩 0        ← 剩余量实时显示
────────────────────────────────
[渠道 A] ──●──────  30
[渠道 B] ──────●──  45
[渠道 C] ─●───────  25
────────────────────────────────
[ 试运行 ] 看这个组合撑得住什么、撑不住什么
```

**核心机制：三根滑块共享一个总量。** 拖高 A，B 和 C 的可达上限同时被压低。

---

## 实现要点

```js
var TOTAL = 100;
var MAX = 60;   // 单腿上限，防止一条腿吃掉全部
var vals = { a: 30, b: 45, c: 25 };

function redraw(changed) {
  var sum = vals.a + vals.b + vals.c;
  // 超出总量的部分，从「没在拖的那两条腿」上按比例扣
  if (sum > TOTAL) {
    var others = Object.keys(vals).filter(function (k) { return k !== changed; });
    var over = sum - TOTAL;
    var theirSum = others.reduce(function (s, k) { return s + vals[k]; }, 0);
    others.forEach(function (k) {
      vals[k] = Math.max(0, vals[k] - Math.round(over * vals[k] / theirSum));
    });
  }
  render();
}
```

**超额时从其余项按比例扣，而不是拒绝这次拖动。**
拒绝拖动 = 滑不动，学员以为是 bug；
按比例扣 = **看得见「我多给它的，是从别人那儿抽的」**。

---

## 三条手法

### ① 让「被削掉的那部分」有名字

不要只显示数字变小。要显示**被牺牲掉的具体东西**：

> 你把 C 从 25 抽到 8 —— **代价是「原本能覆盖的那批老用户，这轮触达不到」。**

数字变小是「结论」，被牺牲的那件事是「过程」。

### ② 试运行给「两句话」，不给分数

```js
// 好：一段能读的描述
if (vals.a >= 40 && vals.c < 20) {
  out.textContent = '新用户拉得动，但老用户这轮基本没人管——'
    + '按过去的数据，流失率会在第 3 个月开始抬头。';
}
```

**分数说了结论，学员就不读那段话了**（同 `10` 陷阱）。

### ③ 收尾给一个「不可能三角」

最优解不是重点，**「哪个目标必须被放弃」才是重点**：

> 这三件事（拉新 / 留存 / 变现）**不可能同时撑满**。
> 你今天必须决定哪一件**这季度先不做**——不做决定，等于让预算替你决定。

---

## 节拍

| 动作 | 时长 |
|---|---|
| 拖动 | 即时（滑块高频，**禁清空重绘**，同 `02`） |
| 被削减项的高亮 | 240ms |
| 试运行输出 | 400ms |

- **不做自动播放**（同 `08`–`11`）。

---

## 陷阱

- **超出上限就拒绝拖动** → 学员以为坏了。**按比例从其他项扣。**
- **只显示数字、不显示被牺牲的东西** → 取舍感归零。
- **单腿无上限** → 学员把 100 全给一处，「权衡」结构被绕过。**必须给单腿上限。**
- **试运行给分数** → 学员不读描述（同 `10`）。
- **只有一个自变量也能玩** → 那用 `02`，别用 `12`。**`12` 的实现成本比 `02` 高。**
- 滑块缺 `aria-label` / `aria-valuetext`（同 `02`，本系列实测最常见的无障碍缺口）。
