# 15 · 前后对照动画（自动演示，不要求读者找错）

**何时用**：内容有一组**前后结果**——改前失败、改后成功，且差别只在一处；读者需要**看懂为什么**，而不是自己把坏点找出来。
**心理机制**：对比 + 因果链。
**判据**：改前和改后**各有一个具体结果**；两版只差**一个决定性改动**；把这个改动讲清楚，比让读者猜更有效。

> 与 `07 A/B 对比` 的分界：**`07` 让读者在两条路里选（有交互、默认播坏的那档）；`15` 只播放，读者不选。**
> 与 `11 找错` 的分界：**`11` 要读者在一整块材料里主动定位坏点；`15` 直接把坏点和修复过程演示出来。**
> 什么时候用 `15` 而不是 `11`：**坏点太难找、或教学目标不是「审稿能力」而是「看懂机制」时，用 `15`。**

---

## 结构

```
[同一句话 / 同一个任务]
        │
[改前材料] ──▶ [失败结果]        ← 只亮坏点，不要求读者点
        │
     改一处（可见的文字替换）
        │
[改后材料] ──▶ [成功结果]        ← 两个结果并排，改前压暗但保留
        │
   [一句可迁移的规则]
```

**必须有：**

- **一个**决定性改动（多一个都会让因果变糊）；
- **两个结果**都可见（改前压暗、改后点亮），不要只留成功的那张；
- 一个**判断面板**：任务 ↔ 关键字段（description / 参数 / 条件）→ 对不上 / 对上了；
- 收尾一句可迁移的规则（如「门牌没换」）。

**示例（现成 Skill 改造）：**

> 同一句「做一张双十一海报」：
> 改前的 SKILL.md 里 name、颜色、字体、语气都换成小q，只有 description 还写 Anthropic → AI 判断「对不上」，不调用，产出大红底金字；
> 把 description 换成小q的说法 → AI 判断「对上了」，读取正文，产出浅灰底青柠绿。

### JS

```js
(function () {
  var root = $('fixAnim'), btn = $('fixPlay'), cap = $('fixCap');
  if (!root || !btn || !cap) return;
  var descLine = $('fixDescLine'), descBad = $('fixDescBad'), descGood = $('fixDescGood');
  var descTag = $('fixDescTag'), descChip = $('fixDescChip');
  var verdict = $('fixVerdict'), read = $('fixRead');
  var badFig = $('fixBadFig'), goodFig = $('fixGoodFig');
  var rule = $('fixRule');
  var timer = [];

  function clear() { timer.forEach(clearTimeout); timer = []; }
  function at(ms, fn) { timer.push(setTimeout(fn, R(ms))); }
  function paint(text) { cap.textContent = text; }

  function reset() {
    clear();
    descLine.classList.remove('hot', 'fixed');
    descBad.hidden = false;
    descGood.hidden = true;
    descTag.className = 'fix-tag bad';
    descTag.textContent = '✗ 没改';
    descChip.textContent = '{改前值}';
    verdict.className = 'fix-verdict bad';
    verdict.innerHTML = '<span class="fix-mark">✗</span> 对不上，不调用';
    read.textContent = '— 没读正文';
    badFig.classList.add('on');
    goodFig.classList.remove('on');
    rule.hidden = true;
    paint('点「播放动画」，看为什么改前不行、改后行了。');
  }

  function finalState() {
    reset();
    descLine.classList.add('fixed');
    descBad.hidden = true;
    descGood.hidden = false;
    descTag.className = 'fix-tag ok';
    descTag.textContent = '✓ 已改';
    descChip.textContent = '{改后值}';
    verdict.className = 'fix-verdict good';
    verdict.innerHTML = '<span class="fix-mark">✓</span> 对上了，调用';
    read.textContent = '✓ 读取正文，按规范执行';
    badFig.classList.remove('on');
    goodFig.classList.add('on');
    rule.hidden = false;
    paint('{一句可迁移的规则}');
    btn.textContent = '↻ 再看一遍';
    btn.disabled = false;
  }

  function play() {
    if (REDUCED) { finalState(); return; }
    reset();
    btn.disabled = true; btn.textContent = '播放中…';
    at(300, function () {
      descLine.classList.add('hot');
      paint('{改前：只有这一处没改，其他都对}');
    });
    at(1300, function () {
      paint('{关键字段和任务对不上}');
    });
    at(2300, function () {
      badFig.classList.add('on'); goodFig.classList.remove('on');
      paint('{失败结果：AI 没调用}');
    });
    at(3400, function () {
      descLine.classList.remove('hot');
      descLine.classList.add('fixed');
      descBad.hidden = true;
      descGood.hidden = false;
      descTag.className = 'fix-tag ok';
      descTag.textContent = '✓ 已改';
      descChip.textContent = '{改后值}';
      verdict.className = 'fix-verdict good';
      verdict.innerHTML = '<span class="fix-mark">✓</span> 对上了，调用';
      read.textContent = '✓ 读取正文，按规范执行';
      paint('{改一处，再跑同一句话}');
    });
    at(4600, function () {
      badFig.classList.remove('on');
      goodFig.classList.add('on');
      rule.hidden = false;
      paint('{成功结果：AI 调用并照做}');
    });
    at(5800, function () {
      paint('{一句可迁移的规则}');
      btn.disabled = false; btn.textContent = '↻ 再看一遍';
    });
  }

  btn.addEventListener('click', play);
  if (REDUCED) finalState();
})();
```

`R()` 与 `$()` 来自页面模板；`finalState()` 是减少动效用户的完整成品页。

## 三条关键手法

### ① 只改一处，因果才清楚

前后两版最好只差**一个决定性字段**（description / 参数 / 条件）。差三处，读者说不清是哪一处让结果翻转——那就退化成 `07 A/B` 或 `11 找错`。

### ② 两个结果都保留，别只留成功的那张

改前结果压暗（`opacity:.45`），改后结果点亮；**不要 `display:none` 把改前删掉**。这样静态截图、减少动效、打印都能看到完整对照，读者也不用凭记忆回想改前长什么样。

### ③ 让「修复」是一个可见的文字替换

不要只把某个边框变绿。让关键行**从旧文案换成新文案**（两句都用 `<code>` 承载，切换 `hidden`），同时更新判断面板的「✗ → ✓」和「没读正文 → 读取正文」。读者看到的是一条**因果链**：这句变了 → 判断变了 → 结果变了。

### ④ 收尾必须抽象成一句规则

最后一句不要复述过程，要给可迁移的判断。例：

> 「门牌没换：屋里全换了，门口那块牌子还挂着上一个人的名字。改现成 skill，先换 description——它是 AI 决定要不要调用的唯一依据。」

## 节拍

| 动作 | 间隔 |
|---|---|
| 亮出坏点 | 300ms |
| 说明「对不上」 | +1000ms |
| 展示失败结果 | +1000ms |
| 执行修复（文字替换 + 判断翻转） | +1100ms |
| 展示成功结果 + 规则 | +1200ms |
| 收束 caption | +1200ms |

- 总时长 5–7 秒；超过 7 秒必须给「↻ 再看一遍」。
- `prefers-reduced-motion`：直接 `finalState()`，两个结果同时可见（改前压暗、改后点亮）。

---

## 陷阱

- **前后差太多处** → 因果糊掉；只留一个决定性改动。
- **把改前结果删掉** → 读者失去对照；必须保留并压暗。
- **只改颜色/边框，不改文案** → 看不到「哪句话决定了结果」；修复必须是可见的文字替换。
- **让读者先找错** → 那是 `11 找错`；`15` 的目标是「看懂」，不是「审稿」。
- **没有收尾规则** → 学员只记住这一次；最后一句必须能迁移。
- **动画太长** → 5–7 秒足够；超过就拆成两张图或改用 `03 分步推进`。
