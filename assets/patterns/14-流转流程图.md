# 14 · 流转流程图（逐节点点亮 + 流动箭头）

**何时用**：内容是一条**可走的链路**——任务在几个节点之间传递，读者需要一次看全「从哪来 → 经过谁 → 到哪去」。
**心理机制**：见证 + 因果链。
**判据**：至少 3 个节点；箭头有方向；链路里有一个**条件分支**或**回路**（下一轮 / 下一次调用）。没有分叉、没有回路的三步清单，用 `03` 就够。

> 与 `03 分步推进` 的分界：**`03` 是读者一步一步点着走，`14` 是整张链路一次看全、自动播放。**
> 与 `06 播放动画` 的分界：**`06` 讲的是一次经历 / 一个时间线，`14` 讲的是一个系统的流向（多个角色、条件、回路）。**
> 与 `13 分支选择` 的分界：**`13` 让读者选择走哪条路，`14` 只展示系统怎么走，不要求读者决策。**

---

## 结构

```
[节点 A] ──①──▶ [节点 B] ──②──▶ [节点 C]
                                      │
                                     ③
                                      ▼
                                  [节点 D]
                                      │
                                      └──⑤ 回到 A（下一轮）
                 └── 条件分支：对不上 → [不读取]
```

**必须有：**

- 3–7 个节点（超过 7 个就拆成两张图）；
- 至少一条**条件分支**（对不上 / 失败 / 跳过）或一条**回路**（下一轮 / 复用）；
- 每个节点一个短标题 + 一行说明；
- 每个箭头一个编号 + 一个动作词（发出 / 匹配 / 读取 / 照做）。

**示例（Skill 被用上的流转）：**

> 新对话（任务）→ AI 当前对话 → 看 description → 读取 SKILL.md → 按说明执行 → 下一次新对话再来一遍；
> 条件分支：description 对不上 → 不读取，AI 自己发挥。

### JS

```js
(function () {
  var svg = $('flowSvg'), btn = $('flowPlay'), cap = $('flowCap');
  if (!svg || !btn || !cap) return;

  var STEPS = [
    { node: '.fa-a', arrow: '.fa-arrow-1', label: '.fa-label-1', text: '第一步：…' },
    { node: '.fa-b', arrow: '.fa-arrow-2', label: '.fa-label-2', text: '第二步：…' },
    { node: '.fa-c', arrow: '.fa-arrow-3', label: '.fa-label-3', text: '第三步：…' },
    { node: '.fa-d', arrow: '.fa-loop',   label: '.fa-label-loop', text: '最后一手：…' }
  ];

  var timers = [];
  function clear() { timers.forEach(clearTimeout); timers = []; }
  function at(ms, fn) { timers.push(setTimeout(fn, R(ms))); }

  function setStep(s, on) {
    [s.node, s.arrow, s.label].forEach(function (sel) {
      if (!sel) return;
      var el = svg.querySelector(sel);
      if (el) el.classList[on ? 'add' : 'remove']('on');
    });
  }

  function reset() {
    clear();
    STEPS.forEach(function (s) { setStep(s, false); });
  }

  function finalState() {
    reset();
    STEPS.forEach(function (s) { setStep(s, true); });
    cap.textContent = '一句话收束：整条链路的关键。';
    btn.textContent = '↻ 再看一遍';
    btn.disabled = false;
  }

  function play() {
    if (REDUCED) { finalState(); return; }
    clear(); reset();
    btn.disabled = true; btn.textContent = '播放中…';
    STEPS.forEach(function (s, i) {
      at(280 + i * 1100, function () {
        setStep(s, true);
        cap.textContent = s.text;
      });
    });
    at(280 + STEPS.length * 1100, function () {
      btn.disabled = false; btn.textContent = '↻ 再看一遍';
    });
  }

  btn.addEventListener('click', play);
  if (REDUCED) finalState();
})();
```

`R()` 与 `$()` 来自页面模板；`finalState()` 是减少动效用户的完整成品页。

## 三条关键手法

### ① 一次只亮一个节点 + 一条箭头

不要一口气全亮。每一步同时做三件事：节点描边变蓝、箭头开始流动、底部解说换成这一步的动作。学员的注意力被**顺序**带着走，而不是被一整张图淹没。

### ② 箭头必须「会流」

静态虚线只是图，流动虚线才是流程。用 `stroke-dasharray:10 10` + `animation:stroke-dashoffset -20`；主线箭头和回路都适用。箭头头用 `fill="context-stroke"`，颜色会自动跟着线走。

### ③ 条件分支与回路是这类图的灵魂

没有分支的链路大多只是清单；没有回路的链路讲不出「下一次还能用」。

- **条件分支**：用灰虚线 + 灰字，放在主线下方的独立小框里（对不上 / 失败 / 跳过）。它不参与主播放，只做对照。
- **回路**：用虚线从终点绕回起点，标「下一轮 / 下次再走一遍」。这是「可复用」的视觉证据。
- 主线用实线或蓝色，分支与回路用低对比虚线，读者一眼能分出主次。

### ④ 静态图先能读，动画只加注意力

加载时所有节点、说明、分支和回路都要在，箭头用低对比灰；播放只负责依次把节点和箭头点亮。不要一开始把图藏起来——对动效敏感的用户、截图、打印都需要一张完整的静态图。

### ⑤ 收尾把链路抽象成一句规则

最后一句解说不要重复节点名，要给出**可迁移的结论**。例：

> 「任务对得上 → 读取 → 照做；文件一直在，下次再来一遍。」

## 节拍

| 动作 | 间隔 |
|---|---|
| 节点 / 箭头点亮 | 280ms 起步，每步 +1100ms |
| 条件分支说明 | 跟随对应节点；不单独占一步 |
| 回路 | 最后一步之后 |
| 收束 caption | 最后一步 +300ms |

- 总时长 4–7 秒；超过 7 秒必须给「↻ 再看一遍」。
- `prefers-reduced-motion`：直接 `finalState()`，所有节点 / 箭头一次性亮起。

---

## 陷阱

- **节点超过 7 个** → 拆图；一张图只讲一条主链路。
- **箭头不动** → 退化成静态流程图；必须用 dash 动画或移动点。
- **只有一条直线** → 用 `03 分步推进`；流转图的价值在分支和回路。
- **文字太小 / 移动端溢出** → SVG 设 `min-width:760px` + 容器 `overflow-x:auto`；页面上不能出现横向溢出。
- **自动播放没有重播** → 必须给「↻ 再看一遍」；首次进入视野可自动播一次（见 `06` 的 `onView`）。
- **把生成型动作做成流转图** → 需要读者自己排 / 拼 / 找的，用 `09`–`11`，不要用播放。
